# ClarifyTrial

환자 정보가 부족한 임상시험 사전 검토에서는 두 가지 실수가 생긴다.

- 더 확인하면 참가 가능성이 있는 시험을 너무 일찍 제외한다.
- 필요한 확인이 남았는데도 참가 조건을 충족했다고 성급하게 표시한다.

ClarifyTrial은 이 두 실수를 줄이기 위해 시험마다 서로 다른 두 질문에 답한다.

1. **계속 확인할 후보인가?**
2. **현재 자료만으로 참가 조건을 확인할 수 있는가?**

예를 들어 시험이 최근 14일 이내 혈액검사를 요구하는데 환자에게 3개월 전 결과만
있다고 하자. 당시 수치가 기준 안에 있으면 이 시험은 계속 확인할 후보로 남는다.
그러나 최근 결과가 없으므로 현재 확인은 끝나지 않는다. 프로그램은 필요한 검사와
이유를 표시하고, 새 결과가 들어오면 그 결과와 연결된 조건만 다시 판단한다.

![ClarifyTrial 전체 흐름](docs/internal/diagrams/clarifytrial-workflow.svg)

## 한 사례가 처리되는 순서

```text
환자 정보와 임상시험 조건을 읽는다
→ 모집 중인 시험에서 관련 후보를 찾는다
→ 검색된 시험이 실제로 환자의 질환을 다루는지 확인한다
→ 선정 조건과 제외 조건을 하나씩 판단한다
→ 현재 확인이 끝난 시험과 추가 정보가 필요한 후보를 나눈다
→ 여러 시험의 판단에 도움이 되는 정보를 먼저 고른다
→ 기존 기록, 환자 답변, 이미 받은 공식 결과, 새 검사 중 확인 방법을 고른다
→ 새 정보를 반영해 관련 조건만 다시 판단한다
→ 근거, 남은 정보, 질문 전후의 변화를 함께 보여 준다
```

부족한 정보가 여러 개라면 프로그램은 어느 정보가 몇 개 시험의 판단을 바꿀 수
있는지 계산한다. 같은 정보를 여러 방법으로 확인할 수 있을 때는 환자가 입력한 이동,
비용, 시간, 새 검사 허용 여부를 반영한다. 이 값은 참가 조건을 바꾸지 않고 확인 순서와
방법만 바꾼다.

## 입력과 결과

기본 입력은 **이름이 붙은 칸에 값을 넣는 JSON 파일**이다. 환자 사실, 값과 단위,
측정 날짜, 자료 출처, 시험 조건, 아직 필요한 정보와 확인 가능한 방법을 분리해
저장한다. 자유 문장 기록은 선택 기능으로 같은 형식에 옮길 수 있다.

한 시험의 결과에는 다음 내용이 남는다.

- 현재 자료로 확인이 끝난 조건과 사용한 근거
- 참가 가능성은 남지만 아직 필요한 정보
- 분명한 조건 위반과 그 근거
- 다음에 확인할 정보와 확인 방법
- 새 정보가 들어오기 전후에 바뀐 판단
- 새 검사, 추가 방문, 예상 대기와 환자 선택

## 현재 구현 범위

| 부분 | 구현된 내용 |
|---|---|
| 시험 검색 | ClinicalTrials.gov에서 넓게 찾은 뒤 실제로 같은 질환을 다루는 시험만 남김. 고정 자료 재현에는 로컬 BM25와 TrialGPT 검색 사용 |
| 조건 판단 | 수치, 날짜, 예·아니오, `모두`, `하나 이상`, `일정 개수 이상` 관계 계산 |
| 원문 보존 | 공식 선정·제외 조건 전체와 조건별 문장 위치를 함께 저장하고 다시 대조 |
| 부족 정보 확인 | 기존 기록 조회, 환자 질문, 기존 공식 결과 확인, 새 검사·평가 |
| 질문 순서 | 지금 영향이 큰 정보 또는 남은 확인 횟수 전체를 고려한 정보 조합 선택 |
| 환자 상황 | 이동·비용·시간 제한과 새 검사·추가 방문 허용 여부 반영 |
| 재판정 | 새 정보와 연결된 조건만 다시 계산하고 중단된 실행을 이어서 진행 |
| 제외 시험 설명 | 다시 볼 수 있는 최소 조건 묶음, 되돌릴 수 없는 조건과 가능한 재확인 날짜 표시 |
| 결과 기록 | 근거, 판단 변화, 모델 호출, 토큰, 검사·방문과 실행 오류 저장 |

이미 수치와 날짜가 분리된 JSON을 입력하면 외부 언어모델을 부르지 않는다. 자유 문장
해석이나 코드로 계산할 수 없는 조건이 있을 때만 GPT 같은 언어모델을 필요한 역할에
사용한다. 일반적인 정보 부족은 검토 모델로 다시 보내지 않고 질문 경로에서 처리한다.
구조와 역할 수는 [프로그램 설계](docs/internal/CLARIFYTRIAL_AGENT_ARCHITECTURE_REDESIGN.md)에
정리돼 있다.

## 사용한 자료와 확인한 결과

현재 환자 자료는 모두 합성이다. 공개 임상시험 원문에서 객관적으로 계산할 수 있는
조건 일부를 골라 가상 환자의 전체 상태를 먼저 만들고, 시작 화면에서는 그중 일부를
감췄다. 질문을 고르는 프로그램은 감춘 답을 볼 수 없으며 실제 확인을 실행한 뒤에만
답을 받는다.

### 전체 흐름 연결 점검

- 고정된 공개 시험 589건에서 평가 대상으로 정한 시험이 검색 결과에 연결되는지 점검했다.
- 10개 질환의 공개 시험 50건에서 조건 202개를 구조화했다.
- 개발에 사용하지 않은 합성 환자 30명과 시험 5개씩을 연결해 150개 판단을 만들었다.
- 환자마다 추가 정보를 최대 세 번 확인했다.

확인 기회가 한 번뿐일 때, 입력 파일 순서대로 확인하면 최종 상태가 94/150개
(62.7%) 일치했고 여러 시험에 영향을 주는 정보를 먼저 확인하면 115/150개(76.7%)가
일치했다. 환자 30명 중 9명에서 좋아졌고 나빠진 환자는 없었다. 한 번의 확인으로
판단을 끝낸 시험도 환자당 2.20개에서 2.90개로 늘었다.

| 부족한 정보를 처리한 방법 | 최종 상태가 기대 결과와 같은 시험 | 실제 참가 가능 후보로 확정 | 결국 제외될 후보를 정리 |
|---|---:|---:|---:|
| 추가 확인을 하지 않음 | 28/150, 18.7% | 0/54 | 0/68 |
| 입력 파일에 적힌 순서대로 확인 | 141/150, 94.0% | 45/54 | 68/68 |
| 현재 가장 많은 시험에 연결된 정보부터 확인 | 143/150, 95.3% | 47/54 | 68/68 |
| 남은 세 번의 확인을 함께 고려해 정보 조합을 선택 | 143/150, 95.3% | 47/54 | 68/68 |

처음 화면에서 확인이 끝난 시험만 보여 주면 실제 참가 가능 후보 54개가 보이지 않는다.
ClarifyTrial은 54개를 추가 확인 후보로 남겼고 세 번 안에 47개를 실제 후보로 확정했다.
반대로 전체 상태에서 제외되는 후보 68개는 모두 정리했다. 다만 가장 많은 시험에
연결된 정보를 바로 고르는 단순한 방법과 최종 결과가 같았으므로, 복잡한 질문 순서
계산이 더 우수하다고 주장하지 않는다.

이동·비용·시간 제한이 있는 합성 상황에서는 모든 환자에게 같은 부담표를 적용했을 때보다
환자별 제한을 먼저 적용했을 때, 실제로 이용할 수 있는 방법 안에서 판단을 끝낸 비율이
81.0%에서 88.5%로 높아졌다. 피해야 할 새 검사 제안은 19회에서 0회, 추가 방문 제안은
46회에서 0회가 됐다. 두 부담 항목은 한 행동에 함께 붙을 수 있어 합쳐 세지 않는다.

### 공식 환자 10명 연결 점검

공식 대회 합성 환자 10명을 ClinicalTrials.gov 검색부터 결과 저장까지 실행했다.
원자료 후보 101건 가운데 질환 확인 단계에서 7건을 제거했고, 환자당 최대 3개씩 이
확인을 통과한 시험 25건을 판정했다. 한 환자에게는 관련 모집 시험이 없었고 다른 한 환자에게는
한 개만 있어 30건을 억지로 채우지 않았다.

- 구조화한 선정·제외 조건: 472개
- 공식 조건 원문과 글자 위치가 일치: 472/472개
- 추가 정보 확인 시도: 27회
- 모델 호출: 97회, 1,538,814토큰

모든 질문에 `unknown`을 입력한 연결 점검이므로 이 숫자는 최종 추천 정확도가 아니다.
실행에서 일반적인 정보 부족을 검토 모델이 7번 되풀이한 사실을 확인했고, 이후에는
근거 충돌이나 잘못된 확정 근거가 있을 때만 검토 모델을 부르도록 고쳤다.

### 기존 평가와 겹치지 않는 새 시험 점검

새 공개 시험 30건을 개발용 15건과 최종 평가용 15건으로 나눴다. 최종 평가에서는
합성 환자 25명과 시험 판단 75개를 사용했다. 객관적으로 구조화한 조건에서는 코드만
사용한 방법, 조건 판단 모델을 부른 방법, 조건 판단과 질문 문장 모델을 부른 방법이
모두 75개를 맞혔다. 외부 모델 호출은 각각 0회, 65회, 105회였다.

이 결과는 구조화된 수치·날짜 조건에 모델을 더 불러도 이득이 없음을 보여 준다.
임상시험 전체 조건이나 자유 문장 의료 판단에서 여러 모델 역할이 더 정확하다는
결과는 아니다.

자료별 정확한 역할과 모든 수치는 [검증 결과](docs/internal/CLARIFYTRIAL_VALIDATION_RESULTS.md)에서
확인할 수 있다.

## 연구에서 말할 수 있는 범위

질문 생성, 답변 반영, 관련 문서 검색, 여러 모델 역할, 비용을 고려한 정보 선택은 이미
선행연구에 있다. 현재 구현에서 중심적으로 보여 주는 부분은 다음과 같다.

- 참가 가능성이 남은 후보와 현재 자료로 확인이 끝난 시험을 분리한다.
- 추가 확인으로 되찾은 실제 후보와 결국 제외된 후보를 함께 센다.
- 질문 수뿐 아니라 새 검사, 추가 방문과 환자 선택을 같은 실행에서 기록한다.
- 검색, 조건 판단, 질문, 답변, 재판정과 결과 생성을 하나의 재현 가능한 흐름으로 잇는다.

현재 결과로 TrialGPT보다 전체 추천 성능이 높다고 말할 수 없다. 95.3%는 구조화한
규칙과 합성 답이 프로그램 전체를 올바르게 통과하는지 확인한 값이다.

## 실행

Python 3.11 이상이 필요하다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c constraints\research.txt -e ".[dev,retrieval-bm25,codex-subscription]"
.\.venv\Scripts\python.exe -m nltk.downloader punkt
.\.venv\Scripts\python.exe -m pytest -q
```

준비된 합성 사례에서 검색부터 질문 뒤 재판정까지 보려면 다음 명령을 실행한다.
기본값은 외부 언어모델을 부르지 않는다.

```powershell
.\.venv\Scripts\clarifytrial.exe run-full-ui --auto
```

공식 대회 형식의 `topics[num, title]` 파일을 자유 문장부터 실행하려면 다음과 같이
사용한다. 기본 검색기는 별도 시험 말뭉치를 요구하지 않고 ClinicalTrials.gov에서 현재
모집 중이거나 모집 예정인 시험을 찾는다. 이 명령은 외부 언어모델을 사용한다.

```powershell
New-Item -ItemType Directory -Force runs | Out-Null
Invoke-WebRequest `
  -Uri "https://raw.githubusercontent.com/skku-aihclab/aihc-lab/main/files/notice/healthcare-agentic-ai-challenge-2026/synthetic-patients.json" `
  -OutFile runs\official-synthetic-patients.json

.\.venv\Scripts\clarifytrial.exe run-challenge `
  --topics runs\official-synthetic-patients.json `
  --topic-id S001 `
  --topic-settings examples\challenge\topic-settings.json `
  --output runs\challenge-S001 `
  --confirm-model-run
```

`--topic-settings`는 선택 사항이다. 원본 환자 파일은 그대로 두고, 환자가 추가 방문을
할 수 있는지, 새 검사를 원하지 않는지, 빠른 확인과 부담 최소화 중 무엇을 더 중시하는지
같은 실행 조건만 별도 파일로 넣는다. 검색 결과가 비면 프로그램은 무관한 시험을 억지로
채우지 않고 `no_related_enrolling_trials` 결과를 저장한다.

별도 환자와 시험 파일을 넣는 방법, 평가자료 재생성, 일괄 평가와 보고서 생성 명령은
[실행과 실험 안내](docs/internal/CLARIFYTRIAL_V5_DEVELOPED_EXPERIMENT_GUIDE.md)에 있다.
