# ClarifyTrial

ClarifyTrial은 불완전한 환자 정보로 임상시험을 사전 선별할 때 다음 두 판단을
분리해서 다루는 연구 프로젝트다.

1. 가능성이 있으므로 후보로 계속 검토할 것인가
2. 현재 확보한 자료만으로 참가 조건을 확정할 수 있는가

두 번째 판단에 필요한 정보가 부족하면 기존 기록 조회, 환자가 답할 수 있는 질문,
공식 검사·의료진 확인 요청, 보류 가운데 적절한 다음 행동을 선택한다.

## 현재 상태

- 현행 연구계획과 구현 설계가 정리된 상태다.
- v5 실행 코드와 공통 평가 코어는 아직 구현하지 않았다.
- v5 구조의 실험은 아직 실행하지 않았으며 현재 성능은 미측정이다.
- 과거 합성 데모와 Solar 수치는 v5 성능이나 기준선으로 사용하지 않는다.
- 이 저장소에 있는 환자 사례는 합성 자료만 사용한다.

## 핵심 구조

```text
버전이 확인된 임상시험 조건 + 날짜와 출처가 있는 환자 상태표
        ↓
후보 검색과 선정·제외 조건별 판단
        ↓
환자 원문·시험 원문·날짜·수치에 대한 근거 검사
        ↓
후보 유지와 현재 확정을 따로 계산
        ↓
현재 정보가 부족할 때만 올바른 확인 경로 선택
        ↓
새 정보와 관련된 조건만 다시 판단
```

성능을 높이기 위한 전체 설계는 PRomop, TrialMatchAI, CLEAR-MATCH, TRIAGE,
MediQ, DQueST와 Fink 계열 연구에서 필요한 부분을 가져온다. 이 기능들을 새 연구
기여로 주장하지 않는다. ClarifyTrial v5가 검증하려는 중심은 같은 임상 사실이라도
자료의 날짜·출처·확인 절차에 따라 후보 보존과 현재 확정이 달라지는지를 정확히
평가하는 것이다.

## 평가 방향

서로 다른 목적의 평가를 한 점수로 합치지 않는다.

| 평가 | 자료 | 확인할 내용 |
|---|---|---|
| 조건별 판단 | TrialGPT Criterion Annotations | 조건 상태와 근거 선택 |
| 후보 검색 | TREC Clinical Trials | 관련 시험 검색과 순위 |
| 대화와 다음 행동 | 새 v5 합성 흐름 자료 | 후보 유지, 현재 확정, 확인 경로와 재판정 |

논문 구현은 다음 세 종류로 구분한다.

- 공식 코드 원형 실행: 저자 코드의 실행 가능 범위 확인
- 논문 기반 재구현: 공개된 구조만 구현하고 원 논문 재현이라고 부르지 않음
- 공통 환경 구조 비교: 같은 모델·근거·행동 환경에서 구조 차이를 비교하는 주 실험

## 다음 구현

첫 구현 단위는 개별 논문의 에이전트가 아니다.

1. 모든 시스템이 사용하는 공통 입력·출력 형식
2. 숨은 합성 환자 정보와 미리 정한 행동 결과를 가진 통제 환경
3. 후보 유지, 현재 확정과 다음 행동을 채점하는 공통 평가기
4. 가짜 시스템을 이용한 실행·채점 점검
5. TrialGPT 조건 판단과 TREC 검색 평가 연결

기반 모델, 유료 API, 일반 의료지식 검색과 무거운 TrialMatchAI 실행 환경은 평가
코어와 분리하며 첫 구현 전에 고정하지 않는다.
