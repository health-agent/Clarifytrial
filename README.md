**연구 검토용 공유본 · 2026-11-21**

학회 발표의 기준은 [9월 선정 원고](docs/internal/CLARIFYTRIAL_KOSMI_POSTER_MANUSCRIPT.md)다.
환자 정보가 서로 어떻게 연결되는지, 확인 기회와 환자 제한이 정보 선택에 어떤 차이를

먼저 [현재 판단과 남은 일](docs/internal/CURRENT_STATUS.md),
[발표 설명과 질의응답](docs/internal/CLARIFYTRIAL_REPORT_PRESENTATION_PACKET.md)을 읽으면 된다.
9월의 수치상 최고 86%는 방법 간 일반 우위나 동등성의 증거가 아니다.
후속 결과에서 재확인 허용·관측 근거·위험 교정의 개별 효과를 분리해 측정하지 않았다.

현재 포스터의 결과를 더 설명하는 [보강 분석](docs/internal/CLARIFYTRIAL_REPORT_PRESENTATION_PACKET.md#정보-선택-결과의-해석)을 추가했다.
기존 확인3회 기록의 환자별 첫 후보 확인과 공통·연쇄 구조의 작은 실행 예시이며,
초록의 방법·주요 수치와 기본 실행은 유지한다.

### 기록 우선 규칙을 추가한 최신 비교

기존 결과를 점검한 뒤 정책을 고정하고 새 합성 교정·평가 환자를 각각 1,200명 생성했다.
판정기·위험 기준·최대 확인 3회·방문 1회는 같다. 기록 우선은 한 단계 선택기가 고른
사실의 기록을 먼저 조회하고, 부족하면 다시 선택하는 규칙이다.

| 방법 | 올바른 수치 부분조건 /4,800 | 방문 | 오판 환자 /새 결론 환자 |
|---|---:|---:|---:|
| 기존 한 단계 | 3,657 (76.19%) | 1,133 | 21 /1,047 |
| 기록 우선 한 단계 | 3,758 (78.29%) | 726 | 25 /1,058 |
| 방문 벌점 .25의 한 단계 | 3,729 (77.69%) | 822 | 20 /1,057 |
| 두 단계 | 3,802 (79.21%) | 940 | 27 /1,062 |

두 단계는 기록 우선보다 44개를 더 맞혔지만 방문도 214회 더 썼다. 상태 일치 차이는
+0.92%포인트(합성 환자 재표집 95% 범위 +0.46~+1.40)다. 따라서 **단순 기록 우선
규칙 대비 판정과 방문의 동시 개선은 확인되지 않았다.** 방문 벌점 .05/.10을 포함한
여섯 정책 전체 결과와 재현 명령은 [최신 비교](docs/internal/results/risk-aware-acquisition-v1/README.md)에 있다.
이 결과에 맞춰 새 방법의 일괄 우위 주장을 좁혔다. 실제 환자 성능이나 임상 비용의 결과는 아니다.

기존 [포스터 PDF](docs/internal/presentation/clarifytrial-poster.pdf)·PPTX는 10월 후속 결과를
중심으로 만든 작업본이다. 11월 내용 점검과 비교군 보완을 반영한 최종 발표본으로 쓰지 않는다.
현행 내용은 위 문서와 최신 결과를 따른다.

## 작게 실행해 보기

Python 3.12에서 다음 명령으로 합성 점수 하나의 확인 순서를 실행한다. 외부 모델이나
API 키는 필요하지 않다. 저장 화면의 재생이 아니라 현재 선택 코드를 실행하는 예제다.

```powershell
git clone --branch codex/presentation-demo https://github.com/health-agent/Clarifytrial.git
cd Clarifytrial
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -X utf8 scripts/run_route_order_demo.py
.\.venv\Scripts\python.exe -X utf8 scripts/run_route_order_demo.py --record-missing
```

입력은 합성 `score >= 1` 조건과 값 0을 반환하는 두 경로다. 한 단계는 방문부터,
기록 우선과 두 단계는 기록 조회부터 고른다. 보고가 하나일 때는 보류하고 두 보고가
모이면 부분조건 위반으로 계산한다. 기록을 얻지 못하는 옵션에서는 방문 보고 하나만
남아 보류와 추가 근거 질문을 반환한다. 이 예제 자체는 성능 비교가 아니다.

저장된 실제 합성 기록을 클릭하며 보려면 [오프라인 시연](docs/internal/demo/clarifytrial-risk-replay.html)을
다운로드해 브라우저로 연다. 이것은 10월 세 사례의 저장 결과 재생이며 새 입력 실행과 다르다.

## 시스템의 흐름

환자 기록이 모자라면 임상시험 후보가 `정보 부족`에 머문다. ClarifyTrial은 이런 시험을
곧바로 버리지 않는다. 계속 확인할 후보인지 먼저 판단하고, 확인이 끝나려면 어떤 정보가
필요한지 찾는다. 답을 받으면 그 정보와 연결된 시험만 다시 계산한다.

가령 여러 시험이 최근 혈액검사를 요구하는데 환자 기록에는 오래된 결과만 있다고 하자.
프로그램은 최근 결과가 필요한 시험을 한꺼번에 찾고, 기록 조회나 환자 질문, 기존 검사
결과 확인, 새 검사 가운데 알맞은 방법을 제안한다. 새 결과가 들어오면 시험마다 다른
기준을 적용해 결과를 갱신한다.

## 작동 방식

```text
환자 자료와 임상시험 원문을 읽는다
→ 모집 중인 관련 시험을 찾는다
→ 선정 조건과 제외 조건을 현재 자료로 확인한다
→ 참가 가능성이 남은 시험과 이번 사전 검토 범위에서 확인이 끝난 시험을 따로 기록한다
→ 아직 필요한 환자 정보를 찾는다
→ 답을 얻을 수 있는 방법과 환자의 제한을 살핀다
→ 한 가지 정보를 확인한다
→ 그 정보가 쓰인 조건만 다시 계산한다
→ 시험별 결과와 근거, 남은 확인 사항을 저장한다
```

같은 환자 정보가 여러 시험에 쓰이면 한 번 받은 답을 함께 사용한다. 새 검사나 추가
방문을 원하지 않는 환자에게는 해당 방법을 제안하지 않는다. 이동과 비용이 부담되면
기존 자료를 우선하고, 시간이 급하면 더 빠른 방법을 찾는다. 이용할 수 있는 방법이
없으면 억지로 결론을 내리지 않고 확인 대기로 남긴다.

## 현재 구현된 범위

| 구간 | 동작 |
|---|---|
| 시험 검색 | ClinicalTrials.gov에서 모집 중인 시험을 찾고 환자의 질환과 관련된 후보를 남긴다. |
| 조건 계산 | 선정·제외 조건의 수치, 날짜, 예·아니오와 논리 관계는 모델을 부르지 않고 계산한다. |
| 시험 상태 | 계속 확인할 후보인지, 현재 자료로 확인을 마쳤는지 따로 기록한다. |
| 다음 확인 | 아직 필요한 환자 정보와 그 정보가 연결된 시험을 계산한다. |
| 확인 방법 | 기존 기록, 환자 답변, 이미 받은 공식 결과, 새 검사와 의료진 확인을 구분한다. |
| 환자 제한 | 새 검사·추가 방문 허용 여부와 시간·이동·비용 부담을 먼저 적용한다. |
| 답변 반영 | 새 답과 연결된 조건만 다시 계산하고 중단된 실행도 이어서 진행한다. |
| 결과 저장 | 판단 근거, 질문 전후 변화, 남은 정보, 확인 방법과 실행 기록을 남긴다. |

모델 호출이나 응답 형식에서 오류가 나면 정상 결과 파일을 만들지 않는다. 그때까지의 실행
기록과 오류 종류는 `trace.jsonl`과 `execution-error.json`에 남긴다. 같은 출력 폴더를
다시 쓰더라도 지난 성공 결과와 이번 실패 기록이 섞이지 않는다.

수치, 날짜와 예·아니오가 정리된 JSON은 코드가 판정 결과를 바로 만들며 조건 판단
모델에 보내지 않는다. 자유 문장이나 계산하기 어려운 조건이 남았을 때만 언어모델을
부른다. 언어모델은 환자가 허용한 확인 횟수나 방법을 바꿀 수 없다. 내부 역할과 종료
조건은 [프로그램 설계](docs/internal/CLARIFYTRIAL_AGENT_ARCHITECTURE_REDESIGN.md)에
정리돼 있다.

합성 환자 한 명의 전체 흐름에서 이 배치를 점검했다. 조건 판단 호출은 3회에서 0회,
전체 모델 호출은 5회에서 2회, 사용량은 72,659토큰에서 23,707토큰으로 줄었다. 최종
시험 다섯 건의 상태와 확인한 정보 순서는 같았다. 한 사례에서 역할 연결과 사용량을
확인한 결과다.

## 이전 시스템 연구: 공개 시험 50건의 결과

공개 임상시험 50건에서 조건 202개를 구조화했다. 10개 질환의 합성 환자 50명을 만들고,
그중 20명은 자료와 규칙을 다듬는 데 썼다. 최종 평가는 나머지 30명에게 시험 5건씩을
연결해 진행했다. 나이, 임신·수유 여부, 활동성 중증 감염처럼 기본 문진에서 확인할
정보는 처음부터 제공했다.

환자-시험 조합 150개 가운데 28개는 처음 환자 자료만으로 이미 상태가 정리돼 있었다. 세 기본 정보를
더하자 명확히 제외할 수 있던 68건과 참가 가능 후보 32건이 추가로 정리됐다. 질문 전
상태가 정해진 조합은 모두 128개였고, 나머지 22개가 추가 정보를 기다렸다. 따라서
아래의 63.6%는 이 22건 안에서 질문이 만든 변화다.

환자마다 한 번까지 확인하도록 하자 실제 질문은 14번 나왔고, 질문을 받은 14명 모두
시험을 한 건 이상 정리했다. 모두 14건이 확인 완료로 바뀌어 시작 당시 미확정 시험의 63.6%를 정리했고
8건은 확인 대기로 남았다. 이미 입력된 나이를 다시 묻는 질문은 없었다.

어떤 정보를 먼저 물었는지에 따른 차이는 작았다. 가능한 질문 순서를 모두 실행한 평균은
94.22%, 현재 규칙은 94.67%의 시험 상태가 합성 정답과 같았다. 환자 30명 가운데 1명만
좋아졌고 29명은 같았다. 처음 실험에서 나온 36.5%포인트 차이는 기본 문진에 들어갈
나이·임신·감염 정보까지 가렸을 때의 값이다. 현재 결과에는 질문으로 정리된 14건과
계속 기다린 8건을 함께 제시한다.

질문 순서가 언제 도움이 되는지도 따로 살폈다. 정보 연결 모양 9종을 각각 200개씩 만든
1,800개 구조에서 확인을 2회와 3회 허용하고 단계별 무작위, 현재 영향 우선과 앞으로
확인할 정보 조합을 계산하는 방법을 함께 비교했다. 여러 시험이 한 정보에 직접 묶인
구조에서 현재 규칙은 단계별 무작위보다 19.03~30.09%포인트 높았고 조합 계산의 추가
이점은 없었다. 시험마다 필요한 정보가 분리된 구조에서는 세 방법의 차이가 없었다.
사슬형 구조에서는 조합 계산이 현재 규칙보다 3.22~4.27%포인트 높았다. 전체 구조
평균에서 두 방법의 차이는 1.2~2.0%포인트였다. 확인 1회 결과는 첫 질문의 즉각적인
효과를 분리해 본 보조 분석으로만 남겼다.

이 수치는 합성 환자와 선별한 구조화 조건에서 프로그램의 상태 변화를 확인한 결과다.
실제 환자의 참가 판정 정확도나 TrialGPT와의 우열을 나타내지 않는다.

## 환자 상황을 반영한 결과

같은 답을 얻는 방법이 둘일 때 환자 상황에 따라 확인 방법이 바뀌는지 점검했다. 부담과
이동·비용을 줄이는 설정에서는 기존 공식 결과를 85번 모두 골랐고, 시간이 급한
설정에서는 빠른 새 검사를 85번 모두 골랐다. 어떤 정보를 확인할지와 최종 시험 상태는
40개 사례에서 그대로 유지됐다.

새 검사와 추가 방문을 허용하지 않은 합성 상황에서는 새 검사 제안이 21회에서 0회,
추가 방문 제안이 56회에서 0회로 줄었다. 대신 설정 하나에 남은 확인 대기 시험은 평균
0.88건에서 1.24건으로 늘었다. 시험 다섯 건을 모두 정리한 설정도 80개 중 42개에서
32개로 줄었다. 환자의 제한을 지키면 일부 시험의 결론을 더 기다려야 한다는 점까지
결과에 남는다.

시간과 부담은 선택 규칙을 점검하려고 정한 합성 값이다. 실제 병원의 대기시간이나
환자가 얻을 편익을 추정한 값으로 사용하지 않는다.

## 실행

재현이 확인된 환경은 Windows와 Python 3.12다. Python 3.13은 현재 고정한 연구용
의존성과 맞지 않으므로 지원하지 않는다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c constraints\repro-python312.txt -e ".[dev,retrieval-bm25]"
.\.venv\Scripts\python.exe -m nltk.downloader punkt
.\.venv\Scripts\python.exe -m pytest -q
```

TrialGPT 방식의 의미 검색이나 외부 모델 실행이 필요할 때만 선택 기능을 추가한다.

```powershell
.\.venv\Scripts\python.exe -m pip install -c constraints\research.txt -e ".[retrieval,codex-subscription]"
```

준비된 합성 사례에서 검색, 질문, 답변과 재판정을 한 번에 실행한다. 이 예제는 외부
언어모델을 부르지 않는다.

```powershell
.\.venv\Scripts\clarifytrial.exe run-full-ui --auto
```

터미널에서 직접 답하려면 `--auto`를 뺀다. 별도 환자·시험 JSON과 공식 대회 형식의
입력은 [실행과 실험 안내](docs/internal/CLARIFYTRIAL_V5_DEVELOPED_EXPERIMENT_GUIDE.md)에
예시가 있다.

## 결과 재현

다음 명령은 별도 API 키 없이 전체 검사, 공개 시험 50건·합성 환자 30명의 핵심 평가,
환자별 확인 방법과 부담 제한 평가를 실행한다. 끝나면 커밋된 발표 근거와 파일·수치를
비교해 `reproduction-report.json`을 만든다.

```powershell
.\scripts\reproduce_core.ps1 -Mode package
```

고정값을 사용한 연결 구조 1,800개까지 다시 계산하려면 `-Mode core`를 사용한다. 이
대량 계산은 발표 수치가 이미 검증된 상태에서 매번 반복할 필요는 없다.

확인 한도 1·2·3회를 모두 실행해 연결 구조 계산 2,073,600회와 발표용 표·그림까지 다시
만들려면 다음 명령을 사용한다. 기존 결과를 지우지 않으므로 같은 출력 폴더가 있으면
`-OutputRoot`로 새 폴더를 지정한다.

```powershell
.\scripts\reproduce_core.ps1 -Mode full -OutputRoot runs\reproduction-full
```

실제 모델을 호출한 합성 환자 한 사례는 모델 성능값이 아니며 완전 동일하게 다시 생성할
수도 없다. 전체 재현 명령은 이 관찰값을 다시 호출하지 않고, Git에 저장한 요약을 발표
근거 묶음에 포함한다.
