# ClarifyTrial v5 쉬운 전체 계획

문서 역할: ClarifyTrial의 진행 방식과 실험 순서를 쉬운 말로 설명  
문서 우선순위: [CLARIFYTRIAL_RESEARCH_PLAN_V5.md](CLARIFYTRIAL_RESEARCH_PLAN_V5.md)  
현재 단계: 정해진 형식의 JSON으로 질문 순서 평가 완료, 자유 형식 입력은 선택 기능

---

## 1. 무엇을 만드는가

ClarifyTrial은 환자에게 맞을 가능성이 있는 임상시험을 찾고, 참가 조건과
환자 정보를 비교하는 도구다.

환자 자료에는 빈칸이 자주 생긴다.

- 최근 혈액검사 결과가 빠질 수 있다.
- 현재 복용 중인 약이 빠질 수 있다.
- 과거 치료 날짜가 빠질 수 있다.

ClarifyTrial은 필요한 빈칸을 찾고, 병원 기록이나 환자 답변으로 채운 뒤,
새 정보를 반영해 참가 가능성을 다시 판단한다.

연구의 기본 입력은 환자 사실과 시험 조건을 정해진 항목에 담은 JSON이다. 자유 형식
진료기록을 JSON으로 바꾸는 과정은 선택 연결 기능이며 현재 성능 평가에 포함하지 않는다.

---

## 2. 기본 진행 방식

### 1단계. 환자 자료에서 일부 항목을 빈칸으로 둔다

실험 제작자가 연구용 환자 사례를 만든다. 최근 검사 결과, 복용 약, 치료 날짜
같은 항목 가운데 일부를 빈칸으로 둔다.

이렇게 하면 실제 사전 검토에서 자료가 덜 모인 상황을 재현할 수 있다.

### 2단계. 현재 자료와 임상시험 참가 조건을 비교한다

예를 들어 임상시험 참가 조건에 다음 내용이 있다고 하자.

- 만 18세 이상
- 최근 14일 안에 받은 혈액검사 결과
- 특정 약을 복용 중인 사람 제외

ClarifyTrial은 현재 환자 자료로 확인되는 조건과 빈칸으로 남은 조건을 구분한다.

### 3단계. 빈칸을 채울 방법을 고른다

빈칸의 종류에 따라 다음 방법을 고른다.

- **병원 기록 확인:** 이미 받은 검사 결과나 치료 기록을 찾아본다.
- **환자에게 질문:** 복용 약, 증상, 생활 습관처럼 환자가 직접 답할 수 있는 내용을 묻는다.
- **담당자에게 전달:** 새 검사나 의사의 판단이 필요한 항목을 임상시험 담당자에게 보여준다.
- **판단 대기:** 필요한 정보가 들어올 때까지 현재 상태를 유지한다.

### 4단계. 선택한 방법에 맞는 정보 카드가 나타난다

실험 제작자는 각 환자에게 보여줄 정보 카드를 준비한다.

예를 들어 다음처럼 작동한다.

- ClarifyTrial이 `병원 기록 확인`을 고른다.
- 화면에 `4월 3일 혈액검사 결과: 기준 범위 안` 카드가 나타난다.
- ClarifyTrial이 `환자에게 질문`을 고른다.
- 화면에 `환자 답변: 현재 A약을 매일 복용 중` 카드가 나타난다.

모든 비교 방식은 같은 행동을 고르면 같은 카드를 받는다. 따라서 어떤 방식이
더 좋은 판단을 했는지 같은 환자 정보로 비교할 수 있다.

### 5단계. 새 정보를 넣어 다시 판단한다

ClarifyTrial은 새로 받은 정보를 임상시험 조건에 반영한다. 결과 화면에는
다음 내용이 함께 나온다.

- 계속 검토할 임상시험
- 현재까지 확인된 조건
- 추가로 필요한 정보
- 판단에 사용한 환자 자료와 임상시험 문장

## 3. 추가하는 기능

기존 화면에서는 참가 가능성을 한 가지 상태로 표시한다.

새 화면에서는 다음 두 질문을 따로 표시한다.

### 질문 1. 후보로 계속 검토할까

현재 자료에서 참가 가능성이 보이면 다음 확인 단계로 보낸다.

### 질문 2. 지금 가진 자료로 조건 확인을 끝낼 수 있을까

임상시험이 요구하는 날짜와 검사 방법을 만족하는 자료가 준비됐을 때
조건 확인 완료로 표시한다.

이 두 질문을 나누면 다음 상태를 분명하게 보여줄 수 있다.

> 참가 가능성은 보인다. 그래서 계속 검토한다. 최근 검사 결과가 들어오면
> 조건 확인을 끝낼 수 있다.

여러 시험에 같은 빈칸이 있을 때는 남은 질문 횟수 안에서 가장 많은 시험의 확인을
끝낼 수 있는 정보 묶음을 먼저 계산한다. 예를 들어 질문을 두 번만 할 수 있다면,
시험 세 개에 이름만 걸쳐 있는 정보보다 두 번 확인해서 시험 두 개를 실제로 끝낼 수
있는 정보 묶음을 고른다. 숨은 답을 미리 보거나 정답 확률을 추측하지 않는다.

## 4. 쉬운 예시

### 임상시험 참가 조건

최근 14일 안에 받은 혈액검사 수치가 기준 안에 들어와야 한다.

### 현재 환자 자료

환자에게는 3개월 전에 받은 혈액검사 결과가 있다. 당시 수치는 참가 조건에
들어온다.

### 질문 1의 답

**후보로 계속 검토한다.** 3개월 전 검사 결과를 보면 참가 가능성이 보인다.

### 질문 2의 답

**최근 검사 결과 대기.** 최근 14일 안에 받은 검사 결과가 들어오면 조건
확인을 끝낼 수 있다.

### 다음 할 일

임상시험 담당자에게 최근 혈액검사 결과가 필요하다고 보여준다.

### 새 결과가 들어온 뒤

- 새 검사 수치가 기준 안에 들어오면 `조건 확인 완료`로 바꾼다.
- 새 검사 수치가 기준을 벗어나면 `참가 조건 불충족`으로 바꾼다.
- 검사 일정이 잡힌 상태라면 `최근 검사 결과 대기`를 유지한다.

## 5. 실험 문제를 만드는 방법

### 임상시험과 조건 선택

공개된 임상시험 15개에서 객관적으로 계산할 수 있는 참가 조건 80개를 골라 첫
평가자료를 만들었다.

다음처럼 일반인이 읽어도 상황을 그릴 수 있는 조건을 우선 사용한다.

- 나이
- 검사 날짜
- 혈액검사 수치
- 과거 치료 날짜
- 현재 복용 중인 약
- 병원 기록에 적힌 진단

### 한 부분만 바꾼 두 문제 만들기

환자의 나이, 병력과 검사 수치는 그대로 두고 한 부분만 바꾼다.

예시 1:

- 문제 A: 혈액검사를 3개월 전에 받음
- 문제 B: 같은 혈액검사를 어제 받음

예시 2:

- 문제 A: 환자가 기억으로 검사 결과를 말함
- 문제 B: 병원에서 발급한 검사 결과지가 있음

예시 3:

- 문제 A: 참가 가능성이 있는 사람을 찾는 첫 검토 단계
- 문제 B: 모든 참가 조건을 최종 확인하는 단계

한 부분만 바꾸면 그 차이가 두 질문의 답에 어떤 영향을 주는지 바로 볼 수 있다.

### 정답 작성

각 문제에는 다음 답을 붙인다.

1. 후보로 계속 검토할까
2. 지금 조건 확인을 끝낼 수 있을까
3. 다음에 필요한 정보는 무엇인가
4. 판단에 사용한 환자 자료와 임상시험 문장은 무엇인가

두 명이 각자 답을 작성한 뒤 서로의 답을 비교한다. 가능하면 임상시험 참가
조건을 검토하는 담당자나 의사가 한 명 참여한다.

### 같은 정보라도 얻는 방법을 나눈다

예를 들어 최근 혈액검사 결과가 없을 때 다음 상황은 서로 다르다.

- 병원 전산에 이미 결과가 있음
- 다른 병원에서 기존 결과지를 받아야 함
- 오늘 진료에서 같은 검사를 받을 예정임
- 이 임상시험을 검토하려고 새로 방문해 검사해야 함

각 방법에 기다리는 시간, 방문, 비용, 통증, 위험과 치료 변경 여부를 따로 붙인다.
환자가 피로하거나 이동이 어렵고 비용 부담이 큰 경우와, 모집 종료가 가까워 시간이
급한 경우도 같은 임상값으로 따로 만든다.

시스템은 기존 자료로 해결할 수 있는 일을 새 검사로 보내면 안 된다. 새 검사,
침습 절차나 약물 변경이 필요하면 자동으로 진행하지 않고 예상되는 이득과 부담을
환자와 의료진에게 보여 준다.

### 환자가 부담 정보를 입력하지 않아도 된다

환자는 이동 어려움, 추가 비용 걱정, 빨리 확인해야 하는 사정 등을 입력할 수 있다.
아무것도 입력하지 않아도 임상시험 후보는 그대로 검토한다. 시스템은 부담이 없다고
짐작하지 않고 `미확인`으로 표시하며, 빠른 확인과 낮은 부담을 한쪽으로 치우치지 않게
살피는 방식을 기본으로 쓴다. 새 검사나 치료 변경은 기본값만으로 진행하지 않는다.

### 결과는 이렇게 보여 준다

예를 들어 최근 혈액검사 결과가 필요하지만 현재 기록에는 없다고 하자.

1. 현재 후보: 추가 확인이 필요한 시험 3개
2. 다음 확인: 다른 병원이나 병원 전산에 기존 결과가 있는지 먼저 확인
3. 이유: 같은 결과가 시험 3개의 조건 확인에 쓰임
4. 예상 부담: 새 방문 없음, 비용 미확인, 대기 시간 미확인
5. 다른 방법: 기존 결과가 없으면 새 검사 여부를 환자와 의료진이 결정
6. 확인 뒤 변화: 수치에 따라 후보가 확정되거나 제외될 수 있음

연구자와 의료진에게는 같은 내용에 사실·조건·시험 번호, 사용한 기본값, 다른 방법을
고르지 않은 이유와 사람 승인이 필요한지를 함께 남긴다.

## 6. 질문 순서를 비교하는 방법

모든 방식은 후보 유지와 현재 확인을 따로 표시한다. 비교하는 차이는 부족한 정보를
어떤 순서로 확인하는가다.

### 질문하지 않음

처음 자료만으로 판단하고 추가 정보를 확인하지 않는다.

### 고정 순서

시험 문서와 자료에 먼저 나온 정보부터 확인한다.

### 현재 방식

남은 확인 횟수 안에서 가장 많은 시험의 판단을 끝낼 수 있는 정보 묶음을 계산한다.
한 항목을 확인할 때마다 남은 시험 상태를 다시 계산해 다음 항목을 고른다.

### 비교 조건

두 방식에 똑같은 내용을 준다.

- 같은 환자 자료
- 같은 임상시험 참가 조건
- 같은 병원 기록 카드
- 같은 환자 답변 카드
- 같은 인공지능
- 같은 확인 횟수

이렇게 하면 모델이나 환자 답의 차이가 아니라 질문 순서의 차이를 비교할 수 있다.

## 7. 무엇을 세는가

### 1. 가능성 있는 환자를 검토 목록에서 뺀 횟수

계속 검토할 가치가 있는 환자를 일찍 뺀 사례를 센다.

### 2. 필요한 자료가 오기 전에 조건 확인을 끝낸 횟수

최근 검사 결과나 담당자 검토가 필요한데도 조건 확인 완료로 표시한 사례를 센다.

### 3. 알맞은 방법으로 빈칸을 채운 횟수

- 병원 기록에 있는 내용을 기록에서 찾았는가
- 환자가 답할 수 있는 내용을 환자에게 물었는가
- 새 검사나 의사 판단이 필요한 항목을 담당자에게 전달했는가

### 4. 확인 횟수

환자 질문 수, 병원 기록 확인 수, 담당자 전달 수를 각각 센다.

### 5. 필요한 정보를 골랐는가

같은 확인 횟수 안에서 가장 좋은 결과를 내는 가장 작은 정보 묶음을 실행 뒤에 계산한다.
여러 묶음이 같은 결과를 내면 모두 정답으로 인정한다. 시스템이 실제로 고른 정보가
이 정답 묶음을 얼마나 포함했는지 센다. 숨은 답은 질문 순서를 정할 때 사용하지 않는다.

### 6. 결과를 더 바꾸지 않은 확인

실제로 답을 받은 뒤에도 최종 판정 일치율을 더 높이지 않은 확인을 센다. 이 값은 답을
미리 알았다면 피할 수 있었다는 뜻이 아니라, 실행 뒤 질문 효율을 살펴보는 값이다.

### 7. 기준과 현재 값의 차이

숫자나 기간 조건 때문에 참가 조건 불충족이 확정됐으면 현재 값이 기준보다 얼마나
높거나 낮은지 표시한다. 서로 다른 검사와 기간의 차이를 하나의 점수로 합치지 않는다.

6. 완료 — 입력 없음·일부 입력의 기본 규칙과 두 결과 형식을 구현
7. 완료 — 새 검사와 위험한 절차가 자동 실행되지 않는지 검사
8. 완료 — 같은 환자에서 이동·비용·시간 부담만 바꾼 360개 상황을 다섯 방식으로 실행
9. 완료 — 정해진 형식의 공개 조건을 쓰는 전체 실행 흐름에 환자 맞춤 질문 규칙 연결
10. 완료 — 합성 자연어 기록을 읽고 질문 없음·고정 순서·ClarifyTrial을 0~5회에서 비교
11. 완료 — 남은 확인 횟수 안의 정보 조합을 모두 계산하는 현재 방식을 일반 실행에 연결
12. 완료 — 새 평가 환자 30명의 핵심 값 다섯 개를 모두 지운 조건을 0~5회에서 실행
13. 완료 — 필요한 정보 선택률, 결과를 더 바꾸지 않은 확인과 미정 해소 수 집계
14. 완료 — 숫자·기간 기준의 차이 출력과 질문 과정을 보여 주는 텍스트 화면 구현
15. 완료 — 새 환자·시험 JSON을 받는 일반 실행 명령과 터미널 직접 답변 구현
16. 완료 — 중단한 실행을 저장된 세션에서 이어가는 기능 구현
17. 완료 — 세 질문 방식을 같은 전체 흐름에서 30명에게 일괄 실행
18. 완료 — 환자별 병렬 실행과 호출·토큰·시간 집계
19. 완료 — 여러 실험 결과에서 표·SVG·Markdown 보고서 자동 생성

## 9. 결과를 읽는 방법

현재 질문 순서가 의미를 가지려면 다음 모습이 나와야 한다.

- 같은 확인 횟수에서 더 많은 시험의 판단을 끝낸다.
- 가능성 있는 환자를 잘못 빼거나 자료가 오기 전에 확정하지 않는다.
- 기존 기록이나 환자 답변으로 알 수 있는 내용을 새 검사로 보내지 않는다.
- 불필요한 환자 질문과 병원 기록 확인이 줄어든다.

고정 순서와 결과가 비슷하면 연구 결과를 예비 시연 수준으로 정리한다.

## 10. 현재 말할 수 있는 범위

- 정해진 형식으로 옮긴 공개 시험 조건에서 질문 순서를 고르는 실험은 실행했다.
- 답의 확률을 가정한 질문 나무는 쓰지 않는다. 대신 남은 질문 횟수 안의 작은 정보
  조합을 모두 계산하는 현재 방식을 사용한다.
- 환자 맞춤 부담 구조 실험은 실행했지만 실제 환자 선호나 실제 비용을 측정하지 않았다.
- 합성 자연어 기록과 고정 후보 흐름은 평가했지만 실제 진료기록과 임상 성능은
  아직 측정하지 않았다.
- 핵심 값이 완전히 빠진 조건은 같은 합성 환자에서 실행했으며, 실제 병원 기록의 결측
  양상을 대표한다고 주장하지 않는다.
- 연구 자료에는 연구진이 예시로 만든 환자 사례를 사용한다.

## 11. 마지막 요약

기본 진행 방식은 환자 자료의 빈칸을 찾고, 병원 기록이나 환자 답변으로 채운 뒤,
후보 유지와 현재 확인 상태를 다시 판단하는 것이다. 빈칸이 여러 개면 남은 횟수 안에
더 많은 시험의 판단을 끝낼 수 있는 정보를 먼저 확인한다.

환자 맞춤 구조 실험에서는 같은 정보를 기존 자료로 확인할 수 있는지, 새 검사가 필요한지,
환자에게 시간·이동·비용·절차 부담이 얼마나 새로 생기는지를 함께 본다. 부담이 큰
행동은 시스템이 자동으로 실행하지 않고 환자와 의료진의 선택으로 남긴다.

새 합성 환자 30명에서 질문 순서만 계산한 평가에서는 세 번 확인 뒤 고정 순서 75.3%,
현재 방식 88.7%였다. 검색·조건 판단·질문·답변·재판정을 실제 실행기에 모두 연결한
평가에서는 질문 없음 42%, 고정 순서 66%, 현재 방식 77%였다. 두 결과는 검사한 범위가
달라 따로 보고한다.

같은 환자의 핵심 값 다섯 개를 모두 지운 조건에서도 질문 세 번 뒤 현재 방식은 88.7%,
고정 순서는 75.3%였다. 현재 방식은 필요한 정보 묶음을 모두 포함했고, 총 88번 확인
가운데 실행 뒤 보니 결과를 더 바꾸지 않은 확인은 9번이었다.

첫 구조 실험에서는 새 검사를 금지하지 않은 상황의 후보 회복을 거의 유지하면서, 이동·비용 제약
상황에서는 허용하지 않은 새 검사와 방문을 선택하지 않았다. 시간 긴급 상황에서는
영향받는 시험 수가 같은 확인 방법 중 더 빠른 방법을 골랐다. 이 결과는 연구진이 만든 부담값에서
규칙이 의도대로 움직였다는 뜻이며 실제 환자의 부담이 줄었다는 뜻은 아니다.
