## 1. 결과를 나누어 보는 이유

현재 결과는 세 종류다. 서로 목적과 정답 작성 방법이 달라 하나의 총점으로 합치지 않는다.

| 결과 종류 | 확인한 것 | 이 결과로 말할 수 없는 것 |

| 통합 점검 | 검색·판정·질문·답변·재판정이 정해진 규칙대로 이어지는가 | 임상 판단 정확도 |

## 3. 공개 시험 기반 통합 점검

### 3.1 자료

팀이 공개한 ClinicalTrials.gov 시험 1,931건 가운데 모집 중·모집 예정 589건을 검색
대상으로 사용했다. 10개 질환에서 시험 5건씩 골라 50건의 일부 조건을 구조화했다.

| 항목 | 수 |
|---|---:|
| 질환 | 10개 |
| 공개 임상시험 | 50건 |
| 구조화 조건 | 202개 |
| 복합 조건 | 3개 시험·4묶음 |
| 합성 환자 | 50명: 개발 20명·별도 평가 30명 |
| 환자–시험 조합 | 250개: 별도 평가 150개 |

나이, 단일 수치 비교, 명확한 참거짓 상태, 짧은 원문 조건과 원문에서 개수 관계가
분명한 네 묶음만 사용했다. 예외가 많거나 시험군에 따라 달라지는 문장은 제외했다.
따라서 202개는 시험 50건의 전체 참가 조건이 아니다.

합성 환자는 먼저 전체 상태를 정하고, 그중 판단에 필요한 정보 1개·2개·3개 또는 5개를
가려 시작 자료를 만들었다. 질문 뒤 답은 숨겨 둔 전체 상태에서만 꺼냈다. 나이와
임신·수유 사실이 모순되지 않도록 생식 가능 연령 밖에서는 해당 사실을 가리지 않았다.

### 3.2 질문 순서 비교

별도 평가 환자 30명에게 시험 5개씩 연결하고 추가 확인을 최대 세 번 허용했다.

| 다음 정보를 고른 방법 | 최종 상태 일치 | 실제 후보 확정 | 제외 후보 정리 | 환자당 평균 확인 |
|---|---:|---:|---:|---:|
| 추가 확인 없음 | 28/150, 18.7% | 0/54 | 0/68 | 0.00회 |
| 입력 파일에 적힌 순서 | 141/150, 94.0% | 45/54 | 68/68 | 2.00회 |
| 지금 가장 많은 시험에 연결된 정보 우선 | 143/150, 95.3% | 47/54 | 68/68 | 1.83회 |
| 남은 확인 횟수 전체를 계산 | 143/150, 95.3% | 47/54 | 68/68 | 1.83회 |

최종 상태는 후보 유지 여부와 현재 조건 확인 완료 여부를 모두 맞혀야 일치로 셌다.
남겨야 할 시험을 잘못 제외한 수, 정보가 부족한데 참가 가능으로 확정한 수와 실행
실패는 모두 0개였다.

남은 횟수 전체를 계산한 방법은 입력 순서보다 환자 1명에서 좋고 29명에서 같았으며
낮은 환자는 없었다. 평균 차이는 1.3퍼센트포인트였고 환자 단위 양측 부호검정 값은
`p=1.0`이었다. 지금 가장 많은 시험에 연결된 정보를 고르는 방식과는 30명 모두 같았다.
복잡한 계산의 우월성을 보여 주는 결과는 아니다.

## 4. 기존 평가와 겹치지 않는 새 시험

### 4.1 자료와 정답

기존 통합 점검의 시험 50건과 겹치지 않는 공개 시험 30건을 골랐다. 점액진균증,
방광암, 폐섬유증, 급성 췌장염, 그레이브스병에서 시험 6건씩 사용했다.

| 구분 | 시험 | 조건 | 합성 환자 | 환자–시험 판단 |
|---|---:|---:|---:|---:|
| 개발 | 15건 | 63개 | 25명 | 75개 |
| 최종 평가 | 15건 | 53개 | 25명 | 75개 |

최종 정답은 현재 실행 코드와 별도로 만든 계산기가 구조화된 연산자와 환자값을 읽어
계산했다. 최종 실행 전에 JSON으로 고정했으며, 개발 시험과 최종 시험은 겹치지 않는다.

### 4.2 같은 자료에서 모델 호출 방식 비교

| 모델 호출 구조 | 최종 상태 일치 | 실제 후보 확정 | 제외 후보 정리 | 잘못 제외 | 성급한 확정 | 실행 실패 | 외부 호출 | 토큰 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 구조화 규칙만 사용 | 75/75 | 36/36 | 23/23 | 0 | 0 | 0 | 0 | 0 |
| 조건 판단 모델만 사용 | 75/75 | 36/36 | 23/23 | 0 | 0 | 0 | 65 | 1,033,320 |
| 코드가 순서를 통제하고 조건 판단·질문 문장 역할 호출 | 75/75 | 36/36 | 23/23 | 0 | 0 | 0 | 105 | 1,565,829 |

모델은 GPT-5.6 Sol `medium`을 사용했다. 세 방식의 최종 결과와 환자 단위 95% 구간은
모두 100.0%였다. 선택적 검토가 필요하다고 판정된 사례도 없었다.

이 자료의 조건은 수치·날짜·참거짓으로 완전히 구조화돼 있다. 모델을 부른 두 방식에서도
코드는 최종 안전 규칙을 유지했다. 조건 판단 모델 출력이 구조화 계산과 달라 코드값을
쓴 판정 단계는 각각 65회와 59회였다. 같은 사례를 질문 전후에 여러 번 볼 수 있으므로
이 숫자는 서로 다른 임상 오류 수가 아니라 판정 단계 수다.

모델 호출을 늘려도 결과가 좋아지지 않았다. 구조화된 JSON은 코드로 처리하고, 모델은
자유 문장 조건의 뜻을 구조화해야 할 때만 부르는 현재 기본값을 뒷받침한다. 자유 문장
조건 해석 성능과 여러 에이전트의 정확도 향상은 이 실험에서 평가하지 않았다.

원시 실행을 묶은 결과는 [모델 호출 방식 비교](results/independent-new-trial-agent-evaluation-v1/report.md)에 있다.

## 5. TREC 시험 검색

TrialGPT가 사용한 BM25와 MedCPT를 같은 TREC 자료에서 다시 실행하고 두 순위를 합쳤다.

| 자료 | 검색 방식 | 관련 시험을 상위 500개 안에 남긴 비율 | 순위 점수 |
|---|---|---:|---:|
| TREC 2021 | BM25 | 79.07% | 66.22% |
| TREC 2021 | MedCPT | 80.44% | 66.25% |
| TREC 2021 | 두 검색 결합 | **83.59%** | **69.97%** |
| TREC 2022 | BM25 | 78.75% | 66.98% |
| TREC 2022 | MedCPT | 78.95% | 66.83% |
| TREC 2022 | 두 검색 결합 | **81.55%** | **70.11%** |

다시 실행한 값과 TrialGPT 공개 자료의 차이는 두 해 모두 0.1퍼센트포인트보다 작았다.
따라서 관련 시험을 먼저 찾는 검색 단계는 TrialGPT 방식과 같은 수준으로 재현됐다.
이 표에는 조건 판단, 질문과 최종 추천 성능이 포함되지 않는다.

## 6. 질문 전 한 번의 조건 판단

지시문 작성에 사용하지 않은 환자 33명·조건 654개를 TrialGPT 전문가 답과 비교했다.

| 방식 | 전문가 답 이름과 일치 |
|---|---:|
| ClarifyTrial 조건 판단 | 517/654, 79.1% |
| TrialGPT 공개 답 | 581/654, 88.8% |

ClarifyTrial의 답 이름 일치율은 TrialGPT보다 낮다. 다만 개발 자료에서 마지막까지 남은
오답 51개 중 47개는 `판단 가능`과 `정보 부족` 사이의 구분이었다. ClarifyTrial에서는
두 답 모두 시험을 바로 버리지 않고 추가 확인 후보로 남긴다. 실제 다음 행동이 같은
답 이름을 맞추기 위해 계속 조정하지 않았으며, 이 표로 TrialGPT보다 높거나 같은 조건
판단 성능을 주장하지 않는다.

## 8. 해석 범위

- 환자 자료는 모두 합성이다.
- 구조화한 조건은 각 시험의 일부이며 전체 참가 조건이 아니다.
- 통합 점검 95.3%는 같은 구조화 규칙으로 만든 기대 상태까지의 회복률이다.
- 새 시험 100%는 별도 계산기로 고정한 객관적 구조화 조건의 결과다.
