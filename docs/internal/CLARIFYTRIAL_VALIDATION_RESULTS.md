# ClarifyTrial 검증 결과

기준일: 2026-08-29

이 문서가 현재 수치의 기준이다. 프로그램 연결 점검, 검색 성능, 조건 판단 성능과
모델 호출 비교는 서로 다른 자료를 사용하므로 한 점수로 합치지 않는다.

## 1. 먼저 알아야 할 표현

| 표현 | 계산 방법 |
|---|---|
| 최종 상태 일치 | 후보 유지 여부와 현재 확인 상태가 합성 환자의 숨겨 둔 전체 상태에서 기대한 결과와 모두 같음 |
| 실제 후보 확정 | 처음에는 정보가 부족했지만 전체 상태에서는 참가 가능한 시험을 질문 뒤 확인함 |
| 제외 후보 정리 | 처음에는 정보 부족으로 남았지만 전체 상태에서는 부적합인 시험을 질문 뒤 제외함 |
| 잘못된 후보 제거 | 전체 상태에서는 참가 가능한 시험을 후보에서 제외함 |
| 너무 이른 확인 | 필요한 정보가 남았는데 현재 확인이 끝났다고 표시함 |
| 구조화한 조건 | 수치, 날짜, 예·아니오와 논리 관계를 코드가 직접 계산할 수 있도록 나눈 조건 |

`실제 후보 확정`과 `제외 후보 정리`는 방향이 다르다. 후보를 많이 남기면 첫 번째 값은
높아질 수 있지만 부적합 시험도 오래 남을 수 있다. 두 값을 항상 함께 보고한다.

### 3.5 답을 얻지 못한 경우

각 정보 선택 방법이 첫 번째로 고른 답을 얻을 수 없다고 표시한 뒤 같은 흐름을 다시
실행했다. 예를 들어 입력 순서대로 고르는 방법과 여러 시험에 도움이 되는 정보를
고르는 방법의 첫 선택이 다르면, 각 방법이 실제로 고른 답을 각각 막았다.

| 상황 | 최종 상태 일치 | 실제 후보 확정 | 제외 후보 정리 | 같은 정보 반복 |
|---|---:|---:|---:|---:|
| 모든 합성 답을 받을 수 있음 | 95.3% | 47/54 | 68/68 | 0회 |
| 환자마다 답 하나를 받을 수 없음 | 91.3% | 41/54 | 68/68 | 0회 |

답이 없으면 해당 정보는 이번 실행에서 다시 고르지 않고 다른 부족 정보로 넘어갔다.

### 3.7 환자 상황에 따른 확인 방법

360개 합성 환자·자료 상황에 다섯 가지 확인 방법 선택 규칙을 적용해 1,800회
실행했다.

| 결과 | 모든 환자에게 같은 비용표 적용 | 환자의 이동·비용·시간 제한 반영 |
|---|---:|---:|
| 제한이 있는 환자에게 실제 이용 가능한 방법만 사용해 판단을 끝낸 시험 | 81.0% | 88.5% |
| 새 검사를 피해야 하는데도 제안한 횟수 | 19회 | 0회 |
| 추가 방문을 피해야 하는데도 제안한 횟수 | 46회 | 0회 |
| 시간이 급한 환자의 평균 누적 대기 | 62.03시간 | 58.31시간 |

환자별 제한을 반영했을 때 판단 완료 비율의 차이는 7.5%p였다. 기본 합성 환자를
단위로 다시 뽑은 95% 결과 범위는 +4.25%p~+11.50%p였고, 환자별 차이에 부호를
무작위로 바꾼 검정의 p값은 0.000122였다. 새 검사와 추가 방문은 한 행동에 함께 붙을
수 있으므로 19회와 46회를 65개의 서로 다른 행동으로 합쳐 말하지 않는다.

부담값과 환자 상황은 합성 규칙으로 만들었다. 이 표는 프로그램이 입력된 제한을
의도대로 적용하는지 보여 주며 실제 환자 편익의 크기를 뜻하지 않는다.

### 3.8 589건 검색의 범위

정밀 평가 대상으로 미리 정한 서로 다른 시험 50건을 환자별로 반복해 150개 연결을
만들었다. 질환명의 일부 단어만 겹친 시험을 제거한 현재 검색기로 다시 실행했을 때
150개 모두 검색 결과 상위 200개 안에 들어왔고 평균 순위는 31.78위, 가장 낮은 순위는
120위였다. 질문 뒤 판단 결과와 나머지 핵심 수치는 이전 실행과 같았다.

검색된 다른 시험에는 조건 판단 정답이 없어 최종 추천 여부를 평가하지 않았다. 따라서
이 결과는 평가 시험이 넓은 검색 결과에 제대로 연결되는지 확인한 값이지 589건 전체의
검색 정확도나 추천 성능이 아니다.

## 5. TREC 공개 임상시험 검색

TREC Clinical Trials는 환자 설명과 관련 임상시험을 전문가가 표시한 공개 평가자료다.
TrialGPT가 공개한 검색 절차를 같은 자료에서 다시 실행했다.

- BM25: 환자 설명과 같은 단어나 비슷한 표기가 있는 시험을 찾는 방법
- MedCPT: 표현이 달라도 의학적 의미가 비슷한 시험을 찾는 방법
- 순위 결합: 두 검색 결과에 TrialGPT가 공개한 비중을 적용해 하나의 순위로 합치는 방법

| 평가자료 | 시험 문서 수 | 전문가가 관련 있다고 표시한 시험을 상위 500개 안에 남긴 비율 |
|---|---:|---:|
| TREC 2021 | 26,149건 | 83.59% |
| TREC 2022 | 26,581건 | 81.55% |

두 해 모두 TrialGPT 논문의 공개 수치와 차이가 0.1퍼센트포인트보다 작았다. 이는 검색
단계 재현 결과이며, 검색된 시험의 참가 조건 판단이나 최종 추천 정확도를 뜻하지 않는다.

## 6. 질문 전 한 번의 조건 판단

TrialGPT Criterion Annotations는 환자 기록과 개별 참가 조건 1,015쌍에 전문가 답과
TrialGPT 공개 답을 붙인 자료다. 개발 환자와 겹치지 않는 환자 33명, 환자–시험 조합
64개, 조건 654개에서 고정된 ClarifyTrial 지시문을 실행했다.

| 방법 | 전문가 답 이름과 일치 |
|---|---:|
| ClarifyTrial 조건 판단 | 517/654, 79.1% |
| 공개 TrialGPT 출력 | 581/654, 88.8% |

ClarifyTrial의 답 이름 기준 성능은 TrialGPT보다 낮다. 개발 중 남은 오답 51개 가운데
47개는 `현재 기록으로 판단 가능`과 `정보 부족`의 경계였다. 예를 들어 제외 조건이
흉관인데 기록에 흉관 언급이 없을 때, 전문가와 TrialGPT는 기록 관행상 위반하지 않음으로
판단한 반면 ClarifyTrial은 직접적인 부재 확인이 없다며 정보 부족으로 남기는 경향이
있었다.

이 두 답은 ClarifyTrial의 후보 유지 결과에서는 같은 행동으로 이어지는 경우가 많다.
따라서 답 이름의 차이를 임의로 없애 점수를 높이지 않았고, 최종 안내에서는 현재 확인
상태와 필요한 근거를 함께 보여 준다. 그렇더라도 79.1%를 사실상 88.8%와 같거나 더 높은
조건 판단 성능으로 표현하지 않는다.

## 7. 공식 환자 전체 실행

### 7.1 실행 조건

- 입력: 공식 대회 합성 환자 10명
- 시험 검색: ClinicalTrials.gov의 모집 중·모집 예정 시험
- 실제 판정: 환자당 관련 시험 최대 3개
- 모델: GPT-5.6 Sol, 추론 수준 `medium`
- 병렬 실행: 환자 4명씩
- 추가 정보 답변: 모두 `unknown`

모든 답을 `unknown`으로 둔 이유는 참가 가능 후보를 많이 만드는 것이 아니라, 답을
얻지 못해도 다음 정보로 넘어가고 실행을 끝까지 저장하는지 확인하기 위해서다.

### 7.2 결과

| 항목 | 결과 |
|---|---:|
| ClinicalTrials.gov에서 가져온 원자료 후보 | 101건 |
| 질환 확인 단계에서 무관하다고 제거 | 7건 |
| 질환은 관련 있지만 상위 3개 밖이라 판정하지 않음 | 69건 |
| 실제 조건 판정으로 넘긴 시험 | 25건 |
| 구조화한 선정 조건 | 204개 |
| 구조화한 제외 조건 | 268개 |
| 전체 조건 | 472개 |
| 공식 원문과 글자 위치가 맞지 않은 조건 | 0개 |
| 복합 조건을 안전하게 확정할 수 없어 참가 가능 확정을 막은 시험 | 11건 |
| 추가 정보 확인 시도 | 27회 |
| 모델 호출 | 97회 |
| 전체 토큰 | 1,538,814 |

S007에는 환자의 질환과 같은 모집 시험이 없었다. 처음 검색된 두 시험은 성인 악성
위출구폐쇄 연구였으므로 제거했다. S009에는 관련 시험이 한 개만 남았다. 따라서
환자 10명에 시험 3개씩을 억지로 채우지 않고 실제 25건만 판정했다.

25개 시험의 선정·제외 조건 472개는 저장한 ClinicalTrials.gov 공식 원문과 글자
위치를 다시 대조했고 모두 일치했다. 복합 조건의 관계를 현재 구조로 확실히 표현하지
못한 11개 시험은 후보로는 남겼지만 참가 가능으로 확정하지 않았다.

실행 중 선택적 검토 모델은 7번 호출됐고, 7번 모두 일반적인 정보 부족을 다시
설명했다. 이 실행 뒤 일반적인 정보 부족은 질문 경로로 보내고, 근거 충돌·잘못된
출처·근거 없는 확정 판단에만 검토 모델을 부르도록 규칙을 고쳤다. 97회와
1,538,814토큰은 수정 전 실제 측정값이다. 수정 뒤 호출량을 추정해 측정값처럼
사용하지 않는다.

이 실행은 자유 문장 입력, 공식 검색, 질환 확인, 조건 원문 보존, 판정, 추가 정보 선택,
결과 저장이 연결되는지 확인한 것이다. 의료 전문가 정답이 붙은 자료가 아니므로 최종
추천 정확도 수치로 사용하지 않는다.

### 7.3 자동 검사

현재 자동 검사 348개가 통과했다. 검사 범위는 다음과 같다.

- 수치, 날짜, 단위, 선정·제외 조건과 복합 논리 계산
- 후보 유지와 현재 확인 상태 집계
- 정보 선택, 환자 제한, 답 없음과 반복 방지
- 각 방법이 처음 고른 답을 얻지 못할 때 다른 정보로 넘어가는지 확인
- 검색 결과의 질환 관련성 확인과 관련 모집 시험 없음 처리
- 공식 조건 원문과 글자 위치 보존
- 검색, 조건 판단, 질문, 답변과 관련 조건 재판정의 전체 연결
- 결과 저장, 중단 뒤 재개, 제외 시험의 재검토 경로와 보고서 생성
- Windows에서 전체 검사 통과, Linux용 GitHub Actions 설정 파일 준비

GitHub Actions 설정 파일은 현재 GitHub 로그인에 `workflow` 권한이 없어 원격 저장소에
올리지 못했다. 코드와 로컬 검사는 이 권한과 무관하다.

자동 검사는 프로그램이 정한 규칙대로 작동하는지 확인한다. 임상적 타당성이나 실제
환자 결과를 대신하지 않는다.

## 8. 현재 결론

1. 두 판단을 분리하면 처음 화면에서 사라질 실제 후보를 추가 확인 대상으로 남길 수
   있다.
2. 추가 확인으로 실제 후보를 확정하는 수와 부적합 후보를 정리하는 수를 함께 계산할 수
   있다.
3. 환자 제한을 반영하면 허용하지 않은 검사와 방문을 피할 수 있다.
4. 현재 자료에서는 복잡한 정보 조합 계산이 강한 단순 방법보다 낫지 않았다.
5. 구조화 조건에서는 언어모델 호출을 늘려도 정확도가 좋아지지 않았다.
6. TrialGPT보다 전체 추천 성능이 높다는 근거는 없다.
