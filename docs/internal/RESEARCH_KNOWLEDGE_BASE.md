# ClarifyTrial 선행연구 정리

선행연구에서 이미 알려진 방법과 ClarifyTrial에 반영한 부분을 함께 정리했다. 현행 연구
질문과 실험 방법은 [연구계획 v5](CLARIFYTRIAL_RESEARCH_PLAN_V5.md)를 기준으로 삼는다.

## 1. 용어

| 표현 | 뜻 |
|---|---|
| 언어모델 | GPT, Claude처럼 문장을 읽고 쓰는 모델 |
| 관련 시험 검색 | 많은 임상시험 가운데 환자와 관련 있는 후보를 찾는 단계 |
| 같은 단어 검색 | 환자 설명과 시험 문서에 같은 단어나 비슷한 표기가 있는지 보는 검색 |
| 의학적 의미 검색 | 표현이 달라도 의학적 뜻이 비슷한 문서를 찾는 검색 |
| 외부 문서 검색과 답변 생성 | 검색한 문서를 언어모델 입력에 붙여 답을 만드는 방식. 논문에서는 흔히 RAG라고 부름 |
| 여러 모델 역할 | 같은 모델 또는 다른 모델을 서로 다른 지시문으로 나누어 부르는 구조 |
| 구조화한 조건 | 수치, 날짜, 예·아니오와 논리 관계를 코드가 계산할 수 있도록 나눈 참가 조건 |

## 2. 이미 알려진 방법

다음 기능은 ClarifyTrial보다 앞선 연구에 있다.

| 이미 연구된 내용 | 대표 연구 |
|---|---|
| 환자 기록과 시험 조건을 하나씩 판단하고 근거와 순위를 만드는 방법 | TrialGPT, TrialMatchAI |
| 시험 조건을 환자가 이해할 질문으로 바꾸는 방법 | Chen et al., Yang |
| 답변 뒤 후보 시험과 다음 질문을 갱신하는 방법 | DQueST, Yang, TrialTriage |
| 기존 기록, 질문, 검사 가운데 다음 행동을 고르는 방법 | AIDS2, Fink 계열 |
| 정보량, 불확실성과 비용을 이용해 질문 순서를 정하는 방법 | DQueST, C-IP, ALMA, SMART |
| 숨겨 둔 전체 기록에서 답을 반환해 질문 시스템을 평가하는 방법 | MediQ, TrialSim-10k |
| 최종 판단과 필요한 증거를 모으는 능력을 따로 평가하는 방법 | EviMed |
| 여러 모델 역할, 지식 그래프와 사람 검토를 결합한 방법 | OncoAgents, TRIAGE |
| 시험 조건의 수치, 시간, 개념과 논리 관계를 구조화하는 방법 | Chia, Leaf, Clinical Trial Knowledge Base |

따라서 외부 문서 검색, 여러 모델 역할, 질문 생성, 답변 반영, 행동 선택, 관련 조건만
다시 판단하는 기능을 새 기여로 표현하지 않는다.

DQueST는 여러 시험의 공통 정보와 현재 예상 정보량을 이용해 다음 질문을 골랐다. 공통
정보에 연결된 시험이 많을수록 후보를 빨리 줄일 수 있지만, 서로 다른 조건을 억지로
묶으면 오류가 늘 수 있다는 절충 관계도 설명했다. Fink 계열은 검사비, 그 검사가 필요한
시험 수, 관련 조건 묶음 수를 함께 계산하고 새 검사 결과가 들어올 때마다 남은 검사
순서를 다시 정했다. ClarifyTrial의 기본 질문 규칙도 이 계열에 속하므로 알고리즘 자체를
새 기여로 다루지 않는다.

## 3. ClarifyTrial이 좁혀 보는 문제

현재 연구는 같은 임상 사실을 두고 자료의 날짜, 출처와 확인 절차가 달라질 때 생기는
두 오류에 집중한다.

1. 더 확인하면 참가 가능성이 있는 환자를 너무 일찍 후보에서 제외함
2. 필요한 확인이 남은 환자를 너무 일찍 참가 가능으로 확정함

이를 위해 시험마다 다음을 나눠 보여 준다.

- 계속 확인할 후보인지
- 현재 자료로 확인이 끝났는지

현재 연구는 두 결과를 전체 실행에서 계속 분리해 저장한다. 추가 확인 뒤 확인을 마친
후보, 계속 기다리는 후보와 조건 불충족으로 정리된 시험을 함께 센다. 환자가 이용할 수
있는 확인 방법과 선택하지 않은 검사·방문도 같은 실행 기록에 남긴다.

부분 정보가 있는 환자를 `명확히 제외`, `현재 정보로 확정`, `추가 정보를 얻으면 판정
가능`으로 나누는 방법은 2013년 연구에 이미 있다. ClarifyTrial에서는 후보로 계속 볼 수
있는지와 현재 자료로 확인을 끝낼 수 있는지를 검색, 질문, 답변, 재판정과 최종 출력까지
따로 추적하는 구현 형식으로 사용한다.

### 현재 실험에서 확인한 범위

공개 임상시험 50건의 조건 202개와 합성 환자 30명을 사용했다. 환자-시험 조합 150개
가운데 28개는 처음 자료만으로 상태가 정리돼 있었다. 나이, 임신·수유 여부와 활동성 중증
감염을 먼저 제공하자 조건 불충족 시험 68건과 확인을 마친 후보 32건이 추가로 정리됐다.
질문 전에 상태가 정해진 조합은 128개, 추가 정보가 남은 조합은 22개였다. 환자마다 한 번까지
확인하도록 하자 질문이 14번 나왔고, 답을 받은 뒤 14건이 확인 완료로 바뀌었다. 8건은
확인 대기로 남았다.

질문 순서에 따른 차이는 기본 문진 세 항목을 제공한 뒤 0.44%포인트였다. 정보 연결 모양
9종을 각각 200개씩 만든 합성 구조에서는 여러 시험이 같은 한 정보에 직접 묶인 경우에
효과가 컸다. 시험마다 필요한 정보가 따로 있거나 사슬처럼 이어진 경우에는 이점이
사라지거나 조금 낮아졌다.

환자 상황에 따른 확인 방법도 따로 점검했다. 부담과 이동·비용을 줄이는 설정에서는
기존 공식 결과를, 시간이 급한 설정에서는 빠른 새 검사를 각각 85회 모두 골랐다. 새
검사와 추가 방문을 허용하지 않자 두 제안은 0회가 됐고, 설정마다 확인 대기로 남는
시험은 평균 0.88건에서 1.24건으로 늘었다.

위 결과는 선택한 공개 조건과 합성 환자에서 프로그램의 상태 변화와 선택 규칙을 확인한
값이다. 실제 환자의 참가 판정 정확도와 임상시험 등록 성과는 측정하지 않았다.

발표에서 다룰 연구 기여는 세 가지 결과로 한정한다. 첫째, 기본 문진 뒤 미확정으로 남은
22건을 숨기지 않고 한 번의 추가 확인 뒤 14건이 확인 완료, 8건이 확인 대기로 남은
과정을 같은 상태표에서 추적했다. 둘째, 이미 알려진 공통 정보 우선 원리를 9가지 연결
모양에서 시험해 효과가 큰 구조와 효과가 없거나 낮아지는 구조를 함께 보였다. 셋째,
환자가 허용하지 않은 검사와 방문을 제외했을 때 미확정 시험이 평균 0.88건에서 1.24건으로
늘어나는 대가까지 기록했다.

## 4. 가장 가까운 선행연구

### 부분 정보 선별과 실제 사전 확인 절차

[부분 정보에서 시험 자격을 다룬 2013년 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC3852288/)는
환자를 참가 가능, 참가 불가, 추가 정보를 얻으면 참가 가능할 수 있는 상태로 나누고
어떤 정보가 더 필요한지 찾았다. 따라서 정보가 부족한 환자를 후보로 남기고 필요한
정보를 표시하는 개념은 이 선행연구에서 이미 확인할 수 있다.

[NIH의 연구 사전 확인 안내](https://irbo.nih.gov/conducting-your-study/screening-for-research-studies/)도
적은 정보로 참가 가능성을 보는 사전 확인과, 동의 뒤 검사 등을 거쳐 최종 자격을
확인하는 단계를 구분한다. ClarifyTrial의 `후보 유지 여부`와 `현재 확인 상태`는 이
현실적인 차이를 프로그램의 검색·질문·재판정·출력 전체에서 유지하기 위한 구현이다.

이 두 근거 때문에 `두 상태를 처음 만들었다`고 말하지 않는다. 알려진 부분 정보 선별
원칙을 여러 시험이 공유하는 질문, 환자별 확인 방법과 제한된 확인 횟수의 비교까지
이어지는 재현 가능한 흐름으로 구현했다는 범위에서 설명한다.

### TrialGPT

[TrialGPT](https://www.nature.com/articles/s41467-024-53081-z)는 검색어 생성,
같은 단어와 의학적 의미 검색, 환자–조건 판단, 근거 설명과 시험 순위화를 한 흐름으로
구현했다. 공개 자료에는 환자 기록과 개별 참가 조건 1,015쌍에 전문가 판단이 붙어 있다.

ClarifyTrial은 다음 부분을 사용한다.

- 후보 검색의 최소 기준
- 질문 전 한 번의 조건 판단 비교
- 환자 근거와 시험 원문을 함께 남기는 출력

공개 조건 자료에는 어떤 질문을 할지, 질문 뒤 답, 종료 시점과 여러 시험 전체 추천
정답이 없다. 따라서 ClarifyTrial의 대화 흐름은 별도 합성 자료에서 평가한다.

TrialGPT의 조건 판단은 환자 기록과 이미 고른 시험 조건을 GPT-4에 직접 넣으며 인터넷
검색을 사용하지 않는다. 외부 검색은 앞단의 후보 시험 검색에 사용된다.

### TrialMatchAI

[TrialMatchAI](https://www.nature.com/articles/s41467-026-70509-w)는 임상 개념
정리, 규칙 필터, 같은 단어와 의미 검색, 관련 조건 재정렬, 조건별 판단과 시험 순위화를
결합했다. ClarifyTrial은 후보 검색과 선정·제외 조건을 나누어 판단하는 구조를 참고한다.

### 실제 업무에서의 평가 기준

[2026년 Nature Communications 무작위 평가](https://www.nature.com/articles/s41467-026-68873-8)는
폐암과 대장암 환자 기록 355건을 연구 코디네이터가 직접 읽는 경우, 인공지능이 정리한
내용을 함께 보는 경우, 인공지능만 사용하는 경우로 나눴다. 환자 기록 한 건마다 열두
항목을 맞게 찾았는지 확인했을 때 코디네이터와 인공지능을 함께 쓴 경우는 76.1%,
코디네이터만 쓴 경우는 71.5%, 인공지능만 쓴 경우는 59.9%였다.

이 연구는 실제 업무 성능을 말하려면 완전한 환자 기록, 독립된 전문가 정답, 사람의
검토 시간과 오류까지 봐야 한다는 기준을 보여 준다. ClarifyTrial의 공개 조건·합성 환자
실험은 질문 순서와 실행 구조를 확인한 결과로 남긴다. 임상 수준의 정확도와 실제 업무
시간 절감은 아직 측정하지 않았다.

### DQueST와 Yang

[DQueST](https://academic.oup.com/jamia/article/26/11/1333/5544734)는 여러 시험의
조건에서 공통 정보를 묶고, 현재 후보를 가장 많이 줄일 것으로 예상되는 조건을 한 번에
하나씩 질문했다. 답변과 맞지 않는 시험을 제거한 뒤 남은 후보에서 다음 질문을 다시
골랐다. 논문은 정보 연결이 촘촘할수록 후보를 빨리 줄일 수 있지만, 무리한 개념 묶기는
오류를 늘릴 수 있다고 설명한다.

[Yang의 2026년 학위 연구 소개](https://sbmi.uth.edu/research/phd-dissertations/a-patient-centric-chatbot-for-improving-clinical-trial-accessibility.htm)는
비슷한 시험 조건을 묶어 환자용 질문을 만들고 답변에 따라 후보를 줄이는 환자 중심
대화 구조를 설명한다.

두 연구는 `여러 시험에 도움이 되는 질문을 먼저 고른다`는 ClarifyTrial 질문 순서의
직접 근거다. ClarifyTrial의 9가지 연결 모양 실험은 DQueST가 설명한 연결성과 효율의
관계를 현재 자료에서 다시 확인하고, 이점이 사라지는 모양까지 함께 기록한 후속 검증이다.
전체 코드와 세부 점수식이 공개되지 않은 부분은 동일한 구현으로 표현하지 않는다.

### TrialTriage

[TrialTriage](https://formative.jmir.org/2026/1/e100779)는 일곱 가지 조건으로 만든
췌장암 합성 사례를 먼저 판정했다. 자료가 빠지거나 모호하면 연구책임자에게 이메일을
보내고, 답변에서 필요한 값을 꺼내 같은 판정 규칙을 다시 실행했다. 90개 합성 사례의
100% 일치는 같은 조건으로 만든 자료와 규칙이 끝까지 맞물리는지 확인한 결과다. 논문도
이를 실제 임상 성능이 아닌 구현 충실도 점검으로 설명한다. 따라서 외부 확인과 답변 뒤
재판정은 ClarifyTrial의 새 기능으로 제시하지 않는다.

### MediQ

[MediQ](https://proceedings.neurips.cc/paper_files/paper/2024/file/32b80425554e081204e5988ab1c97e9a-Paper-Conference.pdf)는
현재 정보로 답할 수 있는지 먼저 판단하고, 부족할 때 질문을 만든다. 질문 시스템과
숨겨 둔 전체 기록에서 답을 반환하는 환경을 분리했다.

ClarifyTrial은 현재 자료의 충분성 확인과 독립된 합성 답변 환경을 이 위치에 사용한다.
질문 횟수를 모두 써도 자료가 부족하면 억지로 결론을 내리지 않는다.

### EviMed

[EviMed](https://aclanthology.org/2026.findings-acl.1372/)는 진단에 필요한 정보를
작은 사실 단위로 나누고, 환자에게 물을 내용과 검사로 확인할 내용을 별도 환경에서
제공했다. 최종 진단을 맞힌 비율과 필요한 사실을 얼마나 모았는지를 따로 계산했다.
강한 모델도 완전한 기록을 처음부터 받았을 때의 추론 능력이 좋다는 이유만으로 대화
중 필요한 증거를 잘 모으지는 못했다.

이 결과는 ClarifyTrial에서 질문 전 조건 판정과 질문 순서를 별도 실험으로 두는 근거다.
가상 환자는 프로그램이 실제로 고른 정보에 해당하는 답만 돌려주며, 확인하지 않은 값을
한꺼번에 보여 주지 않는다. 사실을 작은 단위로 나누거나 질문 과정을 따로 평가하는 방법
자체는 EviMed를 포함한 선행연구에 있으므로 새 기여로 표현하지 않는다.

### Fink 계열과 환자 참여 선호 연구

[비용 효율적 임상시험 배정](https://www.cs.cmu.edu/~eugene/research/full/trial-assignment.pdf)은
검사 비용, 그 검사가 필요한 시험 수와 참가·제외 조건식에서 영향을 받는 묶음 수를
함께 고려했다. 한 검사 결과를 여러 시험이 함께 사용했고, 새 결과가 들어오면 다른
검사의 필요성과 순서를 다시 계산했다.
따라서 `한 번의 답으로 여러 시험을 갱신한다`거나 `여러 시험에 영향을 주는 정보를 먼저
본다`는 기능만으로 새 기여를 주장하지 않는다.

[Thomas et al., 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC9756590/)와
[장기 임상시험 참여자 조사, 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10432794/)는
시간, 이동, 직장을 비우는 부담, 보상, MRI와 장시간 검체 수집이 참여 선택에 영향을
줄 수 있음을 보여 준다.

여기서 확인된 사실과 ClarifyTrial의 설계 판단을 구분한다.

| 구분 | 내용 |
|---|---|
| 연구에서 확인된 사실 | 비용과 여러 시험에 미치는 영향을 함께 보는 방법이 존재하며, 시간·이동·절차 부담의 중요성은 환자마다 다르다. |
| ClarifyTrial의 설계 판단 | 확인 방법을 한 비용 숫자로 합치지 않고 대기, 이동, 직접 비용, 신체·심리 부담, 의료 위험과 치료 방해를 따로 저장한다. |
| 아직 모르는 점 | 각 부담의 실제 가중치와 환자가 정확도보다 부담 감소를 얼마나 우선하는지는 현재 자료로 정할 수 없다. |

[2025년 JMLR의 정보 선택 평가 연구](https://www.jmlr.org/papers/v26/23-1635.html)는
의료처럼 정보를 얻는 데 비용이나 위험이 따르는 분야에서는 정보의 예측 가치와 확인
비용을 함께 다뤄야 한다고 정리한다. 어떤 정보를 확인할지 바꾸면 그 뒤에 관측되는
자료의 분포도 달라질 수 있어, 합성 자료의 선택 방법 점수를 실제 환경의 효과로 그대로
옮기기 어렵다고 지적한다. ClarifyTrial의 합성 실험은 확인 순서와 환자 제한이 코드에서
의도대로 작동하는지를 보는 자료로 한정한다.

### PRomop와 TRIAGE

[PRomop](https://arxiv.org/abs/2607.13947)은 장기 환자 기록을 날짜와 출처가 붙은
하나의 환자 상태로 정리해 여러 판정 단계가 함께 사용하도록 했다. ClarifyTrial의 공통
환자 상태표 근거다.

[TRIAGE](https://doi.org/10.1200/OP-26-00076)는 실제 환자 기록, 버전이 있는 시험
문서, 조건별 원문 근거와 코디네이터의 재검토를 결합했다. ClarifyTrial은 원문 근거와
실제 충돌이 있는 결론만 선택적으로 다시 보는 원칙을 참고한다. 공개되지 않은 내부
검토기를 재현했다고 표현하지 않는다.

## 5. 성능을 위한 구현 구성

다음 항목은 프로그램 품질을 위한 설계 선택이며, 각각을 새 연구 방법으로 내세우지
않는다.

1. 시험 조건은 환자와 대화하기 전에 한 번 구조화하고 원문 위치와 함께 저장한다.
2. 모든 단계가 날짜와 출처가 붙은 같은 환자 상태를 읽는다.
3. 후보 검색은 같은 단어와 의학적 의미 검색을 결합한다.
4. 수치, 날짜와 명시적 논리는 코드가 계산한다.
5. 코드로 계산할 수 없는 조건만 언어모델에 보낸다.
6. 현재 정보가 충분한지 먼저 보고 부족할 때만 다음 확인을 만든다.
7. 여러 시험에 도움이 되면서 환자 부담이 낮은 확인 방법을 고른다.
8. 새 정보와 연결된 조건만 다시 판단한다.
9. 후보 유지 여부와 현재 확인 상태를 따로 저장한다.
10. 판단 근거, 질문 전후 변화, 모델 호출과 환자 부담을 모두 기록한다.

다음 정보의 기본 선택 규칙은 현재 미확정인 시험 수를 먼저 보고, 이어서 연결된 조건
수와 확인 부담을 본다. DQueST와 Fink 계열에서 이미 제시한 판단 기준을 현재
자료 구조에 맞게 구현한 규칙이다. 공개 합성 환자와 1,800개 정보 연결 구조에서 확인 횟수
1회, 2회, 3회를 비교했을 때 가장 넓게 연결된 정보만 고르는 방법과 비슷한 수의 시험을
정리하면서 확인 부담은 더 낮았다. 앞으로 확인할 정보 조합을 계산한
방법은 일부 합성 구조에서 조금 더 많은 시험을 정리했지만 확인 부담이 컸고, 공개 조건의
가능한 값 조합에서는 기본 규칙보다 낮았다. 학습한 순서는 익숙한 정보 분포와 달라진 정보 분포에서 결과가
뒤집혔다. 현재 기본값은 숨은 답의 분포를 사용하지 않는 읽기 쉬운 규칙이다.

언어모델 역할 사이의 자유 토론은 기본 구조에 넣지 않는다. 구조화 조건 최종 평가에서
모델 호출을 늘려도 결과가 좋아지지 않았고, 반복 토론의 이득을 보여 주는 현재 자료도
없기 때문이다.

## 6. 자료마다 답할 수 있는 질문

| 자료 | 답할 수 있는 질문 | 답할 수 없는 질문 |
|---|---|---|
| ClinicalTrials.gov | 시험 원문과 모집 상태는 무엇인가 | 특정 환자가 참가 가능한가 |
| TREC Clinical Trials | 관련 시험을 검색 결과 위쪽에 남겼는가 | 질문 뒤 참가 판단이 바뀌었는가 |
| TrialGPT 조건 자료 | 개별 조건의 상태와 근거가 전문가 답과 같은가 | 어떤 질문을 먼저 해야 하는가 |
| 공개 시험 기반 합성 자료 | 기본 문진 뒤 남은 시험이 질문으로 얼마나 정리됐는가, 어느 정보 연결 모양에서 질문 순서가 달라지는가 | 실제 환자와 전체 프로토콜에서 정확한가 |
| 환자 부담 합성 상황 | 입력된 제한을 확인 방법 선택에 적용했는가 | 실제 환자가 느끼는 편익은 얼마인가 |

미등록 환자를 자동으로 참가 불가로 취급하지 않는다. 환자 거절, 자리, 거리, 보험,
일정과 시험 중단도 실제 등록에 영향을 주기 때문이다.

## 7. 비교할 때 지켜야 할 조건

- 같은 환자와 후보 시험
- 같은 시험 원문과 검색 결과
- 같은 숨긴 답과 확인 가능한 방법
- 같은 확인 횟수와 종료 조건
- 같은 최종 상태 계산
- 언어모델을 비교할 때 같은 모델과 생각량

논문에 나온 숫자는 그 논문의 자료와 환경에서 해석한다. 공개 코드가 있더라도 같은
자료와 설정으로 직접 실행하지 않은 수치를 ClarifyTrial 결과와 바로 비교하지 않는다.

## 8. 현재 남은 지식 공백

- 자유 문장으로 적힌 복잡한 조건에서 모델 역할 분리가 실제로 도움이 되는가
- 여러 질환의 전체 프로토콜에서 두 판단을 일관되게 주석할 수 있는가
- 실제 환자가 이동, 비용, 시간과 정확도 사이에서 어떤 선택을 하는가
- 전체 프로토콜과 더 큰 실제 후보군에서도 현재 영향 우선 규칙의 낮은 확인 부담이 유지되는가
- 실제 업무에서 근거와 남은 정보를 함께 보여 주면 검토 시간이 줄어드는가

과거 Solar 합성 데모 수치는 현행 결과에 포함하지 않는다.
