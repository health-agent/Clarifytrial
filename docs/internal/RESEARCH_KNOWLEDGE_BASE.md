# ClarifyTrial 연구 지식 정리

문서 역할: v5 개발과 논문 작성에 필요한 선행연구·자료·평가 지식
현행 계획: CLARIFYTRIAL_RESEARCH_PLAN_V5.md
현재 실험 상태: 구조화 입력의 v5 질문 정책 평가 완료, 자연어 전체 실행과 임상 성능 미측정

과거 조사에서 다시 쓸 내용을 모은 참고 문서다. 현행 개발계획은
`CLARIFYTRIAL_RESEARCH_PLAN_V5.md`이며, 폐기된 아이디어의 진행 과정과 예비실험
원문은 trash 폴더에 보관한다.

## 1. 연구 경계

임상시험 매칭 분야에는 이미 다음 기술이 존재한다.

| 이미 연구된 내용 | 대표 연구 | ClarifyTrial에서의 사용 |
|---|---|---|
| 환자 기록과 임상시험 기준의 문장별 판정·근거·순위화 | TrialGPT, TrialMatchAI | 고정 입력 판정 기준선 |
| 선정·제외 기준을 환자용 질문으로 변환 | Chen, Yang | 질문 생성 방식 |
| 답변에 따라 후보 시험과 다음 질문 갱신 | DQueST, Yang | 대화형 비교군 |
| 기록·질문·검사 중 다음 행동 선택과 비용 절감 | AIDS2, Fink, 비용 민감 정보 획득 | 행동 선택 비교군 |
| 숨긴 환자 상태와 별도 답변기를 이용한 질문 평가 | MediQ, TrialSim-10k | 통제 실험 설계 |
| 멀티 에이전트, 지식 그래프, EHR, 사람 검토 | OncoAgents, TRIAGE | 시스템 구현 참고 |
| 기준의 개체·수치·시간·논리 구조화 | Chia, Leaf, Clinical Trial Knowledge Base | 기준 파서 정답 형식 |
| 불확실성에 따른 질문·보류·중단 | ClinDet-Bench, C-IP, ALMA, SMART | 강한 정책 비교군 |

따라서 다음 항목은 논문 기여로 주장하지 않는다.

- RAG 또는 멀티 에이전트 사용
- 기준 구조화와 의료 개체 표준화
- 질문 생성과 답변 반영
- 엔트로피·정보량·비용에 따른 질문 정렬
- 기록·질문·검사·전문가 검토 중 다음 행동 선택
- 관련 기준만 다시 판정하는 선택적 재평가
- 캐싱, 배치 호출과 모델 비용 절감

v5가 검증하려는 범위는 더 좁다.

> 같은 임상 사실을 유지하면서 자료의 출처, 시점, 확인 방법과 선별 단계만
> 바꿨을 때, 사전 선별의 후보 유지와 현재 단계의 적합성 확정을 구분할 수
> 있는지 평가한다.

중요한 오류는 두 가지다.

1. 추가 확인 가치가 있는 환자를 너무 일찍 후보에서 제거
2. 필요한 확인이 남은 환자를 너무 일찍 적합하다고 확정

이 평가 구성이 새 기여인지는 아직 확정되지 않았다. 전문가 정답, 가까운
선행연구와의 직접 비교, 기존 평가로 잡히지 않는 오류가 실제로 있어야 한다.

## 2. 가장 가까운 선행연구

### 2.1 정적 임상시험 매칭

**[TrialGPT](https://www.nature.com/articles/s41467-024-53081-z)**는 임상시험
검색, 환자-기준 문장별 판정과 설명, 시험 순위화를 한 흐름으로 평가했다.
공개 Criterion Annotations에는 1,015개 환자-기준 전문가 주석이 있다.
ClarifyTrial의 질문 전 판정기와 근거 생성 비교군으로 사용한다.

조건 판정은 [공개 코드](https://github.com/ncbi-nlp/TrialGPT/blob/main/trialgpt_matching/TrialGPT.py)에서
환자 기록과 이미 고른 시험 조건을 GPT-4에 직접 넣으며 인터넷 검색 도구를 쓰지
않는다. 앞단의 시험 검색은 ClinicalTrials.gov에서 받아 둔 말뭉치를 BM25와
MedCPT로 찾는 과정이다. 두 단계를 인터넷 검색으로 한데 묶어 설명하지 않는다.

논문의 87.3%는 53명에서 뽑은 105개 환자-시험 조합, 1,015개 조건에 대한 결과다.
좋은 예측만 골랐다는 증거는 없지만 표본 선택 방법은 무작위 추출이나 사전 고정으로
상세히 설명되지 않았다. 더 중요한 한계는 세 의사가 TrialGPT의 예측과 설명을 본
상태에서 설명을 평가하고 별도의 조건 라벨을 붙였다는 점이다. 다수결과 토론으로
합의를 만들었지만 TrialGPT 답을 가린 독립 정답은 아니다. 따라서 공개 출력의
87.3%는 논문 절차 안의 결과로 인용하고, 새 모델을 같은 자료에서 다시 실행한
독립 비교값처럼 사용하지 않는다.

**[TrialMatchAI](https://www.nature.com/articles/s41467-026-70509-w)**는 BM25와
벡터 검색, 기준 관련성 재정렬, 선정·제외 기준별 상태와 근거, 최종 순위화를
결합했다. 검색 성능을 단순 키워드 기준선 하나와만 비교해서는 안 되는 근거다.

**[OncoAgents](https://pmc.ncbi.nlm.nih.gov/articles/PMC13091143/)**는 LLM 역할
분리, 종양 지식 그래프, 결정론적 판정, 사람 검토, 시간에 따른 재검색을 실제
종양 자료에서 평가했다. 멀티 에이전트 구조와 사람 검토는 선행연구에서 가져오는
구현 요소로 분류한다.

### 2.2 질문과 동적 후보 축소

**[DQueST](https://academic.oup.com/jamia/article/26/11/1333/5544734)**는 여러
후보 시험에서 구분력이 큰 기준 하나를 골라 질문하고, 답변과 맞지 않는 시험을
제거한 뒤 후보와 다음 질문을 갱신했다. 후보 제거량이나 엔트로피만으로 질문
우선순위를 정하는 접근의 직접 비교군이다.

**[Chen et al., 2025](https://www.nature.com/articles/s41598-025-11876-0)**는
임상시험 기준을 환자용 설문으로 바꾸고, 답변과 기준을 함께 넣어 참여 가능성을
판정했다. 기준-질문 연결과 답변 반영은 이미 구현된 연구 요소다.

**[Yang, 2026](https://sbmi.uth.edu/research/phd-dissertations/a-patient-centric-chatbot-for-improving-clinical-trial-accessibility.htm)**은
비슷한 기준을 묶고 환자가 이해할 질문을 생성하며 답변에 따라 부적합 시험을
대화 중 제거했다. 질문 중복 감소와 동적 후보 제거의 직접 비교 대상이다.

**[TrialSim-10k](https://www.sciencedirect.com/science/article/pii/S2352648326000504)**는
26개 질환 분야에서 프로토콜 기반 다회 선별 대화 9,864건을 구축했다. 대규모
합성 대화와 논리 단위 평가는 자료 기여로 주장할 수 없다.

### 2.3 다음 정보와 획득 경로 선택

**[AIDS2](https://citeseerx.ist.psu.edu/document?doi=e699ba79d1989b38f8f40938fd1b87787f1fdc61&repid=rep1&type=pdf)**와
**[Fink의 비용 효율적 임상시험 배정](https://www.cs.cmu.edu/~eugene/research/full/trial-assignment.pdf)**은
기존 기록을 먼저 사용하고, 부족하면 질문이나 검사를 선택하며 비용·위험·통증과
여러 시험에 미치는 영향을 고려했다. 결과가 들어오면 관련 시험을 다시 판정했다.
질문·기록·검사 가운데 다음 행동을 고르는 문제도 선행연구에서 다뤘다.

Fink의 구현은 검사 가격, 그 검사가 필요한 시험 수와 판정식에서 영향을 받는 부분
수를 함께 사용했다. 싼 검사를 먼저 시행해 비싼 검사를 피할 수 있는지 결과마다 다시
계산했다. 따라서 비용을 고려한 질문·검사 순서 자체는 ClarifyTrial의 새 기여가 아니다.

**[Thomas et al., 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC9756590/)**의
환자 선호 실험에서는 참여 의사가 보상, 연구 기간, 전체 소요 시간과 집 밖에서 보내는
시간의 영향을 받았고, 피로가 있는 사람은 이동 시간이 더 중요했다. 질환 이름만으로
선호를 정할 수 없고 현재 삶의 영향과 치료 경험을 함께 봐야 했다.

**[Participant Perceptions in a Long-term Clinical Trial, 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10432794/)**은
직장을 비우는 시간, MRI와 24시간 소변 수집 등이 실제 부담이 될 수 있음을 보고했다.
참여자 경험은 더 짧고 유연한 일정과 덜 부담스러운 측정을 선호하는 방향이었다.

이 근거로 확인된 사실과 ClarifyTrial의 해석을 구분한다.

| 구분 | 내용 |
|---|---|
| 확인된 사실 | 검사 비용과 여러 시험에 미치는 범위를 함께 보는 방식은 이미 존재한다. 시간, 이동, 절차와 치료 경험의 중요성은 환자마다 다르다. |
| ClarifyTrial의 해석 | 고정된 행동 비용 하나보다 환자에게 새로 생기는 비용·시간·방문·통증·위험·치료 방해를 따로 기록해야 한다. |
| 아직 모르는 점 | 각 부담에 얼마의 숫자를 줄지, 어떤 환자에서 추천 회복보다 부담을 얼마나 우선할지는 현재 자료로 정답이 없다. |
| 현재 계획과의 관계 | 중심 기여를 바꾸지 않고, 질문 정책의 현실성과 평가 범위를 넓히는 보조 연구로 둔다. |

**[MediQ](https://proceedings.neurips.cc/paper_files/paper/2024/hash/32b80425554e081204e5988ab1c97e9a-Abstract-Conference.html)**는
불완전한 임상 정보, 질문 모델과 별도 환자 답변기, 질문 뒤 판단 성능을 평가했다.
숨긴 완전 상태와 독립 답변기라는 실험 형식의 근거다.

**[ClinDet-Bench](https://arxiv.org/abs/2602.22771)**는 정보가 불완전해도
판정 가능한 경우와 더 물어야 하는 경우를 구분한다. 불필요한 질문과 성급한
확정을 함께 측정할 비교 대상이다.

**[Conformal Information Pursuit](https://proceedings.neurips.cc/paper_files/paper/2025/hash/823a3d2cf462fb815978314023e48f65-Abstract-Conference.html)**,
**[ALMA](https://link.springer.com/article/10.1007/s10994-026-07042-w)**,
**[SMART](https://www.jmlr.org/papers/v25/22-1310.html)**는 각각 보정된
불확실성 기반 질문, 정보 양식의 단계적 획득과 보류, 놓친 발견 위험 아래의
순차 측정 최소화를 다룬다. 새 행동 정책을 제시하려면 이 계열보다 나아야 한다.

### 2.4 실제 업무와 사람 검토

**[TRIAGE](https://ascopubs.org/doi/10.1200/OP-26-00076)**는 실제 EHR,
버전이 있는 프로토콜, 기준별 원문 근거와 코디네이터 재판정을 결합했다.
**[RECTIFIER](https://pmc.ncbi.nlm.nih.gov/articles/PMC11833652/)**는 사람 단독과
AI 보조 사전 선별을 비교했다. 실제 업무 개선을 주장하려면 모델 정확도만으로는
부족하고 검토 시간과 오류 유형을 함께 측정해야 한다.

**[CliniCARE-Bench](https://arxiv.org/abs/2608.07796)**는 EHR 도구, 정책 근거,
보류, 필수·금지 절차와 자원 사용을 평가한다. 도구 사용과 과정 평가 자체도
새로운 주장이 아니다.

## 3. 성능을 높이기 위한 구현 구성

아래 구성은 v5의 논문 기여가 아니라 강한 시스템을 만들기 위한 기본 설계다.
원 논문의 실제 역할, 프롬프트, 검색 자료, 반복·종료 방식과 최종 재설계는
[CLARIFYTRIAL_AGENT_ARCHITECTURE_REDESIGN.md](CLARIFYTRIAL_AGENT_ARCHITECTURE_REDESIGN.md)에
정리했다. 원문과 공개 코드 링크는
[CLARIFYTRIAL_AGENT_SOURCE_INDEX.md](CLARIFYTRIAL_AGENT_SOURCE_INDEX.md)에 모았다.

환자 기록 → 환자 정보 표준화 → 후보 시험 넓게 검색 → 기준별 판정과 근거
→ 부족 정보와 가능한 경로 확인 → 다음 행동 선택 → 기록 조회·환자 질문·별도
확인·보류 → 관련 기준만 재판정 → 후보 유지·확정 상태·추천 설명

### 3.1 후보 검색

- ClinicalTrials.gov 모집 상태, 질환, 연령, 위치, 단계와 중재 메타데이터 필터
- BM25 또는 키워드 검색과 임베딩 검색 결합
- 바이오마커, 약물, 병기, 치료 이력의 동의어와 표준 개념 정규화
- 초기 검색은 정밀도보다 실제 가능 후보 재현율 우선
- 최종 추천 평가와 후보 검색 실패를 분리

### 3.2 기준 구조화

- 선정과 제외 조건 분리
- 질환, 수치, 단위, 비교 연산자, 시간 범위, 치료 이력, 예외 조건 추출
- AND, OR, 부정과 적용 범위 보존
- 원문 구절과 구조화 결과 연결
- 시험별 한 번 파싱하고 버전과 수집일을 함께 저장

참고 자료:

- [Chia](https://pmc.ncbi.nlm.nih.gov/articles/PMC7452886/)
- [Leaf Clinical Trials Corpus](https://www.nature.com/articles/s41597-022-01521-0)
- [Clinical Trial Knowledge Base](https://pmc.ncbi.nlm.nih.gov/articles/PMC8407851/)

### 3.3 환자 정보 표준화

- 질환, 병기, 바이오마커, 나이, 성별, 수행 상태, 치료·수술 이력 추출
- 값뿐 아니라 측정 날짜, 출처와 부정 표현 보존
- 기록에 없는 값과 검사하지 않은 값을 구분
- 구조화 EHR 값과 임상 기록의 서술이 충돌하면 두 근거를 모두 유지

### 3.4 기준별 판정

- 수치·날짜·명시적 논리 조건은 코드로 우선 판정
- 모호한 자연어와 임상 의미 연결은 LLM 사용
- 각 기준에 상태, 환자 근거, 프로토콜 근거, 부족 변수와 신뢰도 저장
- 선정 기준과 제외 기준의 상태 의미를 섞지 않음
- 명시적 위반과 단순 정보 부족을 분리

### 3.5 정보 획득과 재평가

- 현재 판단과 다음 행동을 별도 출력
- 가능한 행동: 기록 조회, 환자 질문, 별도 확인 요청, 현재 정보로 판정, 보류
- 환자에게 답할 수 없는 검사값을 질문하지 않음
- 이미 기록에 있는 값을 다시 묻지 않음
- 새 정보와 연결된 기준만 재평가하고 무관한 판정은 유지
- 행동별 효과와 부담을 따로 기록하고 환자에게 새로 생기는 부담만 계산
- 같은 사실을 기존 기록, 외부 기록, 환자 답변과 새 검사 중 여러 경로로 얻을 수 있게 함
- 새 검사, 침습 절차와 약물 변경은 자동 실행하지 않고 사람의 선택을 요구
- 환자의 피로, 이동, 경제 상황, 시간 긴급성과 명시한 선호를 부담 판단에 반영

### 3.6 추천과 설명

- 명시적 제외 근거, 미해결 기준, 후보 검색 관련성과 환자 선호를 분리
- 후보 보존 상태와 현재 확정 상태를 따로 표시
- 추천마다 기준별 근거, 남은 정보, 질문·답변 이력과 전후 변화를 제공

### 3.7 비용과 안정성

- 시험 기준 파싱과 임베딩은 캐시
- 여러 후보를 한 요청에서 처리하되 누락된 시험 ID 검사
- 출력 스키마 검증과 실패 항목만 재시도
- 모델 호출 수, 입력·출력 토큰, 지연과 비용을 환자별 기록
- 모델 사용 비용과 환자 부담을 같은 항목으로 합치지 않음
- 환자 부담도 돈, 기다림, 이동, 신체·심리 부담, 의료 위험과 치료 방해를 한 숫자로 숨기지 않음

### 3.8 한 흐름으로 묶은 성능 구조

첫 구현은 다음 구성을 사용한다.

| 순서 | 하는 일 | 주 근거 |
|---|---|---|
| 1 | 시험 조건을 선정·제외, 수치, 기간과 논리로 미리 정리하고 원문 위치를 보존 | TrialMatchAI, EXACT |
| 2 | 날짜와 출처가 붙은 하나의 환자 상태표를 모든 단계가 함께 사용 | PRomop |
| 3 | 규칙 필터, 글자·의미 검색, 조건 재정렬 뒤 조건별 판정 | TrialMatchAI |
| 4 | 진행 관리 에이전트가 답변마다 후보와 미해결 조건을 갱신 | CLEAR-MATCH |
| 5 | 날짜·수치는 코드로 검사하고 위험 신호가 있는 결론만 별도 검토 | TRIAGE의 원문 인용·재검토 원칙 |
| 6 | 지금 자료로 충분한지 먼저 보고, 부족할 때만 다음 확인을 만듦 | MediQ |
| 7 | 중요한 조건과 여러 시험에 도움이 되면서 부담이 낮은 확인을 우선 | DQueST, Fink |
| 8 | 후보 유지와 현재 확정을 따로 계산하고 기록·환자·공식 확인·보류 중 경로를 선택 | ClarifyTrial v5 |

진행 관리, 검색·판정, 다음 확인의 세 전문 에이전트는 정해진 형식으로 결과를
주고받고 자유 토론은 하지 않는다. 날짜·수치·논리는 코드가 검사한다. 중요한
제거·확정, 근거 충돌과 코드 검사 불일치만 선택적 검토 에이전트가 한 번 확인한다.
그래도 결정할 수 없으면 `자료 부족`, `판단 어려움` 또는 `보류`로 남긴다.
MDAgents·MedAgents·MCC식 토론은 별도 비교 실험으로만 검토한다.

## 4. 자료별 역할

| 자료 | 사용할 평가 | 사용하지 않을 평가 |
|---|---|---|
| [ClinicalTrials.gov API v2](https://clinicaltrials.gov/data-api/api) | 실제 프로토콜·기준·모집 상태 입력 | 환자별 참여 가능 정답 |
| [TrialGPT Criterion Annotations](https://huggingface.co/datasets/ncbi/TrialGPT-Criterion-Annotations) | 기준별 판정과 근거 선택 | 여러 시험 추천 순위 전체, 실제 등록 |
| [TREC Clinical Trials 2022](https://trec.nist.gov/data/trials2022.html) | 후보 검색 Recall@k, nDCG@k | 질문 정책과 기준별 상태 변화 |
| [Synthea](https://synthetichealth.github.io/synthea/) | 합성 FHIR 조회와 정보 경로 시연 | 임상시험 적합성 정답 |
| TrialSim-10k | 대화 견고성과 논리 조건 비교 | 임의 행동 순서의 직접 정답이라고 가정 |
| 실제 프로토콜 기반 v5 짝 자료 | 후보 보존, 확정 가능성, 다음 행동 | 실제 유병률이나 실제 등록률 추정 |

TrialGPT 공개 자료의 현재 확인 규모는 기준 주석 1,015건, 환자 53명,
환자-시험 조합 105개다. 기준별 판정에는 유용하지만 여러 시험의 완전한 추천
순위와 행동 정책을 동시에 평가하기에는 작고 연결 구조가 제한적이다.

TREC 2022는 50개 환자 주제와 35,394개 판정이 있어 검색 평가에 적합하다.
판정되지 않은 환자-시험 쌍을 자동 음성으로 취급하지 않는다.

## 5. 정답과 판정 대상

다음 결과는 서로 다른 정답이다.

| 판정 대상 | 실제 질문 |
|---|---|
| 후보 검색 | 자세히 검토할 후보로 남길 가치가 있는가 |
| 사전 선별 | 다음 확인 단계로 보낼 것인가 |
| 현재 단계의 기준 판정 | 지금 확보한 근거로 기준을 확정할 수 있는가 |
| 등록 준비 | 동의·확인·기관 절차까지 충족했는가 |
| 실제 등록 | 환자가 실제로 시험에 들어갔는가 |

미등록은 자동으로 참여 불가가 아니다. 환자 거절, 의료진 판단, 자리, 일정,
거리, 보험과 시험 중단 등이 실제 등록에 영향을 준다. 이 문제는
[SEAR](https://pmc.ncbi.nlm.nih.gov/articles/PMC5775609/),
[PRISM](https://doi.org/10.1038/s41746-024-01274-7),
[TRIALELIG](https://openreview.net/pdf?id=UgwVxcqEqt) 등에서 이미 확인됐다.
판정 단계 구분 자체를 새 기여로 주장하지 않는다.

v5 짝 사례에는 최소한 다음 정답을 둔다.

1. 임상값이 기준을 지지·위반·미확인하는지
2. 현재 자료가 해당 단계의 확정 근거로 충분한지
3. 후보를 유지·제거·보류해야 하는지
4. 현재 단계에서 허용되는 다음 행동
5. 판정을 지지하는 환자 근거와 프로토콜 근거

## 6. 비교 실험

| 비교군 | 의미 |
|---|---|
| 고정 입력 단일 LLM | 질문 없이 한 번에 판정·추천 |
| 고정 입력 강한 매칭기 | TrialGPT·TrialMatchAI 계열 검색과 기준 판정 |
| 모두 확인 | 모든 부족 정보를 조회하거나 질문 |
| DQueST 방식 | 후보 제거량이 큰 다음 질문 선택 |
| Fink 방식 | 비용과 여러 시험에 미치는 영향을 고려한 행동 선택 |
| 불확실성 방식 | C-IP·ALMA 계열 질문과 보류 |
| v5 방식 | 후보 보존과 현재 단계의 확정 가능성을 분리해 행동 선택 |

비교 조건은 동일하게 맞춘다.

- 같은 환자와 후보 시험
- 같은 검색 결과와 프로토콜 원문
- 같은 기반 모델과 호출 한도
- 같은 행동 결과와 환자 답변기
- 같은 종료 가능 조건
- 같은 최종 판정기

## 7. 평가 지표

### 주 지표

- 실제 유지해야 할 후보의 성급한 제거율
- 확인이 남은 사례의 너무 이른 확정률
- 현재 단계 판정 정확도와 거시 평균 F1
- 허용 행동 집합 안의 행동을 선택한 비율
- 같은 임상 사실을 사용한 짝 사례의 일관된 방향 변화

### 시스템 성능

- 후보 검색 Recall@k와 nDCG@k
- 기준 상태 정확도와 거시 평균 F1
- 부족 변수 탐지 Recall@k
- 질문·조회 뒤 unknown 해소율
- 추천 목록의 Recall@k와 nDCG@k

### 효율

- 환자 질문 수
- 기록 조회와 별도 확인 요청 수
- 전체 행동 수
- 환자별 API 호출, 토큰, 지연과 비용
- 행동 수에 따른 판정 회복률 곡선

### 사람 비교가 있을 때

- 코디네이터 판단 시간
- 원문 근거 확인 시간
- 잘못 제거하거나 너무 일찍 확정한 사례 수
- 보조 도구 사용 전후의 판단 일치도

## 8. 결과 해석 기준

다음 조건이 필요하다.

1. 코디네이터 또는 임상의가 v5 정답 항목을 독립적으로 주석할 수 있음
2. 같은 임상 사실에서도 출처·시점·확인 단계에 따라 올바른 행동이 실제로 달라짐
3. 기존 기준 상태 점수만으로는 두 방향 오류를 충분히 설명하지 못함
4. v5 출력 방식이 같은 기반 모델에서 오류를 줄이거나 검토를 빠르게 함
5. 가장 가까운 비교군과 같은 조건에서 비교 가능

다음이면 중심 기여를 축소한다.

- 같은 공개 평가자료가 이미 존재
- 전문가 합의가 낮음
- 단계와 근거 충분성을 추가해도 오류 분석이나 모델 비교가 달라지지 않음
- 일반 세 상태 판정만으로 중요한 오류를 모두 설명 가능
- v5가 강한 비교군보다 추가 효용을 보이지 못함

## 9. 남은 확인 사항

- Yang 학위논문 전체의 질문 선택 함수와 종료 조건
- TrialSim-10k 공개 파일의 실제 열과 행동 재생 가능 범위
- v5 짝 사례를 만들 실제 프로토콜과 독립 전문가 확보
- 후보 보존과 현재 확정의 주석 일치도
- 코디네이터 비교 실험의 현실적인 사례 수와 시간

과거 Solar 합성 데모 수치는 이 문서에서 사용하지 않는다. v5의 첫 성능값은
자료, 비교군, 정답 지침을 고정한 뒤 새로 실행한 결과만 기록한다.
