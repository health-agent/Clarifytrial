# ClarifyTrial 개발 과정 보관 기록

이 문서는 v5 구현 과정의 주요 방향 전환만 남긴 기록이다. 현재 구조는
[프로그램 설계](../CLARIFYTRIAL_AGENT_ARCHITECTURE_REDESIGN.md), 현재 수치는
[검증 결과](../CLARIFYTRIAL_VALIDATION_RESULTS.md)를 기준으로 삼는다.

## 1. 처음 확인한 문제

TrialGPT 공개 조건 자료에서 새 모델을 한 번 호출해 비교했을 때 답 이름 일치율이
TrialGPT보다 낮았다. 차이의 대부분은 `현재 기록으로 판단 가능`과 `정보 부족`의
경계였다. 예를 들어 제외 조건에 해당하는 사실이 기록에 언급되지 않았을 때,
TrialGPT와 전문가는 기록 관행을 근거로 위반하지 않음으로 판단하는 경우가 많았고 새
모델은 직접적인 부재 확인이 없다며 정보 부족으로 남겼다.

답 이름만 맞추는 지시문 조정은 후보 유지 행동을 거의 바꾸지 않았고, 반복 검토와
인터넷 검색도 개발 자료에서 추가 정답을 만들지 못했다. 이 때문에 연구 중심을 단일
조건 답 이름의 소폭 향상에서 질문 뒤 후보 변화로 옮겼다.

## 2. 질문–답변–재판정 흐름

초기 구현은 공개 시험 15건과 합성 환자 30명에서 시작했다. 가상 환자의 전체 상태를
먼저 만들고 일부 사실을 감춘 뒤, 프로그램이 질문하면 저장된 답만 반환했다.

고정된 정보 순서, 현재 가장 많은 시험에 연결된 정보 우선, 가능한 답의 분포를 가정한
방법과 남은 확인 횟수 전체를 계산하는 방법을 비교했다. 답의 확률을 가정한 복잡한
방법은 개발에 사용하지 않은 자료에서 일관된 이득을 주지 않았다. 현재 영향 우선과
남은 횟수 전체 계산을 최종 비교로 남겼다.

## 3. 후보 유지와 현재 확인의 분리

오래된 검사 결과처럼 참가 가능성은 보이지만 현재 단계의 근거로 충분하지 않은 사례를
하나의 답으로 처리하기 어려웠다. 이에 시험마다 다음 두 결과를 따로 저장했다.

- 더 확인할 후보인지
- 지금 자료로 확인이 끝났는지

질문 뒤 실제 후보로 확정한 수만 세면 후보를 무조건 많이 남기는 방법에 유리하다.
따라서 처음에는 남았지만 결국 부적합인 후보를 질문 뒤 정리한 수도 함께 계산하도록
평가를 바꿨다.

## 4. 환자 부담과 확인 방법

초기 질문 정책은 정보 하나마다 고정 비용을 사용했다. 이후 같은 혈액검사라도 이미
예정된 진료에서 받는 경우와 별도 방문이 필요한 경우의 부담이 다르다는 점을 반영했다.

확인 방법을 기존 기록, 외부 기록, 환자 답변, 기존 공식 결과, 새 검사와 의료진 판단으로
나누고 대기, 이동, 직접 비용, 신체·심리 부담, 의료 위험과 치료 방해를 별도로 저장했다.
환자의 이동·비용·시간 제한과 새 검사·추가 방문 허용 여부는 참가 조건이 아니라 확인
방법 선택에만 적용했다.

## 5. 공개 시험 범위 확장

팀 공개 시험 1,931건 가운데 현재 모집 중이거나 모집 예정인 589건을 넓은 검색 범위로
연결했다. 10개 질환에서 시험 50건과 객관적인 조건 202개를 구조화하고 합성 환자 50명을
만들었다. 개발에 사용하지 않은 환자 30명에게 시험 5개씩을 연결해 전체 흐름을
점검했다.

기존 시험과 겹치지 않는 새 공개 시험 30건도 별도로 골랐다. 절반은 개발용, 절반은
최종 평가용으로 고정했고 구조화 규칙만 사용한 실행과 두 모델 호출 방식을 같은
75개 판단에서 비교했다.

## 6. 모델 역할 구조의 결정

초기에는 진행 관리, 조건 판단, 다음 질문과 검토를 모두 모델 역할로 구성했다. 그러나
구조화 조건 최종 평가에서 코드만 사용한 실행과 모델을 부른 두 실행의 결과가 같았고,
모델 호출만 0회에서 65회와 105회로 늘었다.

최종 구조는 코드가 진행, 수치·날짜 계산, 정보 선택과 종료를 맡는다. 자유 문장 해석이나
코드로 계산할 수 없는 조건에만 필요한 모델 역할을 부른다. 근거 충돌이 있을 때만 별도
검토를 사용하며 역할끼리 자유 토론하지 않는다.

## 7. 통합 실행과 보고서

다음 기능을 한 실행 경로로 연결했다.

- 정해진 형식의 환자와 시험 파일 입력
- 공개 시험 후보 검색
- 조건별 판단과 근거 저장
- 부족 정보 선택과 질문
- 합성 답 또는 직접 입력 답 반영
- 관련 조건만 재판정
- 환자 선택이나 의료진 승인 대기
- 중단된 실행 저장과 재개
- 최종 목록, 변화 통계, 모델 사용량과 환자 부담 보고서

과거의 세부 실험 숫자와 요구사항 표는 Git 기록에 남아 있다. 현재 연구 해석에는 현행
검증 문서의 수치만 사용한다.
