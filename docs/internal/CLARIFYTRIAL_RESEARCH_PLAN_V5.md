# ClarifyTrial 연구계획 v5

ClarifyTrial은 환자 정보가 모자라 임상시험 참가 조건을 끝까지 확인하지 못하는 상황을
다룬다. 선행연구는 [연구 지식 정리](RESEARCH_KNOWLEDGE_BASE.md), 실제 실험 수치는
[검증 결과](CLARIFYTRIAL_VALIDATION_RESULTS.md)에 있다.

## 1. 연구 문제

환자 기록이 불완전하면 한 시험을 곧바로 `참가 가능`, `참가 불가`, `정보 부족` 가운데
하나로 고르기 어렵다. 이때는 다음 두 판단이 모두 필요하다.

1. 더 확인할 가치가 남아 있는가?
2. 현재 자료만으로 참가 조건 확인을 마칠 수 있는가?

최근 검사 결과가 없더라도 오래된 결과와 다른 기록에서 참가 가능성이 보일 수 있다.
이런 시험은 후보로 남기면서 최근 검사를 기다린다. 새 정보가 들어오면 관련 조건을
다시 계산하고, 결과가 확정되거나 더 이상 알아볼 방법이 없을 때 멈춘다.

## 2. 연구 질문

### 2.1 한 번의 추가 확인으로 미확정 시험을 얼마나 정리할 수 있는가?

기본 문진에서 확인할 나이, 임신·수유 여부와 활동성 중증 감염은 처음부터 제공한다.
그 뒤에도 남아 있는 미확정 시험에서 필요한 환자 정보를 찾는다. 환자마다 한 번까지
확인하고, 확인 완료나 조건 불충족으로 바뀐 시험과 계속 기다리는 시험을 따로 센다.

### 2.2 어떤 정보 연결 구조에서 질문 순서가 달라지는가?

한 환자에게 시험이 여러 건 연결돼 있으면 같은 환자 정보가 여러 조건에 쓰일 수 있다.
어느 정보를 먼저 묻느냐는 연결 모양에 따라 효과가 달라질 수 있다. 모든 시험이 하나의
정보를 공유하는 경우, 시험마다 정보가 나뉜 경우, 일부 시험만 사슬처럼 이어진 경우를
포함한 여러 구조에서 같은 확인 횟수로 비교한다.

현재 미확정 시험과 조건에 많이 연결된 정보를 먼저 고르는 규칙을 강한 단순 비교군으로
둔다. 가능한 순서 전체의 평균, 자료에 적힌 순서, 남은 횟수를 함께 계산하는 방법도
같은 환자와 답으로 실행한다.

### 2.3 후보 가능성과 현재 확인 상태를 끝까지 분리할 수 있는가?

최근 자료가 없어도 참가 가능성이 남은 시험은 후보로 둔다. 답을 받은 뒤에는 관련
조건만 다시 계산해 확인 완료, 조건 불충족, 확인 대기를 갱신한다. 남겨야 할 시험을
너무 일찍 제외한 경우와 필요한 근거 없이 확인 완료로 표시한 경우를 따로 기록한다.

### 2.4 환자의 제한을 지키며 확인 방법을 고를 수 있는가?

같은 정보를 기존 기록, 환자 답변, 이미 받은 공식 결과나 새 검사로 알아볼 수 있다.
이동·비용·시간 부담과 새 검사·추가 방문 허용 여부가 주어지면 이용할 수 없는 방법을
먼저 뺀다. 확인을 마친 시험이 줄거나 대기가 길어지면 그 변화도 함께 보고한다.

### 2.5 언어모델은 어느 단계에 필요한가?

값, 날짜와 논리 관계가 분리된 조건은 코드가 계산한다. 자유 문장 해석과 코드로 뜻을
정하기 어려운 조건, 근거 충돌, 사람이 읽을 질문과 설명에 언어모델을 사용한다. 같은
구조화 자료에서 모델 호출을 늘렸을 때 결과와 사용량이 달라지는지 보조 실험으로
확인한다. 여러 모델 역할 자체는 선행연구에서 이미 사용된 방법이다.

### 2.6 연구 기여와 초록에서 밝힐 새로움

ClarifyTrial의 새로움은 질문 생성, 단순한 질문 횟수 제한이나 답변 뒤 재판정 가운데
하나를 처음 제안했다는 데 있지 않다. 임상시험 사전선별을 한 번의 적격성 판정으로
끝내지 않고, 현재 정보로 결론을 내릴 수 없는 상태를 제한된 확인과 다음 행동으로
이어지는 과정으로 다룬 데 있다.

초록에서는 다음 세 가지를 핵심 기여로 제시한다.

1. **제한된 확인 아래의 동적 사전선별**
   - 계속 확인할 후보인지와 현재 자료로 조건 확인을 마쳤는지를 따로 유지한다.
   - 허용된 추가 확인 횟수 안에서 새 근거를 얻고, 끝내 확인하지 못한 시험은 억지로
     확정하지 않고 확인 대기로 남긴다.
   - 전체 정보 기준 적격으로 확인되는 방향과 부적격으로 정리되는 방향을 따로 측정해,
     한쪽 전환만 있는 자료를 전체 성능처럼 제시하지 않는다.
2. **질문 선택 방법이 작동하는 연결 구조의 구분**
   - 한 단계씩 영향이 큰 정보를 고르는 단순 규칙과 남은 확인 횟수의 정보 조합을 함께
     계산하는 방법을 같은 조건에서 비교한다.
   - 여러 시험이 같은 정보에 직접 연결된 구조에서는 단순 규칙으로 충분할 수 있지만,
     질문 사이의 의존관계가 있는 사슬형 구조에서는 여러 단계를 함께 계산하는 방법이
     유리해지는 조건을 보인다.
   - 조합 계산 방법은 보이는 부족 정보의 조합을 빠짐없이 계산하는 비교군이며, 숨겨진
     미래 답을 아는 전역 최적 정책으로 표현하지 않는다.
3. **환자에게 실행 가능한 확인 경로와 그 대가의 측정**
   - 무엇을 확인할지와 기존 기록, 환자 답변, 공식 결과, 새 검사나 의료진 검토 가운데
     어떻게 확인할지를 나눈다.
   - 환자가 허용하지 않은 검사와 방문을 제외하고, 그 결과 확인 대기 시험이 늘어나는
     변화까지 함께 보고한다.

현재 부적격 시험의 재검토 우선순위는 위 핵심 기여와 이어지는 **탐색적 시간축 확장**으로
둔다. 이 확장에서는 현재 부적격 판정을 바꾸지 않고, 배제 사유를 영구형, 시간 경과형,
검사값 변동형과 불확실형으로 나눠 재검토 가치와 시점을 살핀다. 여기서 변하는 것은
주로 고정된 시험 기준에 대한 환자의 검사값이나 시간 조건이며, 시험 프로토콜의 참가
기준 자체가 개정되는 문제와 구분한다. 실제 임상시험 환자의 적격 전환을 추적한 자료가
마련되기 전에는 미래 적격 확률이나 임상 성능으로 제시하지 않는다.

초록의 중심 문장은 다음 범위로 쓴다.

> ClarifyTrial은 불완전한 환자 정보에서 후보 유지와 현재 확인 상태를 분리하고, 제한된
> 확인 기회 안에서 다음 근거와 환자에게 가능한 확인 경로를 선택한 뒤 관련 조건만
> 갱신하는 동적 사전선별 흐름이다.

초록의 결과 문장에서는 공개 시험 기반 평가, 정보 연결 구조 실험과 환자 제한 실험의
자료와 분모를 각각 밝힌다. 합성 환자 결과를 실제 참가 판정 정확도나 환자 편익으로
넓히지 않고, 단순 질문 선택 규칙이나 확인 예산 자체를 최초 제안으로 표현하지 않는다.

## 3. 예상하는 결과와 판단 기준

- 추가 질문이 나온 환자에서는 적어도 한 건의 미확정 시험이 확인 완료나 조건 불충족으로
  바뀔 것으로 본다. 질문 수, 정리된 시험 수와 남은 대기 시험을 모두 보고한다.
- 한 가지 환자 정보가 현재 미확정 시험 여러 건을 직접 정리하는 구조에서는 질문 순서의
  영향이 커질 것으로 본다. 정보가 시험별로 나뉜 구조에서는 차이가 거의 없을 수 있다.
- 후보 가능성과 현재 확인 상태를 따로 저장하면 최근 자료를 기다리는 시험의 다음 행동을
  결과에 남길 수 있다.
- 환자 제한을 적용하면 허용하지 않은 새 검사와 추가 방문이 사라져야 한다. 그 때문에
  확인 대기 시험이 늘어나는 결과도 정상적인 동작으로 기록한다.
- 객관적으로 구조화된 조건은 코드 계산을 우선한다. 언어모델 호출이 필요한 범위는
  자유 문장과 모호한 조건으로 좁힌다.

질문 순서가 언제나 유리하다는 가정은 두지 않는다. 효과가 없거나 낮아지는 구조도 같은
표에 남겨 작동 조건을 찾는다.

## 4. 한 사례의 실행

```text
환자 정보와 시험 조건 준비
→ 관련 시험 검색
→ 조건별 판단과 근거 저장
→ 후보 유지 여부와 현재 확인 상태 계산
→ 아직 필요한 정보와 확인 방법 선택
→ 답을 받으면 연결된 조건만 다시 계산
→ 종료 조건까지 반복
→ 시험별 결과, 변화와 남은 확인 사항 출력
```

다음 상황에서는 반복을 멈춘다.

- 모든 후보 시험의 현재 판단이 끝남
- 확인할 정보가 더 없음
- 허용된 확인 횟수를 모두 사용함
- 필요한 답을 얻을 수 없음
- 새 검사, 추가 방문이나 의료진 판단을 기다려야 함
- 근거 충돌이 남아 별도 검토가 필요함

## 5. 시험별 결과

| 결과 | 뜻 |
|---|---|
| 후보 유지 | 참가 가능성이 남아 있어 더 확인할 가치가 있다. |
| 후보 제거 | 현재 자료에 명확한 조건 위반이 있다. |
| 후보 판단 보류 | 환자 근거나 시험 조건이 충돌한다. |

| 현재 확인 상태 | 뜻 |
|---|---|
| 확인 완료 | 이번 사전 검토에서 요구한 근거가 현재 자료에 있다. |
| 추가 확인 필요 | 참가 가능성은 남지만 날짜, 출처나 절차 확인이 남았다. |
| 참가 조건 불충족 | 현재 자료에 명확한 위반 근거가 있다. |
| 판단 보류 | 자료가 있어도 조건의 뜻이나 적용이 모호하다. |

`후보 유지 · 추가 확인 필요`인 시험에는 필요한 정보와 다음 확인 방법을 붙인다.

## 6. 다음 정보와 확인 방법

현재 미확정인 시험·조건과 연결되지 않은 정보와 이용할 수 없는 확인 방법을 먼저 뺀다.
환자가 허용하지 않은 새 검사와 방문도 후보에서 제외한다. 남은 정보는 다음 내용을
차례로 살펴 고른다.

1. 현재 미확정 시험 몇 건과 연결되는가
2. 아직 풀리지 않은 조건 몇 개와 연결되는가
3. 같은 정보라면 새 검사, 방문, 비용, 대기, 신체·심리 부담과 의료 위험이 어느 정도인가

기존 병원 기록, 외부 기관 기록, 환자 답변, 이미 시행한 공식 검사·평가, 새 검사·평가,
의료진 판단을 서로 다른 방법으로 기록한다. 새 침습 절차나 치료 변경은 자동으로
실행하지 않고 선택 대기 상태로 남긴다.

환자 상황 입력은 선택 사항이다. 입력이 없으면 모든 방법을 허용한다. 입력이 있으면
피로와 이동 제한, 경제 부담, 시간 긴급성, 이미 예정된 진료, 민감한 질문과 새 절차
선호를 확인 방법에 반영한다. 임상시험 참가 조건 자체는 바꾸지 않는다.

## 7. 실험자료

### 공개 시험 50건과 합성 환자 50명

- 모집 중·모집 예정 공개 시험 589건을 검색 대상으로 사용
- 10개 질환에서 시험 5건씩 선택
- 공개 시험 원문의 구조화 조건 202개 사용
- 자료 제작·조정 환자 20명과 최종 평가 환자 30명 분리
- 최종 평가 환자마다 같은 질환의 시험 5건 연결
- 나이, 임신·수유 여부, 활동성 중증 감염은 시작 입력에 제공
- 남은 환자 정보는 해당 정보를 확인했을 때만 공개

### 정보 연결 모양 1,800개

- 시험과 환자 정보가 연결되는 모양 9종
- 모양마다 200개 구조 생성
- 한 번의 확인에서 단순 순서와 현재 규칙 비교
- 비슷한 분포와 일부 조건을 바꾼 분포를 나눠 확인

### 적격·부적격 방향별 보완 평가

- 3개 질환의 공개 시험 15건과 구조화 조건 80개
- 자료 제작·조정 합성 환자 10명과 초기 독립 평가 환자 20명 분리
- 초기 독립 환자마다 정보 가림 2개와 시험 5건을 적용한 200개 반복 관측
- 질문 전 미정 120건을 전체 정보 기준 적격 30건과 부적격 90건으로 나눠 보고
- 프로그램 기본 한도인 3회를 주 평가로 두고 1·2회와 0~3회 전체 곡선을 함께 보고
- 가능한 정보 순서 전체 평균, 현재 영향 우선과 정확 탐색 비교
- 통계 범위는 반복 관측 200개가 아니라 질환별 환자 20명을 단위로 계산

### 확인 방법과 환자 제한 자료

- 합성 환자 20명, 정보를 가린 사례 40개
- 같은 답을 주는 기존 공식 결과와 새 검사 방법
- 부담 최소, 이동·비용 제한, 시간 긴급 설정
- 새 검사와 추가 방문을 허용하거나 금지한 80개 설정의 짝지은 비교

### 공개 비교자료

- TREC Clinical Trials 2021·2022: 관련 임상시험 검색 평가
- TrialGPT Criterion Annotations 1,015쌍: 질문 전 개별 조건 판단 비교
- 개발과 겹치지 않는 공개 시험 30건: 개발용 15건과 최종 점검용 15건을 따로 사용

자료마다 확인할 수 있는 범위가 다르다. 검색 정답으로 질문 순서를 채점하거나, 개별
조건 정답으로 전체 추천을 채점하지 않는다. 세부 구성은
[실험자료](CLARIFYTRIAL_DATASETS.md)에 있다.

## 8. 합성 환자 제작 원칙

1. 공개 시험에서 수치, 날짜, 예·아니오나 논리 관계가 분명한 조건을 고른다.
2. 가상 환자의 전체 상태와 각 시험의 예상 결과를 먼저 만든다.
3. 서로 연결된 환자 값에 모순이 생기지 않게 한다.
4. 기본 문진 정보는 시작 입력에 넣는다.
5. 추가 확인용 정보와 답은 질문을 고르는 프로그램에서 분리해 저장한다.
6. 프로그램이 정보를 선택한 뒤에만 해당 답을 공개한다.
7. 전체 상태에 없는 사실을 답변 과정에서 새로 만들지 않는다.
8. 같은 뜻의 자유 문장 조건은 같은 환자 정보로 묶어 이미 아는 내용을 다시 묻지 않는다.

오래된 검사와 최근 검사, 환자 답변과 공식 결과의 구분은 별도 실행 예제와 코드 검사로
확인한다. 질문 순서 수치와 섞지 않는다.

## 9. 비교 방법

### 다음 정보 선택

| 방법 | 설명 |
|---|---|
| 추가 확인 없음 | 시작 환자 정보만 사용한다. |
| 입력 순서 | 자료 파일에 적힌 순서대로 확인한다. |
| 가능한 순서 전체 평균 | 가능한 정보 순서를 모두 실행해 평균을 낸다. |
| 현재 영향 우선 | 현재 미확정 시험과 조건에 많이 연결된 정보를 고른다. |
| 남은 횟수 전체 계산 | 남은 확인 횟수 안에서 정보 조합을 다시 계산한다. |

모든 방법에 같은 환자, 시험, 숨긴 답, 확인 횟수와 최종 판정 규칙을 사용한다.

### 모델 사용

| 방법 | 언어모델이 맡는 부분 |
|---|---|
| 구조화 규칙만 사용 | 없음 |
| 조건 판단 모델 사용 | 코드로 계산할 수 없는 조건 판단 |
| 역할별 모델 사용 | 조건 판단과 필요한 경우 질문 문장 작성 |

언어모델이 구조화 조건의 수치 계산을 바꾸도록 허용하지 않는다. 모델 사용량은 호출
횟수와 전체 토큰으로 기록한다.

## 10. 평가 항목

### 질문 전후의 변화

- 처음에 추가 정보가 필요했던 시험 수
- 실제 질문을 받은 환자 수와 질문 수
- 확인 완료로 바뀐 시험 수
- 조건 불충족으로 정리된 시험 수
- 전체 정보 기준 적격 복원 기회와 부적격 정리 기회를 각각 분모로 한 방향별 해결률
- 질문 뒤에도 기다리는 시험 수
- 이미 아는 정보를 다시 물은 횟수
- 남겨야 할 시험을 너무 일찍 제외한 횟수
- 필요한 근거 없이 확인 완료로 표시한 횟수

### 질문 순서와 연결 구조

- 같은 확인 횟수에서 시험 상태가 기대 결과와 같아진 비율
- 환자별 개선·동일·하락 수
- 연결 모양별 단순 순서와 현재 규칙의 차이
- 확인한 정보가 연결된 시험과 조건 수

### 환자 부담과 실행 품질

- 새 검사와 추가 방문 제안 수
- 환자가 허용하지 않은 방법을 선택한 수
- 확인 대기로 남은 시험과 모든 시험을 정리한 설정 수
- 합성 대기시간과 선택한 행동 수
- 언어모델 호출과 토큰, 실행 실패와 재시도
- 중단한 실행을 같은 입력으로 이어서 실행할 수 있는지
- 같은 원본과 설정으로 자료를 다시 만들었을 때 결과가 같은지

## 11. 결과 해석

- 처음의 36.5%포인트 차이는 기본 문진 정보까지 가린 자료의 민감도 결과로 다룬다.
- 기본 문진을 제공한 평가에서는 질문으로 정리된 시험과 남은 대기 시험을 중심으로 본다.
- 질문 순서의 효과는 연결 모양별로 보고한다. 효과가 없거나 낮아진 구조도 포함한다.
- 실제 후보 확인과 제외 후보 정리를 따로 기록한다.
- 환자 제한을 적용한 뒤 확인 완료가 줄면 피한 검사·방문과 늘어난 대기를 함께 적는다.
- 구조화 조건과 합성 답으로 얻은 결과는 프로그램의 상태 전이와 선택 규칙을 점검한
  수치로 사용한다.
- 공개 시험의 일부 조건에서 나온 결과를 전체 임상시험 판정으로 넓히지 않는다.
- TrialGPT보다 높은 전체 추천 성능, 실제 환자 편익이나 임상 정확도는 주장하지 않는다.

## 12. 진행 상태

시험 검색, 조건 계산, 질문 선택, 환자 제한 적용, 답변 뒤 재판정, 중단·재개와 보고서
생성까지 구현했다. 공개 시험 평가, 적격·부적격 방향별 보완 평가, 정보 연결 구조 실험,
확인 방법과 환자 제한 실험도 완료했다. 자유 문장으로 적힌 복잡한 의료 조건의 해석
성능은 후속 평가로 남아 있다.
