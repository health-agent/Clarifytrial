# ClarifyTrial 연구계획 v5

이 문서가 현행 연구계획이다. 선행연구의 세부 내용은
[연구 지식 정리](RESEARCH_KNOWLEDGE_BASE.md), 실제 결과는
[검증 결과](CLARIFYTRIAL_VALIDATION_RESULTS.md)에서 관리한다.

## 1. 연구 문제

불완전한 환자 정보로 임상시험을 사전 검토할 때 `참가 가능`, `참가 불가`, `정보
부족` 하나만 고르면 두 가지 판단이 섞인다.

1. 더 확인할 가치가 있는 시험인가?
2. 현재 자료만으로 참가 조건을 확인할 수 있는가?

ClarifyTrial은 두 판단을 분리하고, 추가 정보가 필요한 시험에는 무엇을 어떤 방법으로
확인해야 하는지 붙인다. 새 정보가 들어오면 관련 조건만 다시 판단해 목록을 갱신한다.

## 2. 핵심 연구 질문

### 연구 질문 1. 정보가 부족한 실제 후보를 보존할 수 있는가?

현재 자료만으로 확인이 끝난 시험만 보여 주는 방식과 비교해, 합성 환자의 숨겨 둔 전체
상태에서 참가 가능한 시험을 추가 확인 후보로 얼마나 남기는지 본다. 동시에 명확한
조건 위반이 있는 시험을 잘못 남기는지도 확인한다.

### 연구 질문 2. 제한된 확인으로 후보를 정리할 수 있는가?

확인 횟수가 제한됐을 때 실제 참가 가능 후보를 얼마나 확정하고, 처음에는 정보 부족으로
남았지만 결국 부적합인 후보를 얼마나 제외하는지 함께 측정한다. 두 결과를 하나의
점수로 합치지 않는다.

### 연구 질문 3. 환자의 제한을 지키면서 확인 방법을 고를 수 있는가?

같은 정보를 기존 기록, 환자 답변, 이미 받은 공식 결과 또는 새 검사로 확인할 수 있을
때, 환자가 입력한 이동·비용·시간 제한과 새 검사·추가 방문 허용 여부를 지키는지 본다.
제한을 지킨 결과 확인을 끝낸 시험 수가 줄면 피한 검사와 방문을 함께 보고한다.

### 구현 질문. 언어모델은 어느 단계에 필요한가?

이미 수치·날짜·논리 관계가 분리된 조건은 코드로 계산한다. 자유 문장 해석이나 코드로
계산할 수 없는 조건에만 언어모델을 사용한다. 같은 평가자료에서 모델 호출을 늘렸을 때
정확도와 비용이 어떻게 달라지는지 확인한다. 이는 중심 연구 질문을 보조하는 구현
선택이며, 여러 모델 역할 자체를 새 기여로 다루지 않는다.

## 3. 예상 결과

- 두 판단을 분리하면 정보 부족 때문에 첫 화면에서 사라질 실제 후보를 보존할 수 있다.
- 영향이 큰 정보를 먼저 확인하면 입력 파일 순서보다 적은 확인으로 더 많은 시험 판단을
  끝낼 수 있다.
- 환자 제한을 반영하면 허용하지 않은 새 검사와 추가 방문을 줄일 수 있다.
- 구조화된 조건에서는 언어모델 호출을 늘리는 것보다 코드 계산이 더 싸고 안정적이다.

각 예상 결과는 독립적으로 판단한다. 하나가 맞았다고 나머지도 맞는 것으로 해석하지
않는다.

## 4. 한 사례의 실행 순서

```text
환자 정보와 시험 조건 준비
→ 관련 시험 검색
→ 조건별 판단과 근거 저장
→ 후보 유지 여부와 현재 확인 상태를 따로 계산
→ 부족한 정보가 있으면 다음 정보와 확인 방법 선택
→ 답을 받으면 관련 조건만 다시 판단
→ 종료 조건까지 반복
→ 현재 확인된 시험, 추가 확인 후보, 조건 불충족 시험과 변화 기록 출력
```

종료 조건은 다음과 같다.

- 모든 후보 시험의 현재 판단이 끝남
- 확인할 정보가 더 없음
- 정해 둔 확인 횟수를 모두 사용함
- 필요한 답을 얻을 수 없음
- 새 검사, 추가 방문 또는 의료진 판단을 기다려야 함
- 서로 충돌하는 근거가 남아 별도 검토가 필요함

## 5. 시험별 결과

| 후보 유지 결과 | 뜻 |
|---|---|
| 후보 유지 | 참가 가능성이 남아 있어 계속 확인할 가치가 있음 |
| 후보 제거 | 되돌리기 어려운 명확한 조건 위반이 있음 |
| 판단 보류 | 환자 근거 또는 시험 조건이 서로 충돌함 |

| 현재 확인 결과 | 뜻 |
|---|---|
| 현재 확인 완료 | 이번 사전 검토 범위에서 요구한 근거가 현재 자료에 있음 |
| 추가 확인 필요 | 참가 가능성은 남지만 날짜, 출처 또는 절차 확인이 남음 |
| 참가 조건 불충족 | 현재 자료에 명확한 위반 근거가 있음 |
| 판단 보류 | 자료가 있어도 조건의 뜻이나 임상적 해석이 모호함 |

`후보 유지 + 추가 확인 필요`가 ClarifyTrial이 보존하려는 회색지대다.

## 6. 다음 정보와 확인 방법

먼저 결과를 바꿀 수 없는 정보를 제외한다. 남은 정보는 다음 순서로 비교한다.

1. 몇 개 후보 시험의 판단에 영향을 주는가
2. 몇 개 미해결 조건과 연결되는가
3. 남은 확인 횟수 안에 어느 정보 조합이 더 많은 시험 판단을 끝내는가
4. 환자가 허용한 방법인가
5. 새로 생기는 이동, 비용, 대기, 신체·심리 부담과 의료 위험은 어느 정도인가

확인 방법은 기존 병원 기록, 외부 기관의 기존 기록, 환자 답변, 이미 시행한 공식
검사·평가, 새 검사·평가, 의료진 판단으로 구분한다. 새 침습 절차나 치료 변경은 자동으로
실행하지 않고 선택 대기 상태로 남긴다.

환자 상황 입력은 선택 사항이다. 입력이 없으면 모든 방법을 허용하는 중립 설정을
사용한다. 입력이 있으면 피로와 이동 제한, 경제 부담, 시간 긴급성, 이미 예정된 진료,
민감한 질문과 새 절차 선호를 확인 방법 선택에만 반영한다.

## 7. 실험자료

### 공개 시험 기반 전체 흐름 자료

- 모집 중·모집 예정 공개 시험 589건을 검색 대상으로 사용
- 10개 질환의 공개 시험 50건에서 객관적인 조건 202개를 구조화
- 합성 환자 50명의 전체 상태를 먼저 만들고 일부 사실을 감춘 입력 생성
- 개발 환자 20명과 최종 점검 환자 30명 분리
- 환자마다 같은 질환의 시험 5개를 연결

### 기존 자료와 겹치지 않는 새 시험 자료

- 5개 질환의 공개 시험 30건
- 개발용 시험 15건과 최종 평가용 시험 15건 분리
- 구조화 조건 116개, 합성 환자 50명
- 최종 평가에는 환자 25명과 환자–시험 판단 75개 사용
- 기대 결과는 실행 프로그램의 판정 함수를 부르지 않는 별도 계산으로 고정

### 공개 비교자료

- TREC Clinical Trials 2021·2022: 수만 건에서 관련 시험을 찾는 검색 평가
- TrialGPT Criterion Annotations: 환자 기록과 개별 참가 조건 1,015쌍의 판단 평가

자료마다 평가할 수 있는 문제가 다르다. 검색 정답으로 질문 순서를 평가하거나, 개별
조건 정답으로 여러 시험 추천 전체를 평가하지 않는다. 자세한 내용은
[실험자료 구성](CLARIFYTRIAL_DATASETS.md)에 있다.

## 8. 합성 환자 제작 원칙

1. 공개 시험 원문에서 수치, 날짜, 예·아니오 또는 논리 관계가 분명한 조건만 고른다.
2. 가상 환자의 전체 상태와 각 시험의 기대 결과를 먼저 만든다.
3. 나이, 임신·수유 상태와 치료 이력처럼 서로 연결된 값은 모순되지 않게 만든다.
4. 시작 입력에서는 결과에 영향을 주는 사실 1개, 2개, 3개 또는 5개를 감춘다.
5. 감춘 값과 확인 방법은 질문을 고르는 프로그램과 분리해 저장한다.
6. 프로그램이 선택한 확인 방법이 실행된 뒤에만 해당 답을 공개한다.
7. 전체 상태에 없는 사실은 답변 과정에서 새로 만들지 않는다.

값이 완전히 빠진 경우와 값은 있지만 날짜나 출처가 부족한 경우를 모두 포함한다. 전자는
무엇을 물어야 하는지, 후자는 현재 자료가 충분한지 구분하는 능력을 본다.

## 9. 비교 방법

### 정보 선택 방법

| 방법 | 설명 |
|---|---|
| 추가 확인 없음 | 처음 환자 정보만 사용 |
| 입력 순서 | 파일에 적힌 부족 정보 순서대로 확인 |
| 현재 영향 우선 | 그 순간 가장 많은 미완료 시험에 연결된 정보를 확인 |
| ClarifyTrial | 남은 확인 횟수 안에서 사용할 정보 조합을 다시 계산 |

모든 방법에 같은 환자, 시험, 숨긴 답, 확인 횟수와 최종 판정 규칙을 사용한다.

### 모델 사용 방법

| 방법 | 언어모델이 맡는 부분 |
|---|---|
| 구조화 규칙만 사용 | 없음 |
| 조건 판단 모델 사용 | 코드로 계산할 수 없는 조건 판단 역할 |
| 코드가 역할을 배정 | 조건 판단과 필요한 경우 질문 문장 작성 역할 |

구조화 조건 평가에서 모델이 코드 계산을 바꾸도록 허용하지 않는다. 모델 사용량은 호출
횟수와 전체 토큰으로 함께 기록한다.

## 10. 평가 항목

### 후보 보존과 정리

- 처음 화면에서 보이지 않을 실제 참가 가능 후보 수
- 추가 확인 후보로 보존한 수
- 질문 뒤 실제 참가 가능 후보로 확정한 수와 비율
- 처음에는 남았지만 결국 제외되는 후보 수
- 질문 뒤 제외로 정리한 수와 비율
- 남겨야 할 시험을 잘못 제외한 수
- 필요한 정보가 남았는데 현재 확인 완료로 표시한 수

### 질문과 환자 부담

- 실제로 확인한 정보 수
- 결과 개선에 필요하지 않았던 확인 수
- 같은 정보를 반복해서 확인한 수
- 답을 얻지 못한 확인 수
- 새 검사와 추가 방문 횟수
- 환자가 허용하지 않은 방법을 선택한 수
- 예상 대기 시간, 이동, 직접 비용, 신체·심리 부담과 의료 위험

### 실행 품질

- 외부 언어모델 호출 횟수와 토큰
- 실패한 환자 수와 다시 시도한 횟수
- 중단 뒤 같은 입력으로 이어서 실행할 수 있는지
- 같은 원본과 설정에서 평가자료를 다시 만들었을 때 결과가 같은지

## 11. 결과 해석 기준

- 입력 순서보다 좋다는 이유만으로 새 질문 정책이 우수하다고 말하지 않는다. 현재
  영향이 큰 정보를 바로 고르는 강한 단순 방법과 비교한다.
- 실제 후보 확정과 제외 후보 정리를 함께 보고한다.
- 환자 제한을 지킨 결과 확정 수가 낮아지면 피한 검사와 방문도 함께 보고한다.
- 구조화 규칙과 합성 답을 사용한 결과는 프로그램 연결과 의사결정 규칙의 점검으로
  설명한다.
- 공개 시험의 일부 조건으로 얻은 결과를 전체 프로토콜 판단으로 넓히지 않는다.
- TrialGPT보다 전체 추천 성능이 높다는 결론은 같은 입력과 출력 정의의 직접 비교가
  있기 전에는 내리지 않는다.

## 12. 현재 진행 상태

검색부터 질문 뒤 재판정, 환자 제한 적용, 중단·재개와 보고서 생성까지 구현했다. 공개
시험 기반 전체 흐름과 기존 자료와 겹치지 않는 새 시험 최종 평가는 완료했다. 자유
문장으로 적힌 복잡한 조건의 의미 해석 평가는 후속 범위로 분리돼 있다.
