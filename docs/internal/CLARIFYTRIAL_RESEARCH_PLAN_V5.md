# ClarifyTrial 연구계획 v5

기준일: 2026-08-25

## 1. 연구 문제

임상시험 참가 조건은 구체적이지만 환자 기록에는 빠진 정보와 오래된 결과가 흔하다.
정보가 부족하다는 이유로 시험을 제외하면 참가 가능성이 있는 후보를 잃는다. 반대로
예전 결과나 확인되지 않은 기록만 보고 참가 가능으로 확정하면 현재 상태를 과하게
판단한다.

ClarifyTrial은 시험마다 다음 두 결과를 따로 낸다.

1. **후보 유지:** 참가 가능성이 남아 있어 계속 확인할 시험인가?
2. **현재 확인:** 지금 확보한 자료만으로 참가 조건 확인을 끝낼 수 있는가?

정보가 부족하면 무엇을 어떤 방법으로 확인할지도 함께 정한다.

## 2. 연구 질문

### 연구 질문 1. 정보가 부족한 시험을 안전하게 남길 수 있는가?

처음 자료만으로 조건 확인을 끝낼 수 없는 시험 가운데, 전체 환자 상태를 확인하면 실제
후보인 시험을 몇 개 보존하고 확정하는지 잰다. 동시에 가능성이 남아 보였지만 추가
정보로 제외되는 시험을 몇 개 정리하는지도 잰다.

### 연구 질문 2. 제한된 확인으로 더 많은 시험을 정리할 수 있는가?

여러 시험에 동시에 영향을 주는 정보를 먼저 확인하면 같은 확인 횟수 안에서 더 많은
시험을 확정하거나 제외할 수 있는지 본다. 입력 순서와 강한 단순 방법을 함께 비교해
복잡한 계산에 유리한 비교를 만들지 않는다.

### 연구 질문 3. 환자 선택을 지키면서 확인 방법을 고를 수 있는가?

같은 정보라도 병원 기록, 환자 답변, 기존 공식 결과와 새 검사로 확인할 수 있다. 이동,
비용, 시간과 검사 부담을 입력받아 실제 이용할 수 있는 방법을 고르고, 피한 검사·방문과
그 때문에 남은 미확정 시험을 함께 표시한다.

### 연구 질문 4. 모델을 어디에 써야 하는가?

수치·날짜·참거짓으로 구조화된 조건은 코드와 언어모델 가운데 어느 쪽이 같은 결과를 더
안정적이고 적은 비용으로 내는지 비교한다. 자유 문장으로 적힌 조건은 뜻을 구조화해야 할
때만 모델을 부르고, 실제 근거 충돌이 있을 때만 별도 검토를 부르는 구조를 확인한다.

## 3. 연구 가설

- 후보 유지와 현재 확인을 나누면 정보 부족 때문에 실제 후보를 너무 일찍 없애지 않는다.
- 후보를 넓게 남기더라도 추가 확인 뒤 제외될 시험을 정리하고 성급한 확정을 늘리지 않는다.
- 입력 순서보다 영향이 큰 정보를 먼저 확인하는 방식이 같거나 더 많은 판단을 끝낸다.
- 환자 선택을 반영하면 피하고 싶은 새 검사와 방문을 줄이되, 줄어든 후보 확정 수도 함께 드러난다.
- 완전히 구조화된 조건에서는 모델 호출을 늘리는 것보다 코드 계산이 더 효율적이다.

세 번째 가설은 현재 자료에서 강한 단순 방법과 같은 결과가 나왔다. 복잡한 질문 계산의
우월성은 현재 주장하지 않는다.

## 4. 전체 흐름

```text
환자 상태와 시험 조건 입력
→ 관련 시험 검색
→ 조건별 환자 상태와 근거 확인
→ 후보 유지와 현재 확인 완료 여부 분리
→ 부족한 정보와 영향받는 시험 연결
→ 남은 확인 횟수 안에서 다음 정보 선택
→ 환자 상황에 맞는 확인 방법 선택
→ 새 정보 반영
→ 관련 시험만 다시 판단
→ 현재 확인된 시험·추가 확인 후보·조건 불충족 시험 출력
```

기본 환자 입력은 정해진 형식의 JSON이다. 자유롭게 쓴 환자 기록을 JSON으로 바꾸는
기능은 선택적으로 연결하며 질문 순서 성능과 분리한다.

## 5. 시험별 결과

| 결과 | 뜻 |
|---|---|
| 후보 유지·현재 확인 완료 | 지금 자료로 참가 조건 확인을 끝낸 후보 |
| 후보 유지·추가 정보 필요 | 가능성은 남아 있지만 아직 확인할 정보가 있는 후보 |
| 조건 불충족 | 명확한 조건 위반이 확인된 시험 |

조건 불충족 시험은 수치나 날짜처럼 경계가 분명할 때만 기준과의 차이를 표시한다. 서로
다른 검사값의 차이를 하나의 점수로 합치지 않는다.

## 6. 확인 방법과 환자 입력

확인 방법은 다음 범주로 저장한다.

- 현재 병원 기록 확인
- 다른 병원의 기존 기록 요청
- 환자에게 질문
- 이미 받은 공식 결과 확인
- 새로운 검사 또는 평가
- 담당자의 별도 확인
- 지금 해결할 수 없어 대기

환자 상황 입력은 있을 때만 사용하며 없으면 중립적인 기본값을 쓴다. 입력 항목은 이동
가능성, 비용 부담, 기다릴 수 있는 시간, 새 검사와 추가 방문 허용 여부다. 이 값은 참가
조건을 바꾸지 않고 확인 순서와 방법만 바꾼다.

## 7. 다음 정보 선택

기본 실험은 환자마다 부족한 정보 최대 5개와 확인 기회 3회를 둔다. 프로그램은 다음
정보를 사용해 우선순위를 정한다.

1. 그 정보를 확인하면 상태가 바뀔 수 있는 시험 수
2. 연결된 미확인 조건 수
3. 남은 확인 횟수 안에서 끝낼 수 있는 시험 수
4. 환자가 이용할 수 있는 확인 방법
5. 추가 비용·방문·대기·신체 부담

질문을 고를 때 숨겨 둔 답을 보지 않는다. 답이 들어오면 관련 시험만 다시 판단하고 다음
정보의 우선순위를 새로 계산한다. 답을 얻지 못한 정보는 같은 실행에서 다시 고르지 않는다.

## 8. 연구자료

| 평가 | 자료 | 역할 |
|---|---|---|
| 대규모 관련 시험 검색 | TREC Clinical Trials 2021·2022 | BM25·MedCPT와 두 검색 결합 재현 |
| 질문 전 조건 판단 | TrialGPT 조건 1,015개 | 세 답 이름의 경계 확인 |

| 새 시험 최종 평가 | 새 공개 시험 30건·조건 116개·합성 환자 50명 | 개발·최종 분리와 모델 호출 방식 비교 |

통합 점검과 새 시험 최종 평가에 사용한 조건은 각 시험의 일부다. 나이, 단일 수치·날짜
비교, 명확한 상태와 관계가 분명한 복합 조건만 구조화한다.

## 9. 합성 환자 제작 원칙

1. 공개 시험에서 객관적으로 계산할 수 있는 조건을 고른다.
2. 조건을 만족하거나 위반하도록 환자의 전체 상태를 먼저 정한다.
3. 현재 실행 코드와 분리된 계산으로 시험별 기대 결과를 만든다.
4. 판단에 필요한 정보 일부를 가려 첫 입력을 만든다.
5. 가린 정보마다 확인 방법과 답을 별도로 저장한다.
6. 질문 뒤 답이 들어오면 어떤 시험 상태가 바뀌어야 하는지 저장한다.
7. 한 정보와 여러 정보를 가린 사례를 모두 넣는다.
8. 질문해도 답을 얻지 못하는 사례와 새 검사·방문을 원하지 않는 사례를 넣는다.
9. 전체 상태에서 참가 가능한 시험과 제외되는 시험을 모두 넣는다.
10. 나이, 임신·수유처럼 서로 연결된 사실이 모순되지 않게 만든다.
11. 개발 시험과 최종 평가 시험, 기존 평가 시험이 겹치지 않게 나눈다.

언어모델은 정해진 사실을 자연스러운 문장으로 바꿀 수 있지만 새 수치, 날짜, 검사,
치료와 생활습관을 정답에 추가할 수 없다.

## 10. 비교 방법

### 질문 순서

| 방식 | 설명 |
|---|---|
| 추가 확인 없음 | 처음 받은 자료만 사용 |
| 입력 순서 | 부족 정보 목록의 앞 항목부터 확인 |
| 현재 영향 우선 | 지금 가장 많은 미완료 시험에 연결된 정보를 확인 |
| ClarifyTrial | 남은 횟수 전체를 계산하고 환자 상황을 반영해 매번 다시 선택 |

### 모델 호출 구조

| 방식 | 설명 |
|---|---|
| 구조화 규칙만 사용 | 수치·날짜·참거짓 조건을 코드로 계산 |
| 조건 판단 모델만 사용 | 같은 조건마다 모델을 호출하되 코드 안전 규칙 유지 |
| 코드가 필요한 역할만 호출 | 코드가 순서를 통제하고 조건 판단과 질문 문장 역할만 호출 |

모든 방식은 같은 환자, 시험, 질문 기회와 숨겨 둔 답을 사용한다.

## 11. 평가 지표

### 후보와 최종 판단

- 처음 자료에서는 확정되지 않지만 전체 상태에서는 참가 가능한 시험 수
- 그중 추가 확인 후보로 보존한 수와 실제 후보로 확정한 수
- 처음에는 가능성이 남지만 전체 상태에서는 제외되는 시험 수
- 그중 질문 뒤 제외로 정리한 수와 미정으로 남은 수
- 남겨야 할 시험을 잘못 제외한 수
- 정보가 부족한데 참가 가능으로 확정한 수
- 질문 뒤 최종 상태를 맞힌 시험 수

### 질문과 환자 부담

- 확인 횟수별 실제 후보 확정과 제외 후보 정리
- 입력 순서와 강한 단순 방법 대비 환자별 승·동률·패
- 아무 시험의 판단도 바꾸지 못한 확인 수
- 답을 얻지 못한 확인과 같은 정보 반복 수
- 새 검사와 추가 방문 수
- 환자가 원하지 않은 확인 방법 선택 수
- 예상 대기, 비용과 신체 부담 범주

### 실행과 불확실성

- 환자 단위 재표집 95% 구간과 질환별 결과 범위
- 모델 역할별 외부 호출·입력 토큰·출력 토큰·전체 시간
- 모델 출력 대신 구조화 계산을 적용한 판정 단계 수
- 별도 검토 수, 실행 실패와 재개 수
- 시험 조건 저장본 재사용 수

검색, 질문 전 조건 판단, 질문 순서와 환자 부담 결과는 서로 다른 자료를 쓰므로 하나의
총점으로 합치지 않는다.

3. 완료 — 공개 시험 50건·합성 환자 50명 통합 점검 자료 제작

## 13. 결과 해석 기준

다음 내용을 한 묶음으로 보고한다.

- 정보 부족 때문에 처음에 확정되지 않은 실제 후보를 몇 개 보존하고 확정했는가
- 후보를 넓게 남긴 결과, 결국 제외될 시험을 몇 개 정리했는가
- 잘못 제외와 성급한 확정이 늘지 않았는가
- 환자 선택을 지키면서 몇 번의 검사와 방문을 피했고, 대신 몇 개의 확정이 남았는가
- 강한 단순 방법보다 실제로 좋아졌는가
- 외부 모델 호출이 최종 결과를 바꿨는가

통합 점검의 기대 결과는 프로그램과 같은 구조화 규칙으로 만들었으므로 임상 정확도로
해석하지 않는다. 새 시험 최종 평가는 별도 계산기를 사용했지만 객관적으로 구조화한 일부
조건에 한정한다. TrialGPT보다 높은 전체 추천 성능, 실제 환자의 비용·시간 개선과 자유
