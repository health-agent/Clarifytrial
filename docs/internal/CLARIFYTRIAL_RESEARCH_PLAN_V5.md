# ClarifyTrial 연구계획 v5

기준일: 2026-08-25

## 1. 연구 문제

임상시험 참가 조건은 구체적이지만 환자 기록은 자주 불완전하다. 정보가 부족하다는
이유만으로 시험을 제외하면 참가 가능성이 있는 후보를 잃는다. 반대로 오래되거나
확인되지 않은 기록만 보고 참가 조건을 충족한다고 확정하면 현재 상태를 과하게
판단한다.

ClarifyTrial은 각 시험에 다음 두 결과를 따로 낸다.

1. **후보 유지:** 참가 가능성이 남아 있어 계속 검토할 시험인가?
2. **현재 확인:** 지금 확보한 자료만으로 참가 조건을 확인할 수 있는가?

정보가 부족하면 다음에 무엇을 어떤 방법으로 확인할지도 함께 정한다.

## 2. 연구 질문

최종 평가는 `현재 확인이 끝난 시험만 보여 주는 방식`을 기준으로 삼는다. 이 방식에서는
처음 자료가 부족해 목록에서 보이지 않지만, 모든 정보를 확인하면 실제 참가 가능
후보인 시험이 몇 개인지 먼저 센다. ClarifyTrial이 그 시험을 추가 확인 후보로 남기고,
환자가 허용한 확인 뒤 실제 후보로 확정한 수와 그 과정의 질문·검사·방문을 함께 잰다.

처음에는 후보로 남았지만 모든 정보를 확인하면 제외되는 시험도 따로 센다. 따라서
후보를 많이 남기는 것만으로 좋은 결과로 보지 않는다.

### 연구 질문 1. 두 판단을 안정적으로 분리할 수 있는가?

오래된 결과, 환자 진술, 출처가 맞지 않는 기록과 확인이 끝난 최신 자료를 구분하면서
후보 유지와 현재 확인을 따로 계산한다.

### 연구 질문 2. 제한된 확인 횟수로 어떤 정보를 먼저 확인해야 하는가?

여러 시험에 동시에 영향을 주는 정보를 먼저 확인하면 같은 질문 수로 더 많은 시험의
판단을 끝낼 수 있는지 평가한다.

### 연구 질문 3. 환자 상황에 맞는 확인 방법을 고를 수 있는가?

같은 정보라도 기존 기록, 환자 답변, 공식 결과와 새 검사 중 실제로 이용할 수 있고
부담이 적은 방법을 선택하는지 평가한다.

세 질문의 역할은 다음처럼 구분한다. 중심 실험은 제한된 확인 횟수에서 질문하고 다시
판단하는 전체 흐름이다. 후보 유지와 현재 확인의 분리는 이 흐름이 후보를 과하게 버리거나
성급하게 확정하지 않게 하는 결과 형식이다. 환자 상황에 맞는 확인 방법 선택은 같은
흐름에 붙는 추가 기능으로 평가한다.

## 3. 연구 가설

- 현재 확인이 끝난 시험만 보여 주는 방식보다 참가 가능성이 남은 시험을 더 많이
  보존하고, 제한된 확인 뒤 그중 일부를 실제 후보로 확정할 수 있다.
- 추가 확인 후보를 보존하더라도 명확한 조건 위반을 놓치거나 정보가 부족한 시험을
  참가 가능으로 성급하게 확정하지 않는다.
- 후보 유지와 현재 확인을 분리하면 정보 부족 때문에 발생하는 잘못된 후보 제거를
  줄일 수 있다.
- 입력 목록 순서대로 질문하는 방식보다 여러 시험의 판단을 가장 많이 끝낼 정보를
  계산하는 방식이 같은 질문 수에서 더 많은 판단을 끝낸다.
- 이동·비용·시간 제한을 반영하면 환자가 피하고 싶은 새 검사와 추가 방문을 줄이면서
  실제로 이용 가능한 방법 안에서 더 많은 판단을 끝낼 수 있다.

## 4. 전체 흐름

```text
환자 상태와 시험 조건 입력
→ 관련 시험 검색
→ 조건별 환자 상태와 근거 확인
→ 후보 유지 여부와 현재 확인 가능 여부 분리
→ 부족한 정보와 영향받는 시험 연결
→ 남은 확인 횟수 안에서 가장 도움이 되는 정보 선택
→ 환자 상황에 맞는 확인 방법 선택
→ 새 정보 반영
→ 관련 시험만 다시 판단
→ 현재 확인된 시험과 추가 확인 후보 출력
```

기본 입력은 정해진 형식의 JSON이다. 자유롭게 작성된 환자 기록을 JSON으로 옮기는
기능은 선택적으로 연결하며 질문 정책 성능과 분리한다.

## 5. 판단과 행동

### 시험별 결과

- `retain + confirmed`: 후보로 유지하며 현재 자료로 참가 조건 확인 완료
- `retain + not_confirmed`: 후보로 유지하지만 추가 정보 필요
- `remove + ineligible`: 명확한 조건 위반으로 제외

### 확인 방법

- 현재 병원 기록 확인
- 다른 병원의 기존 기록 요청
- 환자에게 질문
- 이미 받은 공식 결과 확인
- 새로운 검사 또는 평가
- 담당 의료진의 판단
- 현재 해결할 수 없어 대기

환자 부담 입력은 확인 순서만 바꾸고 참가 조건 판단은 바꾸지 않는다.

## 6. 정보 선택 방법

환자마다 부족한 정보 5개와 최대 확인 횟수 3회를 기본 조건으로 둔다. 남은 확인 횟수
안에서 선택할 수 있는 정보 조합을 모두 계산하고, 가장 많은 시험의 판단을 끝낼 수
있는 조합을 우선한다.

동률이면 다음 순서로 고른다.

1. 영향을 받는 시험 수
2. 영향을 받는 참가 조건 수
3. 환자가 실제로 이용할 수 있는 확인 방법
4. 추가 비용·방문·대기·신체 부담

질문을 고르는 과정에서는 가려 둔 환자 답을 사용하지 않는다. 새 정보가 들어오면
영향받는 시험만 다시 판단한 뒤 다음 정보를 새로 계산한다.

## 7. 연구자료

| 평가 | 자료 | 역할 |
|---|---|---|
| 관련 시험 검색 | TREC Clinical Trials 2021·2022 | 수만 건에서 관련 시험을 후보 안에 남기는지 평가 |
| 한 번의 조건 판단 | TrialGPT 조건 1,015개 | 환자 기록과 조건 하나의 판단 평가 |
| 질문과 재판정 | 공개 시험 15건·조건 92개, 합성 환자 30명 | 제한된 질문 뒤 판단 완료 평가 |
| 환자 부담 | 합성 상황 360개 | 확인 방법 선택 평가 |
| 넓은 검색 확장 | 팀 공개 시험 1,931건 | 여러 질환의 후보 검색 |
| 성숙도 점검 | 합성 질환 10개·합성 시험 50개·합성 환자 50명 | 최종 평가 지표와 전체 실행 안정성 확인 |

현재 정밀 평가 질환은 제2형 당뇨병, 유방암, 주요우울장애다.
팀 공개 파일은 모집 상태를 검사한 뒤 현재 모집 중이거나 모집 예정인 589건만 후보
검색에 넣는다. 이 가운데 10개 질환군·50개 시험을 조건 종류가 고르게 섞이도록 고르는
절차까지 구현했으며, 50개 시험의 조건별 정답과 새 합성 환자 제작은 다음 단계다.

최종 평가 전에 별도의 성숙도 점검 자료를 만들었다. 질환 10개, 합성 시험 50개와
합성 환자 50명으로 구성되며, 환자마다 핵심 정보 한 개·두 개·세 개 또는 다섯 개를
가린다. 완전한 정보에서는 참가 가능과 제외가 모두 나오도록 만들었다. 이 자료는
프로그램을 흔들어 보기 위한 합성 시험 조건이며 최종 성능 수치에는 사용하지 않는다.

## 8. 합성 환자 제작 원칙

1. 공개 시험의 객관적으로 계산 가능한 조건을 고른다.
2. 조건을 만족하거나 위반하도록 전체 환자 상태를 먼저 정한다.
3. 전체 상태로 시험별 후보 유지와 현재 확인 결과를 계산한다.
4. 판단에 영향을 주는 정보 일부를 가려 첫 입력을 만든다.
5. 가린 정보마다 허용할 확인 방법과 답을 별도 저장한다.
6. 질문 뒤 새 답이 들어오면 시험 상태가 어떻게 바뀌는지 미리 계산한다.
7. 일부 사례에서는 질문하거나 기록을 찾아도 답을 얻지 못하게 하여, 같은 확인을
   반복하지 않고 다른 정보로 넘어가는지 검사한다.
8. 완전한 정보에서 참가 가능한 사례와 제외되는 사례를 모두 넣어, 실제 후보 회복과
   불필요한 후보 보존을 함께 측정한다.
9. 가리는 정보 수와 시험–정보 연결 구조를 여러 종류로 만들어 한 형태의 문제만
   반복하지 않는다.

언어모델은 정해진 사실을 자연스러운 문장으로 바꿀 수 있지만 새 수치, 날짜, 검사,
치료와 생활습관을 정답에 추가할 수 없다.

## 9. 비교 방식

### 질문 순서

| 방식 | 설명 |
|---|---|
| 추가 질문 없음 | 처음 받은 자료만 사용 |
| 입력 목록 순서 | 처음 부족 정보 목록의 앞 항목부터 확인 |
| 현재 영향 우선 | 현재 가장 많은 미완료 시험과 연결된 정보를 먼저 확인 |
| ClarifyTrial | 남은 횟수 안에서 가장 많은 시험 판단을 끝낼 정보를 매번 계산 |

### 확인 방법

| 방식 | 설명 |
|---|---|
| 같은 확인 순서 | 모든 환자에게 같은 비용·경로 규칙 적용 |
| 환자 상황 반영 | 이동·비용·시간·검사 부담을 반영해 실제 이용 가능한 방법 선택 |

모든 방식에는 같은 환자 정보, 후보 시험, 질문 횟수와 합성 답을 제공한다.

## 10. 평가 지표

### 중심 지표

- 현재 확인이 끝난 시험만 보여 줄 때 목록에서 보이지 않는 실제 참가 가능 후보 수
- ClarifyTrial이 추가 확인 후보로 보존한 수
- 환자가 허용한 확인 뒤 실제 참가 가능 후보로 확정한 수와 그 비율
- 처음에는 보존했지만 모든 정보를 확인하면 제외되는 시험 수
- 질문 뒤 제외로 정리한 수와 아직 미정으로 남은 수
- 질문 뒤 판단이 끝난 시험 수
- 입력 순서 방식과 비교한 환자별 승·동률·패
- 남겨야 할 시험을 잘못 제외한 수
- 정보가 부족한데 현재 확인을 끝낸 수
- 한 질문으로 판단이 끝난 시험 수
- 어떤 시험의 판단도 바꾸지 못한 질문 수
- 정보를 얻지 못한 확인 수와 같은 정보를 반복해서 확인한 수

### 환자 부담 지표

- 환자가 이용할 수 있는 방법만 사용해 판단을 끝낸 시험 비율
- 피해야 할 새 검사와 추가 방문 선택 수
- 환자 제한을 벗어난 확인 방법 수
- 확인 방법의 예상 대기시간과 부담 범주

### 실행 지표

- 모델 호출 수와 토큰
- 전체 실행 시간
- 시험 조건 저장본 재사용 수
- 실패·중단·재개 수

관련 시험 검색, 한 번의 조건 판단, 질문 정책과 환자 부담 결과는 서로 다른 자료를
사용하므로 하나의 총점으로 합치지 않는다.

## 11. 실험 순서

1. TREC 2021·2022에서 TrialGPT 검색 재현
2. TrialGPT 조건 자료에서 한 번의 조건 판단 확인
3. 공개 시험 15건·합성 환자 30명에서 네 질문 방식 비교
4. 환자 부담 상황 360개에서 확인 방법 비교
5. 팀 공개 시험 1,931건을 불러와 현재 모집 가능한 589건을 넓은 검색 자료로 연결
6. 조건 종류를 고려해 10개 질환·50개 정밀 평가 후보를 선택
7. 대체됨 — 질환 수만 늘리는 대신 10개 질환·50명의 성숙도 점검 자료에서 정보 부족
   수와 시험–정보 연결 구조를 함께 확장
8. 완료 — 질환 10개·합성 시험 50개·합성 환자 50명의 성숙도 점검 자료에서 전체
   실행과 후보 회복 지표 확인
9. 선택한 공개 시험 50건의 계산 가능한 조건을 정리하고 그 조건에 맞는 합성 환자 제작
10. 모집 가능한 589건 검색부터 질문 뒤 순위 변경까지 같은 사례로 실행
11. 최종 사용할 외부 모델로 후보 회복, 불필요한 후보 보존, 질문·검사·방문과 모델
    사용량 재계산

## 12. 결과 해석 기준

다음 결과가 함께 나올 때 질문 정책의 효용을 주장한다.

- 입력 순서 방식보다 더 많은 시험 판단을 끝낸다.
- 잘못된 후보 제거와 성급한 현재 확인이 늘지 않는다.
- 판단을 바꾸지 못한 질문이 줄어든다.
- 환자 제한이 있는 상황에서 피해야 할 새 검사와 방문이 줄어든다.

입력 목록 순서보다 높다는 결과만으로 복잡한 질문 계산법의 우월성을 주장하지 않는다.
현재 영향 우선 방식과도 비교하고, 차이가 작으면 남은 횟수 전체를 계산하는 방법은 작은
보완으로 해석한다. 질문했지만 답을 얻지 못한 상황의 결과도 정상 상황과 따로 보고한다.

현재 결과로 설명할 수 있는 범위는 공개 시험 조건과 합성 환자 안에서의 기능 성능이다.
TrialGPT보다 높은 전체 추천 성능, 의사 수준의 판단, 실제 환자의 비용·시간 개선은 아직
평가하지 않았다.

`버려질 뻔한 시험을 살렸다`는 표현은 비교 방식이 현재 확인을 끝낸 시험만 보여 주도록
미리 정해졌을 때만 사용한다. TrialGPT나 다른 시스템이 정보 부족 시험을 실제로
제외했다고 확인하지 않았다면 그 시스템이 버린 시험이라고 표현하지 않는다.

RAG, 여러 모델 역할, 질문 생성, 행동 선택과 선택적 재검토는 기존 연구에 존재하는
구성이다. ClarifyTrial의 중심은 이 기능들의 최초 제안이 아니라, 후보 유지와 현재
확인을 분리하고 제한된 질문과 환자 부담을 하나의 재판정 흐름에서 평가하는 데 있다.
