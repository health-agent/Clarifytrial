## 현재 상태 한눈에 보기

- 기본 모델 호출은 검색·판단과 다음 확인으로 나뉜다. 진행 관리는 코드가 맡으며
  비교 설정에서만 별도 모델 역할로 바꿀 수 있다.
- 시험을 제외하거나 참가 조건을 확인하는 근거가 약할 때만 별도 검토를 한 번 부른다.
- 관련 시험을 후보로 가져오는 검색 능력은 TrialGPT 논문 결과와 소수점 첫째
  자리까지 같았다. 조건 판단과 최종 추천은 이 비교에 포함하지 않았다.
- 여러 정보가 동시에 부족한 사례는 환자 답 5개를 평가용으로 숨기고 세 번만 확인하게
  만들어 검사했다. 핵심 값 5개가 입력에서 모두 빠진 조건도 따로 실행했다.
- 새 합성 환자 30명에서 정보 선택 규칙만 계산한 평가는 세 번 확인 뒤 모든 환자
  정보를 알 때와 같은 판단에 도달한 시험이 입력 목록 순서대로 확인한 경우 75.3%,
  가장 많은 시험 판단을 끝낼 정보를 계산한 경우 88.7%였다. 검색부터 재판정까지
  전체 프로그램에 연결한 평가는 추가 정보를 확인하지 않은 경우 42%, 입력 목록
  순서대로 최대 세 개를 확인한 경우 66%, 가장 많은 시험 판단을 끝낼 정보를 매번
  계산한 경우 77%였다.
- 기본 입력은 환자 상태와 시험 조건을 정해진 칸에 넣은 JSON 파일이다. 자유롭게
  작성된 기록을 JSON으로 바꾸는 기능은 선택 사항이다.
- 새 환자·시험 JSON을 받는 일반 실행 명령, 직접 답변과 중단·재개, 세 방식 일괄
  평가와 자동 보고서 생성을 포함한다. 공개 시험 15개로 전체 과정을 재생하는 고정
  화면과 질문 순서만 보는 축소 화면도 따로 남겼다.
- 현재 수치는 92개 시험 조건과 합성 환자를 사용한 예비결과다.

연구계획은 v5 문서 하나만 현행 기준으로 사용한다. `trash/`는 과거 기록이며 출처의
세부 확인이 필요할 때만 본다. 과거 Solar 합성 데모 수치와 84%는 현재 결과나
비교 기준으로 사용하지 않는다.
