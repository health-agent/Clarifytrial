# ClarifyTrial 실험자료 작업 문서

문서 목적: 실제로 사용할 데이터와 새로 만들 데이터를 결정하기 위한 공동 작업 기록

마지막 갱신: 2026-08-23

현재 공개 TrialGPT 자료로 개별 참가 조건 판단을 검사했고, TREC 2021·2022로 관련
시험 검색을 검사했다. 별도로 공개 임상시험 15건·조건 92개와 합성 환자를 만들어
질문 순서와 환자 부담에 맞는 확인 방법을 평가했다. 참가 조건 92개는 AI가 먼저
검토했으며, 아직 사람 두 명의 독립 확인을 거치지 않았다.

---

## 1. 이 문서에서 결정할 것

ClarifyTrial 실험에는 서로 다른 종류의 정답이 필요하다.

1. 많은 임상시험 중에서 관련 있는 시험을 찾았는가?
2. 환자 정보가 임상시험의 개별 조건을 만족하는가?
3. 현재 정보만으로 판단할 수 있는가, 정보가 더 필요한가?
4. 정보가 더 필요하다면 무엇을 확인해야 하는가?
5. 새 정보가 들어온 뒤 판단이 올바르게 바뀌었는가?

현재 공개된 자료 가운데 이 다섯 가지의 정답을 모두 주는 자료는 없다. 따라서 다음
두 종류를 함께 사용한다.

- 공개 데이터셋을 용도에 맞게 나누어 그대로 사용
- 공개 연구의 합성 방법을 참고해 ClarifyTrial용 흐름 자료를 새로 제작

- 공개 자료: 기존 연구와 공정하게 비교할 수 있는 정답으로 사용
- 새 합성 자료: 공개 자료에 없는 질문, 기록 확인, 별도 확인과 다시 판단하는 흐름을 평가

세부 순서는 공개 자료의 실제 입력과 라벨을 이해한 뒤 계속 조정한다.

### 전체 관계를 먼저 이해하기

전체 자료의 관계는 다음과 같다.

1. 합성 환자 자료가 있다.
2. ClinicalTrials.gov에서 가져온 많은 임상시험 자료가 따로 있다.
3. 검색 시스템이 환자와 관련 있어 보이는 시험을 고른다.
4. 사람이 선택된 환자와 시험의 조합을 검토해 정답 라벨을 붙인다.

다만 다음 두 점에 주의한다.

- 합성 환자 정보가 항상 다섯 개의 고정 항목으로 되어 있지는 않다. TREC
  2021·2022와 TrialGPT가 사용한 환자 정보는 주로 짧은 진료기록 형태의 문장이다.
- 모든 환자와 모든 임상시험의 조합을 사람이 검토한 것이 아니다. 여러 검색
  시스템이 상위에 올린 시험들을 모은 뒤, 그 일부 조합에만 사람 정답을 붙였다.
  정답이 없는 조합을 자동으로 오답이라고 취급하면 안 된다.

```text
합성 환자 자료                    임상시험 원문 모음
  예: TREC 2022 환자 50명          예: ClinicalTrials.gov 시험 375,581개
             \                         /
              \                       /
               검색 시스템이 관련 후보를 고름
                          ↓
             사람이 환자-시험 조합을 검토
                          ↓
       관련 없음 / 제외 / 참가 가능 정답 파일
```

TrialGPT와 TREC의 관계는 다음과 같다.

```text
SIGIR·TREC가 먼저 만든 자료
  ├─ 합성 환자 설명
  └─ 환자-임상시험 전체 판단
              ↓ TrialGPT가 재사용
TrialGPT 검색·조건 판단·순위 평가
              ↓ SIGIR 일부 105개 환자-시험 조합을 더 잘게 나눔
의사 세 명이 조건별 조합 1,015건을 다시 검토
```

따라서 TrialGPT는 처음부터 모든 합성 환자와 임상시험을 새로 만든 독립 데이터셋이
아니다. 기존 SIGIR와 TREC 자료를 사용해 시스템 전체를 평가했고, 별도로 SIGIR
일부에 더 자세한 조건별 의사 라벨을 추가했다.

## 2. 실험자료 하나를 볼 때 반드시 확인할 항목

여기서 `라벨`은 환자와 시험 또는 참가 조건에 붙인 정답을 뜻한다. 각 자료에 다음
항목을 기록한다.

| 확인 항목 | 쉬운 설명 |
|---|---|
| 한 행이 뜻하는 것 | 환자 한 명인지, 환자와 시험 한 쌍인지, 조건 하나인지, 대화 한 회인지 |
| 환자 정보 생성 방법 | 실제 기록을 가공했는지, 사람이 사례를 썼는지, 모델이 만들었는지 |
| 임상시험 정보 출처 | ClinicalTrials.gov 요약인지, 전체 프로토콜인지, 별도 문서인지 |
| 라벨 이름과 뜻 | `eligible`, `excluded`, `정보 부족` 등이 정확히 무엇을 뜻하는지 |
| 정답 작성자 | 의사, 의학 지식이 있는 평가자, 일반 연구자, 규칙 프로그램, 언어모델 중 누구인지 |
| 라벨 작성 과정 | 독립 검토, 다수결, 합의, 자동 계산 중 어떤 방식인지 |
| 평가용으로 숨긴 환자 답 | 질문하거나 기록을 확인했을 때 공개할 답이 미리 정해져 있는지 |
| 다음 행동 정답 | 질문, 기록 조회, 별도 확인, 보류 중 무엇을 해야 하는지 들어 있는지 |
| 시간과 자료 출처 | 검사 날짜, 검사실, 환자 진술과 의무기록의 차이가 표현되는지 |
| 개발·평가 분리 방법 | 같은 환자의 비슷한 사례가 양쪽에 섞이지 않는지 |
| 사용 조건 | 공개 여부, 내려받기 가능 여부, 이용 조건과 출처 표기 방식 |
| 알려진 한계 | 실제 환자와 다른 점, 생략된 조건, 라벨이 답하지 못하는 질문 |

## 3. 공개 데이터 목록

### 3.1 TrialGPT 개별 조건 판단 자료

공개 주소: [Hugging Face 데이터](https://huggingface.co/datasets/ncbi/TrialGPT-Criterion-Annotations)

논문: [Matching patients to clinical trials with large language models](https://www.nature.com/articles/s41467-024-53081-z)

#### 무엇이 한 건인가

환자 기록 하나와 임상시험 조건 하나의 조합이다.

#### 확인된 규모

- 조건별 조합 1,015건
- 환자 53명
- 환자와 임상시험의 조합 105개
- 서로 다른 임상시험 ID 103개

과거 감사에서 공개 자료의 행 수와 식별자 구성을 다시 확인했다. 해당 원시 감사
파일은 현재 저장소로 옮기지 않았다.

#### 환자 정보는 어떻게 만들어졌는가

1,015건은 SIGIR 환자 사례에서 가져왔다. 이 사례들은 실제 환자 EHR 원문이
아니며, 의료 사례를 바탕으로 전문가가 작성한 이상적인 환자 기록 형태다.

#### 들어 있는 주요 정보

- 환자 기록
- 임상시험 조건 원문
- TrialGPT의 설명
- TrialGPT가 고른 환자 근거 문장
- 의사가 고른 환자 근거 문장
- TrialGPT의 조건별 판정
- 전문가의 조건별 판정
- TrialGPT 설명이 맞았는지에 대한 평가

#### 조건별 라벨

선정 조건에는 다음 네 라벨을 사용한다.

| 원래 라벨 | 뜻 |
|---|---|
| `included` | 환자가 이 선정 조건을 만족함 |
| `not included` | 환자가 이 선정 조건을 만족하지 않음 |
| `not enough information` | 현재 기록으로 판단할 정보가 부족함 |
| `not applicable` | 이 환자에게 해당 조건을 적용하지 않음 |

제외 조건에는 다음 네 라벨을 사용한다.

| 원래 라벨 | 뜻 |
|---|---|
| `excluded` | 환자가 제외 조건에 걸림 |
| `not excluded` | 환자가 제외 조건에 걸리지 않음 |
| `not enough information` | 현재 기록으로 판단할 정보가 부족함 |
| `not applicable` | 이 환자에게 해당 조건을 적용하지 않음 |

전문가 라벨 1,015건의 저장소 재확인 결과는 다음과 같다.

| 전문가 라벨 | 건수 |
|---|---:|
| `included` | 150 |
| `not included` | 23 |
| `excluded` | 10 |
| `not excluded` | 484 |
| `not enough information` | 293 |
| `not applicable` | 55 |

#### 전문가 정답은 어떻게 만들어졌는가

의사 세 명이 TrialGPT의 설명, 근거 문장과 조건별 판정을 검토했다. 두 명 이상이
같은 라벨을 고르면 합의 라벨로 사용했고, 세 명의 라벨이 모두 다르면 추가
논의로 합의했다.

주의할 점: 의사들은 TrialGPT 출력도 함께 검토했다. 따라서 완전히 독립적이고
눈가림된 의사 판정이라고 설명하면 안 된다.

#### 289건과 34건의 뜻

이 숫자는 공개 데이터에 따로 붙어 있는 집단 이름이 아니다. 이전 연구계획(v3)에서
TrialGPT 판정과 전문가 판정을 다시 대조해 만든 부분집합이다.

| 구분 | 건수 | 뜻 |
|---|---:|---|
| TrialGPT가 `not enough information`이라고 판정 | 289 | TrialGPT가 판단을 보류한 조건 |
| 전문가도 `not enough information` | 255 | 실제로 전문가도 정보가 부족하다고 본 조건 |
| 전문가는 판단했지만 TrialGPT만 정보 부족 | 34 | TrialGPT가 기록 속 근거를 충분히 연결하지 못했을 가능성이 있는 조건 |

34건의 전문가 라벨 구성:

- `included` 14건
- `not included` 3건
- `not excluded` 17건
- `excluded` 0건

이 34건을 정식 실험에 사용하려면 공개 데이터 원본에서 같은 필터를 다시
실행하고, 행 번호 목록을 저장소 안에 재현 가능한 파일로 남겨야 한다. 2026-08-20
원본 1,015행을 로컬 캐시에 받아 34건을 다시 확인했다. 최종 실험에서는 무시되는
캐시가 아니라 실행 표본 목록을 별도 결과 파일에 남긴다.

#### 2026-08-20 조건 지시문 개발과 평가

- 실행 단위: 조건 한 행이 아니라 환자-시험 조합의 선정·제외 조건 묶음
- 개발: 환자 20명, 환자-시험 20조합, 조건 211개
- 평가: 개발과 겹치지 않는 환자 33명, 64조합, 조건 654개
- 개발 환자의 다른 시험 20조합은 환자 중복 자료로 따로 분리
- 공개자료 한 행은 조건 원문이 비어 있어 해당 환자-시험 조합을 모델 실험에서 제외

평가자료에서 기존 Sonnet 지시문은 52.0%, 선정 조건의 미확인과 제외 조건의 기록
부재를 다르게 처리한 지시문은 79.1%, 공개 TrialGPT 고정 출력은 88.8%였다. 새
지시문의 답 이름을 그대로 채점한 점수는 공개 TrialGPT보다 낮았다. 그러나 별도 개발
표본에서 실제 후보를 남길지 뺄지로 채점하면 207/211, 98.1%가 전문가와 같았다.
틀린 답 대부분이 `판단 가능`과 `정보 부족` 사이에 있었고, 두 답은 모두 후보 유지로
이어진다. 따라서 TrialGPT의 답 이름을 그대로 맞춰 점수만 올리는 작업은 중단했다.
답을 어떻게 묶느냐에 따라 통계가 크게 달라지기 때문이다. 98.1%는 개발 표본을
사후에 분석한 결과이며 최종 평가 수치가 아니다.

`training` 열은 평가 분할이 아니다. 공개 카드에는 뜻이 없고, 원본에서 `true`
881행은 공개 GPT 라벨과 전문가 라벨이 모두 같으며 `false` 134행은 5행만 같다.
따라서 공개 GPT 출력의 정답 여부와 거의 같은 품질 표시로만 관찰하고 평가자료
분리에 사용하지 않는다.

개발 과정, 실패한 지시문, 비용과 개발에 쓰지 않은 환자 결과는
[검증 결과](CLARIFYTRIAL_VALIDATION_RESULTS.md)에 기록했다.

#### ClarifyTrial에 바로 쓸 수 있는 부분

- 환자 기록과 조건을 읽고 조건별 상태를 판단하는 실험
- 모델이 정보 부족이라고 보류한 사례 중 전문가가 판단한 사례 분석
- 근거 문장 선택
- 단일 판단과 여러 관점 검토의 비교

#### 바로 쓸 수 없는 부분

- 무엇을 환자에게 물어야 하는지에 대한 정답
- 어떤 기존 기록을 찾아야 하는지에 대한 정답
- 검사가 필요한지에 대한 정답
- 질문에 대한 숨은 환자 답변
- 새 정보가 들어온 뒤의 다음 상태
- 검사 날짜나 검사실이 현재 선별에 충분한지에 대한 정답
- 환자 한 명의 전체 임상시험 등록 가능성

#### 현재 판정

**조건별 판단과 회색지대 분석에는 가장 중요한 공개 자료다. 전체 대화 및
행동 흐름의 정답 자료로 사용하면 안 된다.**

### 3.2 TREC Clinical Trials 2022

공개 주소: [TREC 2022 Clinical Trials Track](https://trec.nist.gov/data/trials2022.html)

설명 문서: [TREC 2022 Clinical Trials Track 개요](https://trec.nist.gov/pubs/trec31/papers/Overview_trials.pdf)

#### 무엇이 한 건인가

합성 환자 설명 하나와 임상시험 하나의 조합이다.

#### 환자 정보는 어떻게 만들어졌는가

환자 주제는 실제 입원 기록처럼 보이는 5~10문장가량의 합성 환자 설명이다.
특정 질환을 염두에 두고 작성했지만, 그 질환 이름을 별도 정답으로 참가자에게
제공하지는 않았다.

#### 라벨

| 숫자 | 원래 라벨 | 뜻 |
|---:|---|---|
| 0 | `not relevant` | 환자와 임상시험의 대상 질환이 관련 없음 |
| 1 | `excluded` | 대상 질환은 관련 있지만 제외 조건 때문에 참가할 수 없음 |
| 2 | `eligible` | 제공된 환자 설명을 기준으로 참가 조건을 만족한다고 평가 |

평가는 검색 결과를 모아 만든 후보에 대해 의사 과정 대학원생, 미국 국립의학도서관
색인 담당자와 그 밖의 생의학 분야 평가자가 수행했다.

#### 저장소에서 확인한 규모

- 환자 주제 50개
- 환자와 임상시험 판정 35,394건
- 서로 다른 임상시험 ID 26,585개
- `not relevant` 28,419건
- `excluded` 3,036건
- `eligible` 3,939건

과거 감사에서 공개 qrels의 라벨과 규모를 다시 확인했다. 해당 원시 감사 파일은
현재 저장소로 옮기지 않았다.

#### 중요한 생략

TREC 2022 판정은 검색 성능에 집중하기 위해 임상시험의 현재 모집 상태와 지역을
판정에서 제외했다. 따라서 실제 등록 가능성 정답으로 해석하면 안 된다.

#### ClarifyTrial에 바로 쓸 수 있는 부분

- 많은 임상시험 중 관련 후보를 찾는 검색 실험
- 환자별 추천 순위 비교
- `관련 없음`, `관련 있지만 제외`, `참가 가능`의 시험 단위 비교

#### 바로 쓸 수 없는 부분

- 조건 하나하나의 전문가 라벨
- `정보 부족` 라벨
- 어떤 정보를 더 확인해야 하는지
- 질문과 답변의 순서
- 새 정보 뒤 다시 판단
- 실제 모집 상태와 지역을 포함한 최종 등록 가능성

#### 현재 판정

**검색과 추천 순위에는 강한 공개 자료다. 정보 획득 흐름의 정답은 제공하지
않는다.**

### 3.3 TREC Clinical Trials 2021

현재 확인된 기본 사실:

- 합성 환자 주제 75개
- TREC 2022와 같은 세 종류의 시험 단위 라벨 사용
- ClinicalTrials.gov 임상시험 모음에서 후보를 검색하고 순위를 평가

현재 저장소에는 공식 결과 분석 자료가 있으나, 원본 환자 주제와 판정 파일을
ClarifyTrial 입력 형식으로 정리한 자료는 아직 없다.

현재 판정: **TREC 2022와 같은 검색용 후보. 원본 파일, 정확한 판정 수와 이용
조건을 다음 조사에서 확인한다.**

### 3.4 SIGIR 2016 환자-임상시험 자료

TrialGPT 1,015건의 환자 사례가 나온 원자료다.

TrialGPT 논문에서 확인되는 라벨은 다음과 같다.

| 원래 의미 | 쉬운 설명 |
|---|---|
| would not refer | 이 임상시험에 의뢰하지 않음 |

그러나 조건별 정답이나 다음 확인 행동은 아니다.

현재 판정: **후보 유지 개념을 분석할 가치가 있다. 원본 파일 구조와 TrialGPT
1,015건과의 정확한 연결을 다음 조사에서 확인한다.**

### 3.5 TrialSim-10k

논문: [TrialSim-10k](https://www.sciencedirect.com/science/article/pii/S2352648326000504)

논문 설명에서 확인된 내용:

- 프로토콜에 근거한 합성 선별 대화 9,864개
- 여러 차례 질문과 답변이 이어지는 형식
- 수치, 시간, 논리 조건의 경계 사례 포함
- 가상 환자의 말투와 불확실한 답변을 변화시킴

아직 확인하지 못한 핵심 사항:

- 실제 공개 파일을 내려받을 수 있는지
- 한 행과 한 대화의 실제 열 구조
- 최종 라벨 종류
- 매 대화 차례의 숨은 환자 상태와 정답 행동이 있는지
- 질문 순서가 유일한 정답인지, 가능한 행동 중 하나인지
- 개발 및 평가 분리가 환자·임상시험 단위로 되어 있는지
- 이용 조건

현재 판정: **우리 목적에 가장 가까울 가능성은 있지만, 공개 파일과 실제 라벨을
확인하기 전에는 사용할 수 있다고 결정하지 않는다.**

특정 임상시험 조건에 대한 참가 가능 정답이나 다음 행동 정답은 제공하지 않는다.

현재 판정: **기록 조회 흐름을 실제 시스템처럼 시험하는 데 쓸 수 있다. 임상시험

## 4. 과거 합성 자료의 처리

이전 저장소의 데모용 환자, 프로그램 구조 검사용 입력과 GPT 작성 답안은 현재
저장소로 옮기지 않았다. 공개 전문가 정답이 아니며 v5의 연구 정답이나 비교 기준으로
사용하지 않는다. 새 합성 자료는 v5의 라벨과 행동 정의를 확정한 뒤 다시 만든다.

## 5. 세 가지 데이터 구성 선택지

### 선택 1. 공개 데이터만 그대로 사용

구성:

- TrialGPT 1,015건: 조건별 판단
- TREC 2021/2022: 검색과 순위

장점:

- 이미 공개된 정답을 사용하므로 기존 연구와 비교하기 쉽다.
- TrialGPT에는 의사 세 명의 합의 라벨이 있다.
- 공개 전문가 정답을 사용하므로 연구자가 답을 임의로 정했다는 비판을 줄일 수 있다.

한계:

- 환자 질문, 기록 조회, 별도 확인과 다시 판단하는 실험을 완성할 수 없다.
- 한 시스템의 전체 흐름을 하나의 정답으로 평가하기 어렵다.

### 선택 2. ClarifyTrial용 합성 자료를 전부 새로 제작

구성:

- 공개 임상시험 프로토콜에서 규칙 추출
- 숨은 가상 환자 상태 제작
- 처음에는 일부 정보를 가림
- 질문, 기록 조회 또는 별도 확인 결과를 미리 정함
- 정보 공개 뒤 조건과 시험 상태가 바뀌도록 제작

장점:

- ClarifyTrial이 다루는 전체 흐름을 직접 평가할 수 있다.
- 어떤 정보를 가렸고 어떤 행동으로 복구되는지 완전히 통제할 수 있다.

한계:

- 같은 연구팀이 생성 규칙과 정답을 모두 만들면 순환 평가가 생길 수 있다.
- 의료 전문가가 없으면 복잡한 조건의 임상 정답을 보장하기 어렵다.
- 기존 공개 데이터와 직접 비교하기 어려워질 수 있다.

### 선택 3. 공개 자료와 새 합성 자료를 역할별로 함께 사용

구성:

1. TrialGPT로 조건별 판단과 회색지대 검토
2. TREC로 검색과 추천 순위 검토
3. 새 합성 흐름으로 질문, 기록 조회, 별도 확인과 다시 판단 검토

장점:

- 공개 전문가 라벨과 전체 흐름 평가를 둘 다 확보할 수 있다.
- 한 데이터셋에 없는 라벨을 억지로 만들어 붙이지 않는다.
- 각 결과가 무엇을 증명하는지 분명하다.

한계:

- 결과표가 둘 또는 세 부분으로 나뉜다.
- 공개 자료와 새 자료의 환자 및 임상시험 구성이 다를 수 있다.

채택한 자료 구성: **공개 자료와 새 합성 자료를 목적에 맞게 나누어 함께 사용**

## 6. 새 합성 흐름에 필요할 최소 정답

새 자료를 만들기로 결정하면 각 사례에 최소한 다음 값이 있어야 한다.

| 정답 | 뜻 |
|---|---|
| 평가용으로 숨긴 환자 답 | 질문하거나 기록을 확인하면 공개할 사실 전체 |
| 처음 제공되는 환자 정보 | 시스템이 첫 판단 때 실제로 볼 수 있는 내용 |
| 조건별 현재 상태 | 만족, 위반, 정보 부족, 적용 대상 아님 |
| 시험 전체 상태 | 후보, 제외, 추가 확인 필요 중 무엇인지 |
| 부족한 사실 | 판단을 끝내려면 어떤 정보가 필요한지 |
| 허용되는 다음 행동 | 질문, 기록 조회, 별도 확인, 보류 중 가능한 행동들 |
| 정보별 확인 방법 | 같은 정보를 내부 기록, 외부 기록, 환자 답변, 기존 결과와 새 검사 중 어디서 얻을 수 있는지 |
| 확인 방법별 추가 부담 | 대기, 방문, 비용, 신체·심리 부담, 의료 위험과 치료 방해 |
| 환자 부담 상황표 | 시간 긴급성, 이동·경제 제약, 절차 선호와 명시한 한도 |
| 환자 입력 상태 | 입력 없음, 일부 입력, 전체 입력 중 무엇인지와 기본값을 사용한 항목 |
| 사람 승인 필요 여부 | 새 검사·침습 절차·치료 변경을 자동 실행할 수 없는지 |
| 행동 결과 | 행동을 실행하면 새로 공개되는 정보 |
| 다시 판단한 결과 | 새 정보 뒤 바뀌어야 하는 조건과 시험 상태 |
| 근거 | 환자 정보와 임상시험 원문의 해당 문장 |

`다음 행동`은 하나만 정답으로 강제하지 않는다. 같은 사실을 환자 질문과 기록
조회 양쪽으로 확인할 수 있다면, 둘 다 허용하거나 어떤 방법이 우선인지 별도
규칙을 둔다.

## 7. 확정한 첫 대화형 자료

### 결정 1. 첫 실험의 최소 단위

환자 한 명, 고정 후보 시험 5개와 확인 후보 사실 5개를 한 사례로 둔다. 행동은 3회로
제한한다. 사실 수와 행동 수가 같으면 모두 확인하는 방식과 좋은 질문 선택을 구분할 수 없다. 조건 하나씩
따로 보는 실험은 이미 TrialGPT 자료로 끝냈다. 이제 여러 시험에 공통인 사실을
무엇부터 확인할지 평가하려면 환자-시험 하나가 아니라 후보 묶음이 필요하다.

### 결정 2. 새 합성 자료의 질환 범위

- 제2형 당뇨병: 검사값, 유효기간과 약물 이력
- 유방암: 병리·바이오마커 확인과 치료 이력
- 주요우울장애: 증상 기간, 공식 점수, 복약과 환자 답변 가능 정보

각 질환에서 객관적으로 확인 가능한 조건만 첫 정답에 넣는다. 진단의 미묘한 임상적
판단과 복합 중증도는 개발에 사용하지 않을 첫 평가 자료에서 제외한다.

### 결정 3. 새 합성 자료의 정답 작성 방식

시험 조건과 정해진 형식의 전체 환자 상태를 먼저 작성하고 코드로 정답을 계산한다.
언어모델은 사실을 자연스러운 환자 설명으로 바꾸는 데만 사용한다. 정답 상태에 없는
식습관, 생활 방식, 검사와 치료를 추가한 문장은 거부한다.

비전공자 두 명이 조건 원문, 환자 사실과 코드 판정을 독립 대조한다. 합의하지 못한
사례는 개발에 사용하지 않을 평가 자료에 넣지 않거나 `판단 보류`로 남긴다. 의사 합의 정답이라고 표현하지
않는다.

### 결정 4. 공개 자료를 그대로 쓸지 변형할지

공개 시험 문서와 TREC 관련 시험 검색은 그대로 사용한다. 환자 전체 상태는 새로
만든다. 한 환자마다 서로 다른 정보 조합을 가린 버전을 두 개 만들되, 이를 서로 다른
환자 두 명으로 세지 않는다.

### 결정 5. 규모와 정답 질문

- 작동 확인: 기본 환자 12명, 정보를 가린 버전 한 개씩
- 첫 비교: 기본 환자 30명, 개발용 10명·평가용 20명
- 실행 수: 기본 환자마다 정보를 가린 버전 두 개, 총 60회
- 질문 정답: 문장을 똑같이 썼는지가 아니라 어떤 정보를 어떤 방법으로 확인했는지 채점
- 여러 정답 허용: 같은 판단을 끝낼 수 있는 정보 조합을 모두 계산
- 정보별 실제 도움: 다섯 정보의 가능한 조합 32개를 비교해 각 정보가 끝낸 시험 수 계산
- 질문 순서 계산용 답 비율: 실제 평가 환자의 답과 분리해 개발 자료에서만 정함
- 답 비율 변화 검사: 개발 자료의 비율, 통과·위반 반반, 불리한 답 가정을 따로 실행
- 환자 상태 묶음: 주 실험에서는 사실별 독립 확률 대신 함께 나타날 수 있는 전체 상태를 미리 고정

12명 작동 확인은 합성 시험 조건과 반복된 의존 구조를 사용한다. 따라서 이 자료는
코드, 숨은 답 분리와 지표의 작동 확인용이며 주 성능 자료가 아니다. 30명 자료는 공개 시험
원문의 객관적 조건을 사용하고, 사실 연결 구조와 통과·위반 답을 다양하게 만든 뒤 따로
고정한다.

### 첫 공개 조건 자료 완성 상태

- ClinicalTrials.gov 공개 시험 15건: 질환별 5건
- 원문에서 옮긴 객관적 조건 80개
- 합성 환자 30명: 방법을 만드는 데 쓰는 환자 10명, 그 과정에 쓰지 않는 평가 환자 20명
- 환자마다 정보를 가린 버전 2개: 총 60회
- 질환마다 확인 가능한 정보 7개, 각 버전에는 처음 보이는 정보 2개와 숨긴 정보 5개
- 오래되거나 출처가 맞지 않는 임시 자료는 실제 숨은 답과 별도로 생성

조건 80개는 공개 원문과 자동 대조했지만 연구자가 골라 구조화했다. 의사 정답이나
독립적인 전문가 합의 자료는 아니다. 따라서 이 자료로 측정한 값은 질문 선택 정책의
학생 과제 결과이며 실제 임상시험 적합성 정확도로 쓰지 않는다.

### 결정 6. 환자의 이동·비용·시간 제한을 반영한 확인 방법 선택 자료

기존 30명의 임상값과 정보를 가린 방식은 바꾸지 않고 환자 상황과 자료 가용성만 바꾼다.

- 환자 상황 3개: 추가 부담이 낮음, 이동·비용 제약, 시간 긴급
- 자료 구조 2개: 기존 자료 중심, 새 확인 필요
- 실행 규모: 30명 × 정보를 가린 버전 2개 × 환자 상황 3개 × 자료 구조 2개 = 360개 상황
- 개발 환자 실행 120회, 개발에 사용하지 않은 환자 실행 240회

360개 상황 평가는 환자 상황에 따라 선택이 달라지는지 보는 자료다. 같은 문제가 다시
생기지 않는지 확인하는 자동 검사에는 환자 입력이 전혀 없는 사례와 일부만 입력한 사례를 둔다. 이때 답하지 않은
부담은 0으로 채우지 않고 `미확인`으로 남기며, 기본값 사용 전후의 후보·제외 결과는
같아야 한다.

비용과 부담은 실제 가격 정답이 없으면 임의의 금액을 만들지 않고 범주로 기록한다.
새 검사 결과는 합성 환경에 미리 정하지만, 정책은 행동 전 그 결과를 볼 수 없다.
실제 환자 선호 정답이라고 부르지 않고 환자 상황에 따른 정책 민감도 자료로 사용한다.

### 결정 7. 자연어 전체 평가자료

기존 공개 시험 15건·조건 80개·환자 30명은 코드와 질문 정책 개발에 이미 사용했으므로
자연어 전체 흐름의 최종 수치로 다시 사용하지 않는다. 새 자료는 다음처럼 분리한다.

- 새 공개 시험 15건: 질환별 5건, 기존 시험 ID와 중복 없음
- 원문으로 확인 가능한 객관적 조건 60개 이상
- 새 기본 환자 30명: 질환별 10명
- 같은 임상값에서 근거 상태만 바꾼 두 사례: 환자당 2회, 총 60회
- 근거 충분 사례: 최근 날짜, 허용 출처, 확인 완료
- 추가 확인 사례: 오래된 날짜, 환자 진술 또는 확인 대기

새 시험 15건에서 객관적으로 정답화할 조건이 60개보다 적으면 같은 질환 비율로 시험을
추가한다. 조건 발견률을 계산할 시험은 객관적 조건을 일부만 고르지 않고 빠짐없이
정답화한다.

GPT Pro는 정답 초안을 만들 수 있지만 사람이 원문을 확인하기 전에는 정답으로 쓰지
않는다. 두 사람이 독립 대조하고 합의하지 못한 조건은 주 평가에서 제외하거나
`uncertain`으로 남긴다. 두 번째 검토자를 확보하지 못하면 개발과 분리한 평가가 아니라 단일
검토 예비평가로 표시한다.

자연어 환자 기록은 구조화된 전체 상태에서 코드로 만든다. 문장 표현을 LLM이 다듬을
수는 있지만 상태표에 없는 수치, 날짜, 검사, 치료와 생활습관을 추가할 수 없다. 숨은
답은 별도 파일에 두고 질문이나 기록 확인 행동 전에는 실행기에 전달하지 않는다.

2026-08-22 실제 수집에서는 본 시험 15건과 예비 15건을 고정했다. 본 시험의 자동
표시 문구는 제2형 당뇨병 47개, 유방암 61개, 주요우울장애 56개로 총 164개다. 자동
규칙이 빠뜨린 객관적 조건까지 확인하도록 조건 원문 272줄을 두 검토표에 모두 넣었다.
개발 시험 중복, 원문 글자 위치 오류와 선정·제외 구역 미확인은 0건이었다. 164개와
272개 모두 두 사람 검토 뒤의 정답 조건 수가 아니다.

사람 검토 전에 GPT-5.6 Sol로 272줄의 예비 검토를 진행했다. 조건 방향까지 다시 읽은
마지막 결과에서 높은 확신 조건은 203개였지만, 복합 관계를 현재 규칙이 잘못 풀 수
있는 43줄은 사용하지 않았다. 원문 한 줄에 독립 조건 하나가 있거나 같은 수치의
하한·상한만 있는 59줄에서 62조건을 만들었다. 이 파일은 원문과 수치 검사를 통과한
AI 단독 예비 정답이며 두 사람 합의 정답이 아니다.

유방암·주요우울장애 예비 시험 10건의 조건 원문 231줄도 같은 방식으로 검토했다.
시험당 단순 조건 4줄 이상인 7건 가운데 고정된 예비 순서의 앞쪽 6건으로 부족한 본
시험을 교체했다. 새 구성은 15건·92조건이다. 이 조건에서 질환별 합성 환자 10명씩
총 30명을 만들고, 같은 임상값에 근거만 충분하거나 부족한 짝 60회를 붙였다. 두
상태의 후보 결과는 모두 같았고, 가린 답을 확인한 뒤 모든 정보를 넣어 계산한 판단과
다른 사례는 0건이었다. 이는 자료 구조
검사이며 에이전트 성능이 아니다.

첫 30명에서 질문 규칙의 약점을 확인했기 때문에 이들은 개발 자료로 전환했다. 같은
조건 생성 규칙으로 질환별 10명, 총 30명의 새 평가 환자를 추가했다. 새 환자의 부족한
근거 기록 30회는 정보 선택 방법을 정한 뒤에만 열었다. 추가 확인을 세 번 허용한 뒤
모든 환자 정보를 알 때와 같은 판단에 도달한 시험 비율은 추가 정보를 확인하지 않은
경우 42%, 처음 빠진 정보 목록 순서대로 확인한 경우 75%, 남은 세 번 안에 가장 많은
시험 판단을 끝낼 정보 조합을 매번 계산한 경우 89%였다. 정해진 문장 틀과 AI 예비 조건을 쓴
합성 결과이며 사람 합의 정답이나 임상 성능이 아니다.

값이 보이지만 확인 출처만 부족한 사례와 별도로, 같은 30명의 핵심 값 다섯 개를 처음
입력에서 모두 제거한 조건도 실행했다. 새 환자나 새 정답 파일을 만들지는 않았다.
고정된 JSON에서 해당 값을 실행할 때만 제거하고, 검증용 답은 기존 숨은 답 파일에서만
읽는다. 추가 확인을 세 번 허용한 뒤 모든 환자 정보를 알 때와 같은 판단에 도달한 시험
비율은 가장 많은 시험 판단을 끝낼 정보 조합을 매번 계산한 경우 88.7%, 입력 목록
순서대로 확인한 경우 75.3%로 기존 결과와 같았다. 이는
완전히 빈 핵심값에서도 흐름이 작동하는지 보는 구조 검사이며 자연어 이해 성능이 아니다.

## 10. 안전 범위

- 실제 환자 정보는 사용하지 않는다.
- 공개 합성 사례와 새로 만든 가상 환자만 사용한다.
- 현재 자료로 실제 임상시험 등록 가능성이나 임상 성능을 주장하지 않는다.
- 실제 환자 진료와 임상시험 등록 결정에는 의료 전문가와 공식 임상시험 담당자의
  판단이 필요하다.
