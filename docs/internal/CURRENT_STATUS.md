## 현재 모습

검색부터 질문 뒤 재판정과 결과 저장까지 한 번에 실행된다. 환자 자료가 모자란 시험은
계속 확인할 후보인지 먼저 판단한다. 확인이 필요하면 여러 시험에 쓰이는 환자 정보를
찾고, 환자에게 가능한 방법으로 답을 얻은 뒤 관련 조건만 다시 계산한다.

시험마다 다음 내용이 남는다.

- 계속 확인할 후보인지
- 현재 자료로 이번 사전 검토 범위의 조건 확인을 마쳤는지
- 판단에 쓴 환자 정보와 시험 조건
- 아직 필요한 정보와 알아볼 방법
- 답변 전후에 달라진 시험 상태
- 조건을 충족하지 못했을 때 기준에서 벗어난 수치나 시점

수치, 날짜, 예·아니오처럼 규칙이 분명한 조건은 코드가 바로 판정 결과를 만든다. 이
조건은 조건 판단 모델에 보내지 않는다. 언어모델은 자유 문장 환자 기록과 시험 원문을
구조화하고, 뜻을 코드로 정하기 어려운 조건과 근거 충돌을 검토하며, 사람이 읽을 질문과
설명을 작성한다.

## KOSMI 포스터 원고 기준

제목은 **제한된 확인 횟수와 환자 제약을 고려한 상호작용형 임상시험 사전선별:
ClarifyTrial**이다. 확인 예산, 환자에게 가능한 경로, 한 번의 판정으로 끝나지 않는
흐름을 담고 있어 유지해도 된다고 판단했다. 사용자가 최종본을 제시한 뒤 전체 내용과
제목을 검토했고, 전면 재구성할 논리 문제는 찾지 못했다. 선정 가능성을 수치로 평가하거나
학회 접수를 완료한 것은 아니다.

최종 HWP의 구성은 초록, 서론, 연구 방법(시스템 흐름·평가 설계), 연구 결과,
고찰, 결론, 참고문헌이다. 도식 1개와 주요 결과 표 1개가 있고, 이전 평가 설계표는
없다. 고찰과 결론을 합치자는 논의가 있었지만 최종본은 둘 다 유지한다. 저자는
김군협·정승진·오상준·채인영·김서환·신민영·이수지의 7명이며 참고문헌은 6개다.
키워드는 임상시험 사전선별, 순차 정보 선택, 환자 제약이다. 저자 정보는 최신 HWP를
옮긴 것으로 연구 기여나 저자 자격을 새로 판정한 결과가 아니다.

현재 원고에는 다음 세 평가가 들어 있다. 같은 표에 있어도 자료와 분모는 서로 다르다.

| 평가 | 무엇을 고정하고 무엇을 바꿨는가 | 단위와 대표 결과 |
|---|---|---|
| 공개 시험 기반 정보 선택 | 같은 환자·시험·가린 답·확인 한도에서 정보 선택 방법만 변경 | 공개 시험 15건·조건 80개, 평가 환자 20명 × 가림 설정 2개 × 시험 5건 = 200개 관측. 3회에 영향 우선 84.0%. |
| 시험-정보 연결 구조 | 시험 5건·정보 5개의 연결 모양과 답 상태를 통제, 2회·3회에서 세 방법 비교 | 9종 × 200개 = 1,800개 구조. 공통에서는 영향 우선, 연쇄에서는 조합 탐색의 이점. |
| 환자 제약 | 동일한 설정에서 모든 경로 허용과 새 검사·추가 방문 제한 비교 | 합성 환자 20명 × 가림 2개 × 자료 이용 상황 2개 = 80개 짝. 미정 평균 0.88→1.24건. |

공개 시험 기반 평가의 합성 환자는 TREC 환자를 추출한 것이 아니다. 공개 시험의 객관적
조건에 맞춰 값·날짜를 갖춘 전체 환자 상태를 새로 만들고, 같은 상태에서 일부 정보를
숨겼다. 개발 환자 10명과 평가 환자 20명을 나눴고, 프로그램이 고른 답만 공개했다.
TREC는 별도의 검색 성능 점검 자료다. 선행연구에서 얻은 문제 설정이나 설계 아이디어와
환자 데이터의 출처를 혼동하지 않는다.

### 비교 방법을 설명할 때

| 원고의 이름 | 뜻 | 코드·결과 식별자 |
|---|---|---|
| 영향 우선 | 현재 가장 많은 미정 시험에 연결된 정보를 하나씩 고른다. 같으면 조건 수와 확인 부담 등으로 정한다. | `clarifytrial_rule_v1` |
| 조합 탐색 | 남은 횟수 안에서 필요한 정보를 모두 채울 수 있는 시험이 가장 많아지는 정보 묶음을 고르고, 한 답을 받은 뒤 다시 계산한다. 숨긴 답을 미리 읽거나 확률로 예측하지 않는다. | `clarifytrial_exact_coverage_v3`, `interactive/coverage_policy.py` |
| 답 비율 기반 | 개발 환자 10명에서 얻은 답 비율을 사용해 다음 한 번의 확인 뒤 정리될 시험 수를 예상한다. 조합 탐색과 다른 방법이다. | `exact_decision_tree_expected_horizon_1_v1` |
| 120개 확인 순서 평균 | 가린 정보 5개를 나열하는 모든 순서 5!를 실행한 평균이다. 각 실행은 같은 확인 한도에서 멈추며 지금 불필요해진 정보는 건너뛴다. | `random_order_expectation` |
| 단계별 무작위 | 매 단계 현재 남은 확인 대상 중 하나를 같은 확률로 고른다. 구조 실험의 무작위 비교군이다. | `random` |

`widest_impact`라는 별도 정책은 영향 우선 기본 규칙과 같지 않다. 3회 성능도 각각
83.5%와 84.0%다. 결과 파일의 이름에 `exact`가 있어도 답 비율 기반과 조합 탐색을
같은 방법으로 설명하지 않는다.

`rescue`와 `cleanup`은 서로 다른 목적으로 질문을 따로 수행한 두 실험이 아니다.
같은 실행에서 처음 미정인 시험을 전체 정보 기준 적격·부적격으로 나눠 계산한 지표다.
적격 확인에는 여러 조건을 채워야 할 수 있고, 부적격은 한 배제 근거로 끝날 수 있다.
질문 세 번이 시험 세 건 확정을 보장하지도 않는다. 한 답이 여러 시험에 쓰일 수 있고,
한 시험이 여러 답을 요구할 수도 있다.

### 숫자를 해석할 때

- 200개 중 80개는 처음부터 기준 상태와 같았다. 초기 미정 120개는 적격 30개와
  부적격 90개였고, 3회에 13+75=88개가 정리됐다. 88/120=73.3%와
  (80+88)/200=84.0%는 분모가 다르며 서로 모순되지 않는다.
- 84.0%는 120개 순서의 평균 78.27%보다 5.73%p 높다. 120은 순서의 수이며
  표본 수가 아니다. 통계 단위는 같은 환자의 두 설정·다섯 시험을 묶은 환자 20명이다.
- 답 비율 기반 86.0%, 조합 탐색 82.5%를 누락하지 않는다. 답 비율 기반과 영향
  우선의 +2.0%p에 대한 환자 단위 95% 구간은 -2.0~+6.5%p다. 우위도 동등성도
  단정하지 않고, 기본 규칙을 쓰는 실용적인 이유를 설명한다.
- 최종 표의 공통 정보 +30.1/+19.2%p와 연쇄 정보 +3.2/+3.6%p는 각각 확인
  2회/3회, 개발 때와 비슷한 답 분포의 값이다. 두 분포를 합친 평균이나 구간이 아니다.
  [검증 결과](CLARIFYTRIAL_VALIDATION_RESULTS.md)에 분포별 대응을 기록했다.
- 검사 21→0회와 방문 56→0회는 제안 횟수이며 같은 행동에 두 항목이 함께 붙을
  수 있다. 둘을 합쳐 77회 절감이라고 말하지 않는다. 제약 실험의 요점은 입력 제한을
  지킨 것과 동시에 확인 대기가 늘어난 변화다.

### 연구·편집 방향을 결정한 맥락

사용자가 처음 짚은 기여는 단순 선택과 깊은 탐색의 비교, 제한된 질문 횟수의 가치,
변동 가능한 부적격 사유의 향후 재검토였다. 논의와 추가 측정 뒤 현재 원고의 중심은
후보를 유지하는 상호작용 흐름, 연결 구조에 따른 방법의 차이, 환자 제약과 미정 상태의
관계로 정리됐다. 모든 구조에서 단순 규칙이 최선이라는 결론은 아니다. 연쇄 구조에서
조합 탐색이 유리하다는 결과를 함께 보존한다. 연결 형태에 따라 정책을 자동 전환하는
하이브리드 시스템을 별도로 검증한 것은 아니다.

변동 가능한 부적격 사유의 재검토는 연구계획의 탐색적 확장으로 남겼다. 과거 발표의
eICU 기반 62.6→71.3%, AUROC 0.777은 현행 2쪽 원고의 주 결과가 아니며 이번 최종
검토에서 재검증하지 않았다. 그 수치를 다시 사용할 때는 해당 실험의 자료·예측 대상·
단위를 별도로 읽어야 한다. 현재 부적격을 뒤집거나 미래 참가 확률을 입증한 결과로
끌어오지 않는다.

질문 한 번만 허용한 구조 실험의 +43.28%p는 보조 분석으로 낮췄다. 코드와 원자료를
삭제한 것이 아니며, 현재 주 비교는 같은 확인 2회·3회에서 무작위·영향 우선·조합
탐색을 비교하는 것이다. 공개 시험 50건 평가의 +0.44%p, 이전 150건 평가의 95.3%,
초기 나이 가림의 +36.5%p를 현재 15건·200개 관측 원고의 수치와 섞지 않는다.

### 최종 검토 뒤 남아 있는 일

02:07 저장본에서 결론 문장과 조합 탐색 정의가 수정된 것을 확인했다. 고찰의
`차이는 2.0%p에 그쳐`, 연결 구조 표의 답 분포 설명 누락, `펼요` 오타는 남아 있다.
`정보 가림 2개`를 `정보를 가리는 두 가지 설정`으로 바꾸자는 제안은 선택 사항이다.
정확한 현재 문장과 제안은 [원고의 내부 편집 메모](CLARIFYTRIAL_KOSMI_POSTER_MANUSCRIPT.md)에
따로 적었다. 새 세션은 이 제안을 자동 적용하지 않는다.

최종 HWP의 전체 쪽수·조판·심사용 익명화·실제 제출 여부는 이번 검토에서 확인하지
않았다. 이전 PDF가 2쪽 또는 3쪽이었다는 기록으로 현재 파일의 분량을 단정하지 않는다.
사용자가 제공한 학회 안내는 2쪽 이내·초록 250단어 이내·키워드 3개이며, 실제 제출
파일은 HWP 또는 Word다. 분량을 줄일 때 연구에 필요한 정의와 고찰을 희생하는 임의의
대규모 재구성을 하지 않는다.

### 새 세션의 작업 방식

- 판단 전에 실제 최신 원고를 읽는다. 사용자 질문에 등장한 문장이 파일 어디에 있는지
  확인하고 없는 문장을 인용하지 않는다. 초록과 본문 중 어느 부분을 말하는지도 먼저
  맞춘다.
- 전체 논리와 설명성을 먼저 보고 필요한 수정만 제안한다. 평범한 한국어를 사용하며
  알아들을 수 있는 영어 용어까지 억지로 바꾸지 않는다. 깊게 검토하되 출력은 간단히 한다.
- 현재 제목·흐름·단색 그림·결과 표를 유지할 수 있다고 평가했다. 형식적인 주석이나
  새로운 지표로 원고를 다시 복잡하게 만들지 않는다. 연구의 범위는 정확히 지키되 이를
  방어적인 문장으로 매 문단 반복하지 않는다.
- 사용자는 한글 API 작업 중 복사본 생성, 창을 열고 닫는 동작, 반복 권한 요청을
  원하지 않았다. 텍스트 수정 요청이 주어져도 양식과 정렬을 임의 변경하지 않는다.
  이번에는 HWP 바이너리 추출로 읽었고 원본 HWP를 변경하지 않았다.
- 외부 Pro 검토는 새로 명시적으로 요청받을 때만 한다. 현재 요청은 연구 맥락 기록과
  새 세션 생성이며 새 실험, 발표자료 재작성, 학회 제출 요청은 아니다.
- 상세 원시 파일은 기존 결과 폴더를 이용한다. 세션마다 별도 핸드오프를 만들지 않고
  이 상태 문서와 현행 원고·설계·검증 문서의 역할을 이어간다.

## 질문 순서가 영향을 주는 구조

공개 시험 50건의 조건 202개 가운데 130개가 같은 질환의 시험 두 건 이상에서 쓰이는

조건의 수만으로 질문 순서가 도움이 된다고 단정하기 어려워 정보 연결 모양을 따로
실험했다.

9가지 연결 모양을 각각 200개씩 만든 1,800개 합성 구조에서 확인 2·3회의 세 방법을 주
비교로 두고, 확인 1회는 보조 진단으로 남겼다.

| 정보 연결 모양 | 확인 2·3회의 주 비교 | 차이 |
|---|---|---:|
| 시험 다섯 건이 한 정보에 함께 연결 | 현재 영향 우선−단계별 무작위 | +19.03~+30.09%p |
| 시험마다 필요한 정보가 서로 분리 | 세 방법 | 0.00%p |
| 이웃 시험끼리 사슬처럼 연결 | 조합 탐색−현재 영향 우선 | +3.22~+4.27%p |

한 정보가 현재 미확정 후보 여러 건을 직접 정리하는 모양에서는 현재 규칙만으로도

규칙보다 높았다. 전체 구조 평균의 조합 탐색과 현재 규칙 차이는 +1.2~+2.0%포인트였다.
기본 실행에는 현재 규칙을 두고, 조합 탐색은 연결이 복잡한 경우의 비교 대상으로
제공한다.

난수 시작값 `20260830`으로 다시 실행해 정확히 일치한 확인 1회 결과는 첫 선택의
즉각적인 효과와 재현 경로를 확인한 보조 진단으로 보존한다. +43.28%포인트를 현행 논문과
결과 요약의 핵심 수치로 사용하지 않는다.

## 환자 상황에 맞춘 확인 방법

같은 답을 주는 기존 공식 결과와 새 검사에 서로 다른 합성 대기시간과 부담을 붙였다.
부담 최소와 이동·비용 제한 설정은 기존 공식 결과를 85번 모두 골랐다. 시간 긴급
설정은 새 검사를 85번 모두 골랐다. 어떤 정보를 확인했는지와 최종 시험 상태는 40개
사례에서 바뀌지 않았다. 이 실험은 확인 방법 선택 규칙이 입력에 맞게 작동하는지 살핀
동작 점검이다.

환자가 새 검사와 추가 방문을 허용하지 않은 별도 실험에서는 새 검사 제안이 21회에서
0회, 추가 방문 제안이 56회에서 0회가 됐다. 설정 하나에 남은 확인 대기 시험은 평균
0.88건에서 1.24건으로 늘었다. 시험 다섯 건을 모두 정리한 설정도 80개 중 42개에서
32개로 줄었다. 금지한 방법을 피한 만큼 일부 시험의 결론이 늦어졌다.

합성 대기시간과 부담값은 프로그램 동작을 분명하게 보기 위해 정했다. 실제 병원 운영이나
환자 편익을 추정하는 데에는 쓰지 않는다.

## 보조 평가

TREC 2021·2022에서는 TrialGPT가 공개한 후보 검색 절차를 같은 자료에서 다시 실행했다.

문장 작성 2회에 23,707토큰을 사용했다. 최종 시험 다섯 건의 상태와 확인한 정보 순서는
같았다. 한 사례의 연결과 사용량을 확인한 결과이므로 평균 처리량이나 성능 수치로
사용하지 않는다.

## 현재 결과의 범위

현재 수치로 확인한 내용은 다음과 같다.

1. 기본 문진 뒤 남은 미확정 시험 22건 가운데 14건이 한 번의 추가 확인으로 정리됐다.
2. 별도 방향별 평가의 확인 3회에서 영향 우선은 적격 13/30건과 부적격 75/90건을
   정리했고, 가능한 정보 순서 전체 평균보다 상태 일치가 5.73%포인트 높았다.
3. 질문 순서의 효과는 여러 미확정 시험이 같은 한 정보에 직접 묶인 구조에서 컸다.
4. 사슬형 연결에서는 앞으로 확인할 정보 조합을 계산한 방법이 현재 규칙보다 높았다.
5. 환자 상황에 따라 같은 정보를 얻는 방법이 바뀌었고, 금지한 검사와 방문은 선택하지
   않았다.
6. 환자 제한을 지키면 결론을 기다리는 시험이 늘어나는 변화도 함께 기록됐다.

실제 환자의 임상시험 참가 판정 정확도, 실제 비용이나 시간 절감, TrialGPT보다 높은
전체 추천 성능은 측정하지 않았다. 질문 생성, 대화형 재판정, 여러 모델 역할, 검색과
환자 부담 반영을 각각 처음 만든 연구라는 주장도 하지 않는다.
