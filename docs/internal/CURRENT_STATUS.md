# ClarifyTrial 현재 상태

기준일: 2026-08-25

## 현재 결론

공개 임상시험 검색부터 조건 판단, 추가로 확인할 정보와 방법 선택, 답변 반영, 관련
시험 재판정, 결과 보고서 생성까지 한 프로그램으로 연결돼 있다. 정해진 형식의 환자
JSON을 넣으면 이 전체 흐름을 터미널에서 확인할 수 있다.

현재 연구의 중심은 모델 하나의 정답률 경쟁이 아니다. 정보가 부족한 시험을 바로
버리지 않으면서도 참가 가능으로 성급하게 확정하지 않고, 제한된 확인을 거쳐 다음 두
결과를 얼마나 정리했는지 측정한다.

- 전체 정보를 확인하면 참가 가능인 시험을 추가 확인 후보로 보존하고 실제 후보로 확정한 수
- 처음에는 가능성이 남았지만 추가 정보로 조건 불충족이 드러난 시험을 정리한 수

환자가 새 검사나 추가 방문을 원하지 않을 때는 그 선택을 지킨 결과와 줄어든 후보 확정
수를 함께 표시한다. 질문 수만 줄이고 환자 부담을 숨기지 않는다.

## 구현 범위

- 모집 중·모집 예정 공개 시험 589건에서 관련 시험 검색
- 구조화된 수치·날짜·참거짓 조건과 복합 조건 계산
- 후보 유지 여부와 현재 조건 확인 완료 여부를 따로 저장
- 여러 시험에 영향을 주는 미확인 정보 우선 선택
- 병원 기록, 환자 답변, 기존 공식 결과, 새 검사 가운데 가능한 확인 방법 선택
- 답을 얻지 못한 정보의 반복 방지
- 새 정보와 관련된 시험만 재판정
- 호출 수·토큰·검사·방문·대기·질문 전후 변화 기록
- 실행 중단 뒤 재개, 조건 저장본 재사용, Markdown·CSV·SVG 보고서 생성

구조화된 JSON은 코드가 먼저 계산한다. 문장의 뜻을 구조화 규칙으로 정할 수 없을 때만
조건 판단 모델을 부르고, 실제 근거 충돌이 발견될 때만 별도 검토를 부른다.

모든 환자는 합성 자료다. 생식 가능 연령을 벗어난 환자에게 임신·수유 정보를 억지로
가리지 않도록 나이와 관련 사실을 함께 생성한다. 공개 시험 50건과 새 시험 30건의 전체
참가 조건을 옮긴 것은 아니며, 객관적으로 계산할 수 있는 일부 조건만 사용했다.

## 통합 점검 결과

기존 공개 시험 기반 자료의 별도 평가 환자 30명에게 시험 5개씩 연결해 150개 판단을
만들었다. 기대 결과도 프로그램과 같은 구조화 규칙으로 만든 자료이므로 아래 수치는
임상 정확도가 아니라 전체 연결이 의도대로 작동하는지 보는 소프트웨어 점검이다.

| 다음 정보를 고른 방법 | 최종 상태 일치 | 실제 후보 확정 | 제외될 후보 정리 |
|---|---:|---:|---:|
| 추가 확인 없음 | 28/150개, 18.7% | 0/54개 | 0/68개 |
| 입력 파일에 적힌 순서 | 141/150개, 94.0% | 45/54개 | 68/68개 |
| 지금 가장 많은 시험에 연결된 정보 우선 | 143/150개, 95.3% | 47/54개 | 68/68개 |
| 남은 확인 횟수 전체를 계산 | 143/150개, 95.3% | 47/54개 | 68/68개 |

남은 횟수 전체를 계산한 방법은 입력 순서보다 환자 1명에서 좋고 29명에서 같았다. 지금
가장 많은 시험에 연결된 정보를 고르는 단순한 방법과는 30명 모두 같았다. 복잡한 질문
계산이 더 우수하다고 주장할 근거는 없다.

세 번 확인한 ClarifyTrial 결과 95.3%의 환자 단위 재표집 95% 구간은 91.3~98.7%였고,
질환별 결과는 86.7~100.0%였다. 같은 환자에게서 나온 시험 판단을 서로 독립인 것처럼
세지 않고 환자 단위로 묶어 계산했다.

## 새 시험에서 확인한 모델 호출 구조

기존 50건과 겹치지 않는 공개 시험 30건을 새로 골라 15건은 개발용, 15건은 최종
평가용으로 나눴다. 최종 평가는 합성 환자 25명과 환자–시험 판단 75개이며, 정답은 현재
판정 코드를 부르지 않는 별도 계산표에 먼저 고정했다.

| 모델을 부르는 방법 | 최종 상태 일치 | 실제 후보 확정 | 제외될 후보 정리 | 외부 호출 | 토큰 |
|---|---:|---:|---:|---:|---:|
| 구조화 규칙만 사용 | 75/75개 | 36/36개 | 23/23개 | 0회 | 0 |
| 조건 판단만 GPT-5.6 Sol `medium` 사용 | 75/75개 | 36/36개 | 23/23개 | 65회 | 1,033,320 |
| 조건 판단과 질문 문장 작성에 같은 모델 사용 | 75/75개 | 36/36개 | 23/23개 | 105회 | 1,565,829 |

세 방식에서 잘못 제외한 시험, 정보가 부족한데 확정한 시험과 실행 실패는 모두 0개였다.
조건이 이미 수치·날짜·참거짓으로 구조화된 자료에서는 모델 호출을 늘려도 결과가
나아지지 않았다. 따라서 구조화 자료의 기본 실행은 코드로 두고, 모델은 의미 해석이
필요한 입력에만 사용한다. 이 결과는 여러 에이전트가 정확도를 높였다는 증거가 아니다.

상세 수치는 [모델 호출 방식 비교](results/independent-new-trial-agent-evaluation-v1/report.md)에 있다.

## 주장 범위

- 정보가 부족한 후보를 보존하고 질문 뒤 실제 후보 확정과 제외 후보 정리를 함께 잰다.
- 환자 선택을 지킨 결과와 피한 검사·방문을 같은 표에 제시한다.
- 구조화 조건에서는 모델을 더 부르는 것이 이득이 없었다.
- TrialGPT보다 전체 추천 성능이 높다고 말하지 않는다.
- 질문 생성, 답변 반영, 여러 모델 역할과 행동 선택을 최초 기여로 말하지 않는다.
- 589건 결과를 다른 시험까지 판정한 전체 검색 성능으로 말하지 않는다.
- 외부 모델 비교의 100%는 객관적으로 구조화한 일부 조건의 합성 환자 결과이며, 실제
  임상시험 전체 조건이나 자유 문장 판단 성능으로 넓히지 않는다.

세부 수치와 실행 조건은 [검증 결과](CLARIFYTRIAL_VALIDATION_RESULTS.md), 자료 생성 규칙은
[실험자료 구성](CLARIFYTRIAL_DATASETS.md)에 있다.
