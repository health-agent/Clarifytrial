# ClarifyTrial 현재 상태

마지막 갱신: 2026-08-20

## 완료한 설계

- 연구 질문과 실험 원칙
- 에이전트 전체 워크플로우
- 워크플로우 단계별 근거문헌과 공개 코드 색인
- 공통 RAG의 자료, 검색 순서와 후처리 방법
- 공통 입력·출력, 합성 답변 환경과 평가 구분
- 모델 교체 방식과 주 비교의 기본 모델

| R10 | 중요한 결론에서만 선택적 검토 에이전트 호출 | 구조적 호출 규칙과 사례당 1회 제한 완료 |

| R12 | 구조화된 수치·기간·출처와 확인 상태를 코드로 검사 | 첫 구현 완료, 단위 변환과 자유문 추출은 미구현 |

첫 구현은 고정된 합성 시험 한 건으로 상태 흐름을 검사한다. 후보 시험 전체 검색,
외부 LLM 호출과 공개 평가자료 실행은 아직 연결하지 않았다.

## 확정한 실행 조건

- 주 비교 모델: Claude Sonnet 5, `medium` effort
- 성능 상한 확인: Claude Opus 4.8, 대표 사례
- 저비용 작동 확인: Solar Pro 4
- 주 비교 반복: 사례별 3회
- 외부 확인 행동: 최대 3회
- 고정 에이전트: 진행 관리, 검색·판정, 다음 확인 3개
- 선택적 에이전트: 근거 검토 1개, 사례당 최대 1회
- 모델 호출: 후보·조건 묶음 수에 따라 계산하고 에이전트별 실제 횟수를 기록
- 모든 구조에 같은 검색 결과, 모델과 합성 답변 환경 사용

## 다음 구현

1. 현재 한 건인 합성 흐름을 기록 조회·환자 질문·보류까지 3~5개로 확장
2. 공통 호출 계약에 외부 모델 제공자 어댑터 연결
3. 작은 BM25 결과를 검색·판정 에이전트 입력에 연결
4. TrialGPT 1,015건 조건 판단 변환기와 평가 실행
5. 단일 모델과 공개 연구 구조를 옮긴 비교 시스템
6. TREC 2021·2022 전체 검색과 MedCPT 연결

## 남은 자료 결정

- 첫 v5 합성 자료의 질환 범위와 사례 수
- 비전공자 검토로 확정할 수 있는 조건의 범위
- TrialMatchAI 공식 실행에 사용할 계산 환경

이 세 항목은 현재 첫 사례를 넓히기 전에 다음 자료 설계 단계에서 확정한다. 지금
구현한 합성 흐름과 자동 검사에는 영향을 주지 않는다.

## 실험 결과

- 구현 검사: 합성 오래된 검사 사례가 `retain/not_confirmed`에서 공식 확인 뒤
  `retain/confirmed`로 바뀌는 전체 흐름 통과
- 자동 검사: 로컬 테스트 통과. 구체적인 최신 개수는 저장소에서 `pytest -q`로 확인
- 외부 LLM을 사용한 v5 실험: 시작 전
- 조건 판단 성능: 미측정
- 후보 검색 성능: 미측정
- 대화와 다음 행동 성능: 미측정
- 과거 합성 데모 결과: v5 결과에서 제외
