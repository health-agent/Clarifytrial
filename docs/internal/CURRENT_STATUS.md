# ClarifyTrial 현재 상태

마지막 갱신: 2026-08-23

## 완료한 설계

- 연구 질문과 실험 원칙
- 모델 호출과 코드 실행의 전체 순서
- 각 실행 단계의 근거가 된 논문과 공개 코드 목록
- TrialGPT와 같은 수준을 목표로 한 관련 시험 검색 자료와 처리 순서
- 모든 역할이 함께 쓰는 입력·출력 형식과 평가용 숨은 답의 분리
- 모델 교체 방식과 주 비교의 기본 모델
- 기존 자료·새 검사와 환자별 추가 부담을 구분하는 후속 설계
- 선택 가능한 환자 부담 입력의 기본 규칙과 환자용·연구자용 결과 형식
- 팀 설명에 바로 쓰는 대표 사례, 결과 그림과 보고서·발표 문안

현행 연구계획은 [CLARIFYTRIAL_RESEARCH_PLAN_V5.md](CLARIFYTRIAL_RESEARCH_PLAN_V5.md)다.
세부 구현은
[에이전트 실행 구조](CLARIFYTRIAL_AGENT_ARCHITECTURE_REDESIGN.md)와
[관련 시험 검색·평가 구현계획](CLARIFYTRIAL_RAG_EVALUATION_IMPLEMENTATION_PLAN.md)을 따른다.

## 구현 상태

뜻이고, `보류`는 현재 핵심 기능에는 필요하지 않아 나중으로 미룬 일이다. `기각`은
실험 결과 도움이 없거나 평가가 불공정해 더 진행하지 않기로 한 일이다.

현재 기본 평가는 공개 임상시험 15건의 참가 조건 92개와 합성 환자 30명을 사용한다.
환자마다 다섯 정보의 실제 값은 정해 두고, 그 정보가 아직 확인되지 않은 상태만 따로
만들었다. 시스템은 세 번 안에 무엇을 먼저 확인할지 고른 뒤 새 정보를 반영해 관련
시험만 다시 판단한다.

새 합성 환자 30명에서 세 번 확인한 뒤 미리 계산한 최종 답과 같아진 시험은 질문하지
않은 방식 42%, 정해진 순서 75%, 현재 방식 89%였다. 참가 조건 92개는 AI가 먼저
검토한 상태이며, 사람 두 명이나 의사가 확정한 정답은 아니다. 자유롭게 작성된 기록을
JSON으로 바꾸는 기능은 별도 합성 사례에서만 작동을 확인했다.

같은 30명에서 핵심 값 다섯 개를 입력에서 모두 지운 조건도 따로 실행했다. 질문 세
번 뒤 결과는 현재 방식 88.7%, 고정 순서 75.3%로 기존 근거 부족 조건과 같았다. 현재
방식은 같은 질문 한도에서 필요했던 정보는 모두 골랐고, 88번 확인 가운데 실행 뒤
보니 결과를 더 바꾸지 않은 확인은 9번이었다. 이는 정해진 합성 답으로 실행 뒤 계산한
평가이며 실제 환자 질문 성능이 아니다.

## 확정한 실행 조건

- 주 구조 비교 모델: GPT-5.6 Sol, ChatGPT 구독 연결, `medium` effort
- 평가 조건 예비 검토: GPT-5.6 Sol `medium` 초안 뒤 애매한 줄과 채택 줄을 `max`로 재검토
- 모델 생각량 변경 확인: GPT-5.6 Sol `high`, 결과가 엇갈린 20~30조건
- 다른 회사 모델에서의 확인: Claude Sonnet 5 `medium`, 대표 사례
- 저비용 작동 확인: Solar Pro 4
- 주 비교 반복: 전체 한 번, 개발 20조합과 엇갈린 사례만 반복
- 외부 확인 행동: 주 비교 3회, 확인 횟수를 0~5회로 바꾼 결과도 계산
- 대화형 작동 확인: 기본 환자 12명, 환자당 후보 5개, 확인 후보 5개, 행동 3회
- 자연어 질문 정책: 남은 행동 횟수 안에서 끝낼 수 있는 시험 수를 모든 사실 조합으로 계산하는 v3
- 첫 비교: 기본 환자 30명, 개발 10명·평가 20명, 정보를 가린 버전 2개씩
- 질환 범위: 제2형 당뇨병, 유방암, 주요우울장애의 객관적으로 확인 가능한 조건
- 고정 에이전트: 진행 관리, 검색·판단, 다음 확인 3개
- 선택적 에이전트: 근거 검토 1개, 사례당 최대 1회
- 모델 호출: 후보·조건 묶음 수에 따라 계산하고 에이전트별 실제 횟수를 기록
- 모든 구조에 TrialGPT 공개 구조 이상으로 확인된 같은 후보 검색 결과, 모델과
  합성 답변 환경 사용

## 다음 작업

현재 범위의 학생 과제 코드, 합성 예비평가와 팀 설명 자료까지 끝났다. 기본
입력은 정해진 형식의 JSON이며, 여러 정보가 동시에 부족한 상태에서 검색, 세 번의 확인과
최종 안내까지 구현하고 평가했다. 대표 환자 한 명은 외부 모델 없이 다시 실행할 수
있고, 결과 그림과 보고서·발표 문안은
[보고서·발표 정리본](CLARIFYTRIAL_REPORT_PRESENTATION_PACKET.md)에 모았다.

다음 항목은 현재 구현을 막지 않는 후속 검증이다.

1. 외부 연구 주장에 필요할 때 92개 조건을 두 사람이 독립 검토하고 정책 평가 재실행
2. 관련 없는 임상시험 문서를 충분히 포함하고 정답 질환을 입력에 직접 쓰지 않은
   환자 설명이 준비될 때 전체 추천 평가
3. 숫자·기간 조건의 차이 설명이 의료진에게 이해되며 오해를 만들지 않는지 외부 검토

자유 형식 진료기록을 JSON으로 바꾸는 연결 기능은 이미 합성 사례에서 검사했다. 그
해석 성능은 모델에 따라 달라지는 선택 기능이며 현행 연구의 완료 조건으로 두지 않는다.

팀의 별도 구현을 복제한 직접 성능 비교와 임상시험 문서 15건만 사용한 추천 순위 평가는
현재 범위에서 진행하지 않는다. 이미 질문 없음·고정 순서·기존 v1·현재 v3를 같은
자료와 행동 한도에서 비교했고, 작은 후보군의 검색 점수는 실제 검색 능력을 보여 주지
못하기 때문이다.
