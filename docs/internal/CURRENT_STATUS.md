# ClarifyTrial 현재 상태

기준일: 2026-08-29

## 현재 결론

검색부터 최종 결과까지 한 명령으로 실행된다. 자유 문장 환자 기록에서 질환과 환자
사실을 정리하고, ClinicalTrials.gov에서 모집 가능한 시험을 찾은 뒤, 실제로 같은
질환을 다루는 시험인지 확인한다. 이어서 선정·제외 조건을 하나씩 판단하고, 부족한
정보를 어떤 방법으로 확인할지 고른다. 답이 들어오면 관련 조건만 다시 판단한다.

시험마다 다음 두 결과를 따로 낸다.

1. 더 확인할 가치가 있는 후보인가
2. 현재 자료만으로 참가 조건 확인을 끝낼 수 있는가

현재 연구의 강점은 기존 방법보다 모든 조건을 더 잘 맞힌다는 주장이 아니다. 정보가
부족한 시험을 바로 버리지 않고, 무엇을 확인해야 후보가 살아나는지 보여 주며, 질문
뒤 살아난 후보와 결국 제외된 후보를 따로 집계하는 데 있다.

## 완성된 실행 범위

- ClinicalTrials.gov의 모집 중·모집 예정 시험 검색과 응답 저장
- 검색 결과가 환자의 질환과 실제로 관련 있는지 확인하고, 무관한 시험 제거
- 선정 조건과 제외 조건의 수치·날짜·예·아니오 판단
- `모두`, `하나 이상`, `일정 개수 이상`으로 묶인 조건 계산
- 해석하지 못한 복합 조건이 있는 시험의 성급한 참가 가능 확정 차단
- 후보 유지 여부와 현재 자료의 충분성 분리
- 여러 시험에 함께 영향을 주는 정보와 확인 방법 선택
- 이동·비용·시간, 새 검사와 추가 방문 허용 여부 반영
- 첫 확인 방법이 실패했을 때 다른 정보나 방법으로 이동
- 새 정보와 연결된 조건만 다시 판단
- 중단된 실행 저장과 재개
- 제외된 시험을 다시 볼 수 있는 최소 조건 묶음과 가능한 재확인 날짜 계산
- 근거, 판단 변화, 남은 정보, 환자 부담, 모델 호출과 오류를 결과 파일과 보고서에 저장
- GitHub 자동 검사 설정 파일 준비

현재 자동 검사 348개가 통과한다.

정해진 JSON 입력의 수치와 날짜는 코드로 계산한다. 자유 문장 환자 기록, 시험 원문,
코드로 계산하기 어려운 의료 조건, 실제 근거 충돌에만 언어모델을 사용한다. 일반적인
정보 부족은 검토 모델로 다시 보내지 않고 질문 경로에서 처리한다.

## 확인된 결과

### 질문으로 후보를 되찾는 전체 흐름

개발에 사용하지 않은 합성 환자 30명과 시험 5개씩을 연결한 150개 판단에서 추가
정보를 최대 세 번 확인했다.

- 처음에는 확인이 끝나지 않았던 실제 참가 가능 후보: 54개
- 세 번 안에 참가 가능 후보로 확정: 47개
- 결국 제외돼야 할 후보를 정리: 68/68개
- 남겨야 할 시험을 잘못 제외: 0개
- 정보가 부족한데 확인이 끝났다고 표시: 0개
- 최종 상태 일치: 143/150, 95.3%

가장 많은 시험에 연결된 정보를 바로 고르는 방법과 세 번의 확인을 함께 계산하는
방법은 모두 143/150이었다. 따라서 복잡한 정보 선택 계산이 더 우수하다고 주장하지
않는다.

확인 기회가 한 번뿐일 때는 입력 순서대로 확인한 방법이 94/150, 여러 시험에 영향을
주는 정보를 먼저 확인한 방법이 115/150이었다. 한 번의 확인으로 보류 상태를 끝낸
시험도 환자당 2.20개에서 2.90개로 늘었다. 환자별 비교에서는 9명이 개선되고 21명이
같았으며 낮아진 환자는 없었다(양측 정확 부호 검정 p=0.003906). 이 차이는 정보
영향도를 보는 것의 효과이며, 복잡한 다단계 계산의 우위를 뜻하지 않는다.

### 환자 상황에 따른 확인 방법

이동·비용 제한이 있는 합성 상황에서 모든 환자에게 같은 부담표를 적용한 방법과
환자가 입력한 제한을 먼저 적용한 방법을 비교했다.

- 환자가 이용할 수 있는 방법 안에서 판단 완료: 81.0% → 88.5%, +7.5%p
- 환자 단위 95% 결과 범위: +4.25%p~+11.50%p
- 피해야 할 새 검사 제안: 19회 → 0회
- 피해야 할 추가 방문 제안: 46회 → 0회

새 검사와 추가 방문은 한 행동에 함께 붙을 수 있어 두 수를 합치지 않는다. 부담과
환자 상황은 합성 입력이므로 실제 환자 편익의 크기로 해석하지 않는다.

### 공식 환자 10명 전체 실행

공식 합성 환자 10명을 4개씩 병렬로 실행했다. 모든 질문에는 `unknown`을 입력해
검색부터 결과 저장까지의 연결과 실패 처리를 확인했다.

- ClinicalTrials.gov에서 가져온 원자료 후보: 101건
- 질환 확인 단계에서 무관하다고 제거: 7건
- 관련 있지만 상위 3개 밖이라 판정하지 않음: 69건
- 실제 조건 판정으로 넘긴 시험: 25건
- 구조화한 선정·제외 조건: 472개
- 공식 원문과 글자 위치가 맞지 않은 조건: 0개
- 복합 조건을 안전하게 확정할 수 없어 참가 가능 확정을 막은 시험: 11건
- 추가 정보 확인 시도: 27회
- 모델 호출: 97회, 1,538,814토큰

환자당 최대 3개 시험을 판정했다. S007에는 관련 모집 시험이 없었고 S009에는 1개만
남아 총 30개를 억지로 채우지 않았다. 이 실행은 프로그램 연결과 입력 보존 점검이며,
임상적 추천 정확도 평가는 아니다.

전체 실행에서 선택적 검토 모델이 7번 호출됐지만 모두 평범한 정보 부족을 다시
설명하는 데 그쳤다. 이를 확인한 뒤 정보 부족은 질문 경로로 보내고, 근거 충돌·잘못된
출처·근거 없는 확정 판단에만 검토 모델을 부르도록 규칙을 고쳤다. 위 토큰 수는 이
수정 전 실제 실행값이며, 수정 뒤 수치를 추정해 섞지 않았다.

### 구조화 조건의 최종 평가

개발에 쓰지 않은 공개 시험 15건, 합성 환자 25명, 환자와 시험의 조합 75개에서 세
실행 방식을 비교했다.

| 실행 방식 | 최종 상태 일치 | 외부 모델 호출 | 전체 토큰 |
|---|---:|---:|---:|
| 구조화 규칙만 사용 | 75/75 | 0회 | 0 |
| 조건 판단에 GPT-5.6 Sol 사용 | 75/75 | 65회 | 1,033,320 |
| 조건 판단과 질문 문장 작성에 같은 모델 사용 | 75/75 | 105회 | 1,565,829 |

객관적으로 구조화한 조건에서는 모델을 더 불러도 결과가 좋아지지 않았다. 자유 문장과
의료적 해석이 필요한 조건까지 같은 결론을 확대하지 않는다.

## 남은 범위

- R127은 코드와 무관한 공개 배포 선택이다.
- R128은 언어모델 자체의 의료 문장 해석 성능을 다루는 별도 연구다.
- R143은 현재 자료로 정당화하기 어려운 미래 예측이므로 보류 상태를 유지한다.
- R141은 코드 문제가 아니라 GitHub 로그인 권한 문제다. `workflow` 권한을 추가한 뒤
  준비된 `.github/workflows/tests.yml`을 올리면 끝난다.

세부 실행 조건과 수치는 [검증 결과](CLARIFYTRIAL_VALIDATION_RESULTS.md), 프로그램의
역할과 연결 방식은 [프로그램 설계](CLARIFYTRIAL_AGENT_ARCHITECTURE_REDESIGN.md)에서
확인할 수 있다.
