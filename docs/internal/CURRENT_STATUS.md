# ClarifyTrial 현재 상태

기준일: 2026-09-03

## 현재 모습

검색부터 질문 뒤 재판정과 결과 저장까지 한 번에 실행된다. 환자 자료가 모자란 시험은
계속 확인할 후보인지 먼저 판단한다. 확인이 필요하면 여러 시험에 쓰이는 환자 정보를
찾고, 환자에게 가능한 방법으로 답을 얻은 뒤 관련 조건만 다시 계산한다.

시험마다 다음 내용이 남는다.

- 계속 확인할 후보인지
- 현재 자료로 이번 사전 검토 범위의 조건 확인을 마쳤는지
- 판단에 쓴 환자 정보와 시험 조건
- 아직 필요한 정보와 알아볼 방법
- 답변 전후에 달라진 시험 상태
- 조건을 충족하지 못했을 때 기준에서 벗어난 수치나 시점

수치, 날짜, 예·아니오처럼 규칙이 분명한 조건은 코드가 바로 판정 결과를 만든다. 이
조건은 조건 판단 모델에 보내지 않는다. 언어모델은 자유 문장 환자 기록과 시험 원문을
구조화하고, 뜻을 코드로 정하기 어려운 조건과 근거 충돌을 검토하며, 사람이 읽을 질문과
설명을 작성한다.

## 구현된 범위

- ClinicalTrials.gov의 모집 중·모집 예정 시험 검색
- 검색 결과와 환자 질환의 관련성 확인
- 선정·제외 조건의 수치, 날짜, 예·아니오와 논리 묶음을 모델 호출 없이 계산
- 후보 유지 여부와 현재 확인 상태의 분리
- 여러 시험에 쓰이는 환자 정보의 공동 사용
- 기존 기록, 환자 답변, 외부 결과 조회, 새 검사와 의료진 확인의 구분
- 새 검사와 추가 방문 허용 여부, 시간·이동·비용 부담 반영
- 확인에서 답을 얻지 못했을 때 같은 실행에서 그 정보를 반복하지 않고 다른 정보 선택
- 새 답과 연결된 조건만 다시 계산
- 실행 중간 저장과 재개
- 모델 호출이나 응답 형식 오류가 났을 때 오류 파일과 그때까지의 실행 기록 저장
- 같은 출력 폴더를 다시 쓸 때 지난 성공 결과와 이번 실패 기록의 혼동 방지
- 제외된 시험의 수치 차이와 가능한 재확인 시점 표시
- 근거, 판단 변화, 남은 정보, 확인 방법과 모델 사용량 저장
- 연구 결과표와 발표용 그림 생성
- Python 3.12 고정 환경에서 설치, 검사와 핵심 결과 대조를 실행하는 재현 명령
- ClinicalTrials.gov 공개 원문 15건의 고정 사본과 파일·참가 조건 해시 확인
- source checkout과 wheel 설치 양쪽에서 같은 프롬프트와 CLI 사용
- 상태 읽기부터 반복·종료 판단까지 단계별로 재생하는 16:9 합성 데모와 마지막 장면 PNG 생성
- KOSMI 2쪽 원고용 상호작용 흐름 단색 SVG·PNG와 재생성 스크립트
- 동료의 36장 자료를 검토한 이전 17+13 재배치안, 말하기 대본과 화면별 수정 참고표 보존

기준 화면은 동료가 갱신한 [Google Slides 36장](https://docs.google.com/presentation/d/1h31cn4EuP3Rr9zdDGe6zM1jiZRmhIlDIEh1ccOyaB8o/edit)이다.
[발표 구성과 말하기 대본](CLARIFYTRIAL_REPORT_PRESENTATION_PACKET.md)에 적힌 본편 17장과
부록 13장 재배치안은 이전 참고안이며, 현재 슬라이드 전체에 적용하는 지시가 아니다.
현재 적용할 변경은 기존 흐름을 유지하면서 13번 슬라이드를 시스템 설계의 마지막 데모로
바꾸는 것이다. Google Slides 파일은 직접 수정하지 않는다.

준비된 예제는 `clarifytrial run-full-ui --auto`로 실행한다. 터미널에서 직접 답하려면
`--auto`를 뺀다.

발표용 대화형 데모는 기존 합성 실행 결과를 읽어 만든다. 두 시험이 같은 최근 HbA1c
결과를 기다리는 상태와 새 검사·추가 방문을 원하지 않는 환자 제한을 읽고, 기존 공식
결과와 새 검사를 비교해 환자 제한에 맞는 방법을 고른 뒤, 확인 도구가 돌려준 근거로
관련 조건 두 개와 공유 상태를 갱신한다. 미확정이 남으면 새 상태에서 다음 행동을 다시
고르고, 이번 사례처럼 모두 정리되면 끝내는 순환을
보여 준다. 자동 재생, 단계별 이동과 전체 화면을 지원하며 외부 자료를 불러오지 않는다.
HTML과 마지막 장면 PNG는
`docs/internal/demo/`에 있다. Google Slides 파일은 직접 수정하지 않았다.

2026년 9월 2일 Python 3.12 고정 환경에서 전체 자동 검사 397개가 통과했다. 별도
wheel 환경에서도 프롬프트 읽기, CLI 실행과 의존성 검사가 통과했다. 대량 구조 계산을
제외한 패키지 재현 경로에서 발표 근거 CSV 20개가 커밋된 파일과 정확히 일치했다.

## 공개 시험 평가

공개 임상시험 50건에서 조건 202개를 구조화했다. 10개 질환의 합성 환자 50명 가운데
20명은 자료와 규칙을 조정하는 데 썼고 30명은 최종 평가에 남겼다. 환자 한 명에게 같은
질환의 시험 다섯 건을 연결했다.

최종 평가에는 나이, 임신·수유 여부, 활동성 중증 감염을 처음부터 넣었다. 자유 문장으로
남아 있던 나이 조건도 같은 정보로 묶어, 이미 아는 나이를 다시 묻던 다섯 사례를
없앴다. 다시 만든 자료에서는 나이 중복 질문이 나오지 않았다.

환자-시험 조합 150개 가운데 28개는 처음 환자 자료만으로 이미 상태가 정리돼 있었다. 세 기본 정보를
더하자 명확히 제외되는 68건과 참가 가능 후보 32건이 추가로 정리됐다. 질문 전까지
128개의 상태가 정해졌고, 남은 22개가 추가 정보를 기다렸다. 아래 결과는 이 22개에서
생긴 변화다.

환자마다 한 번까지 확인했으며 실제 질문은 14번 나왔다. 질문을 받은 환자 14명 모두
시험을 한 건 이상 정리했고, 14개 시험이 확인 완료로 바뀌었다. 시작 당시 미확정 시험의 63.6%가 정리돼
8개가 확인 대기로 남았다. 이 미정 22건은 전체 정보 기준 적격 사례에만 해당하므로,
조건 불충족으로 정리되는 방향은 아래 별도 평가에서 측정했다.

확인 한도를 0회부터 5회까지 늘리면 전체 정보 기준 상태와 일치한 조합은
128→142→147→149→150→150/150으로 늘었다.

가능한 질문 순서를 모두 실행한 평균과 현재 규칙의 시험 상태 일치율은 각각 94.22%와
94.67%였다. 현재 규칙으로 좋아진 환자는 1명, 같은 환자는 29명이었다. 기본 문진을
받은 뒤에는 어느 정보부터 묻느냐에 따른 차이가 거의 없었다.

초기 실험에서는 기본 문진 정보도 가렸다. 그 설정에서 현재 규칙과 가능한 순서 평균의
차이가 36.5%포인트였지만, 30명 가운데 29명이 첫 질문으로 나이를 받았다. 나이만 먼저
주자 차이는 3.44%포인트로 줄었고, 나이·임신·감염을 모두 주자 0.44%포인트가 됐다.
36.5%포인트는 자료 구성의 영향을 확인한 민감도 결과로만 남긴다.

## 적격·부적격 방향별 보완 평가

2형 당뇨병, 유방암과 주요우울장애의 공개 시험 15건과 구조화 조건 80개를 사용했다.
자료 제작·조정 합성 환자 10명과 분리한 초기 독립 환자 20명에게 두 가지 정보 가림과
시험 다섯 건을 적용했다. 펼쳐진 환자-시험 관측은 200개지만 통계 단위는 환자 20명이다.

처음부터 전체 정보 기준 상태와 같았던 관측은 80개였다. 미정 120개는 전체 정보 기준
적격 30개와 부적격 90개였다. 영향 우선 규칙은 확인 1·2·3회에 적격 0·3·13/30건,
부적격 39·57·75/90건을 정리했고, 전체 상태 일치율은 59.5%, 70.0%, 84.0%였다.

주 평가 한도 3회에서 가능한 120개 정보 순서 전체 평균은 78.27%, 영향 우선은 84.00%,
정확 탐색은 82.50%였다. 영향 우선과 순서 평균의 차이는 +5.73%포인트였고 환자 단위
95% 범위는 +3.04~+8.55%포인트였다. 정확 탐색과 영향 우선의 차이는
-1.50%포인트(95% 범위 -4.00~+1.00%포인트)로, 이 자료에서는 복잡한 계산의 추가
이점을 확인하지 못했다. 확인 1회와 2회의 영향 우선 차이는 95% 범위가 0을 포함했다.
세 확인 한도에서 안전성 오류는 없었다.

## 질문 순서가 영향을 주는 구조

공개 시험 50건의 조건 202개 가운데 130개가 같은 질환의 시험 두 건 이상에서 쓰이는
정보와 연결됐다. 그중 126개는 나이, 임신·수유 여부, 활동성 중증 감염이었다. 공통
조건의 수만으로 질문 순서가 도움이 된다고 단정하기 어려워 정보 연결 모양을 따로
실험했다.

9가지 연결 모양을 각각 200개씩 만든 1,800개 합성 구조에서 한 번만 확인했다.

| 정보 연결 모양 | 현재 규칙과 단계마다 남은 정보 중 하나를 고르는 무작위 선택의 차이 |
|---|---:|
| 시험 다섯 건이 한 정보에 함께 연결 | +43.28%p |
| 시험마다 필요한 정보가 서로 분리 | 0.00%p |
| 이웃 시험끼리 사슬처럼 연결 | -0.75%p |

한 정보가 현재 미확정 후보 여러 건을 직접 정리하는 모양에서는 질문 순서가 크게
작용했다. 정보가 분리되면 차이가 사라졌고, 사슬형 연결에서는 확인 한 번의 현재 규칙이
낮았다. 확인을 두세 번 허용하고 앞으로 확인할 정보 조합을 계산한 방법은 현재 규칙보다
전체 구조 평균 +1.2~+2.0%포인트, 사슬형 구조 +3.2~+4.3%포인트 높았다. 현재 규칙은
모든 자료에서 우수한 방법으로 제시하지 않는다. 기본 실행에는 현재 규칙을 두고, 앞으로
확인할 정보 조합을 계산하는 방법은 연결이 복잡한 경우의 비교 대상으로 제공한다.

난수 시작값 `20260830`으로 확인 1회 구조 실험 1,800개를 새 폴더에서 다시 실행했다.
선택 방법별 결과와 연결 모양별 결과가 기존 발표 근거와 모두 일치했다. 실행 안내서에는
구조 생성과 무작위 선택에 쓴 두 난수값을 명시했다.

## 환자 상황에 맞춘 확인 방법

같은 답을 주는 기존 공식 결과와 새 검사에 서로 다른 합성 대기시간과 부담을 붙였다.
부담 최소와 이동·비용 제한 설정은 기존 공식 결과를 85번 모두 골랐다. 시간 긴급
설정은 새 검사를 85번 모두 골랐다. 어떤 정보를 확인했는지와 최종 시험 상태는 40개
사례에서 바뀌지 않았다. 이 실험은 확인 방법 선택 규칙이 입력에 맞게 작동하는지 살핀
동작 점검이다.

환자가 새 검사와 추가 방문을 허용하지 않은 별도 실험에서는 새 검사 제안이 21회에서
0회, 추가 방문 제안이 56회에서 0회가 됐다. 설정 하나에 남은 확인 대기 시험은 평균
0.88건에서 1.24건으로 늘었다. 시험 다섯 건을 모두 정리한 설정도 80개 중 42개에서
32개로 줄었다. 금지한 방법을 피한 만큼 일부 시험의 결론이 늦어졌다.

합성 대기시간과 부담값은 프로그램 동작을 분명하게 보기 위해 정했다. 실제 병원 운영이나
환자 편익을 추정하는 데에는 쓰지 않는다.

TREC 2021·2022에서는 TrialGPT가 공개한 후보 검색 절차를 같은 자료에서 다시 실행했다.
TrialGPT 조건 자료 1,015쌍은 질문 전에 조건 하나를 판단하는 보조 비교에 썼다. 두
자료에는 다음 질문, 답변 뒤 여러 시험의 상태 변화와 종료 시점에 대한 정답이 없다.

공식 대회 합성 환자 10명으로 검색부터 저장까지 이어지는지도 확인했다. 개발과 겹치지
않는 공개 시험 15건에서는 구조화 조건을 코드만으로 계산한 결과와 언어모델을 추가한
결과가 같았다. 이 두 실행은 프로그램 연결과 역할 분담을 확인한 기록이다.

전체 화면 흐름의 합성 환자 한 명에서도 같은 프롬프트로 역할 배치를 다시 점검했다. 구조화 조건까지
모델에 보내던 실행은 조건 판단 3회와 질문 문장 작성 2회로 72,659토큰을 사용했다.
구조화 조건을 코드에서 바로 끝내도록 바꾼 실행은 조건 판단 호출이 0회가 됐고, 질문
문장 작성 2회에 23,707토큰을 사용했다. 최종 시험 다섯 건의 상태와 확인한 정보 순서는
같았다. 한 사례의 연결과 사용량을 확인한 결과이므로 평균 처리량이나 성능 수치로
사용하지 않는다.

## 현재 결과의 범위

현재 수치로 확인한 내용은 다음과 같다.

1. 기본 문진 뒤 남은 미확정 시험 22건 가운데 14건이 한 번의 추가 확인으로 정리됐다.
2. 별도 방향별 평가의 확인 3회에서 영향 우선은 적격 13/30건과 부적격 75/90건을
   정리했고, 가능한 정보 순서 전체 평균보다 상태 일치가 5.73%포인트 높았다.
3. 질문 순서의 효과는 여러 미확정 시험이 같은 한 정보에 직접 묶인 구조에서 컸다.
4. 사슬형 연결에서는 앞으로 확인할 정보 조합을 계산한 방법이 현재 규칙보다 높았다.
5. 환자 상황에 따라 같은 정보를 얻는 방법이 바뀌었고, 금지한 검사와 방문은 선택하지
   않았다.
6. 환자 제한을 지키면 결론을 기다리는 시험이 늘어나는 변화도 함께 기록됐다.

실제 환자의 임상시험 참가 판정 정확도, 실제 비용이나 시간 절감, TrialGPT보다 높은
전체 추천 성능은 측정하지 않았다. 질문 생성, 대화형 재판정, 여러 모델 역할, 검색과
환자 부담 반영을 각각 처음 만든 연구라는 주장도 하지 않는다.
