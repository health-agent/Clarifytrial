# ClarifyTrial 현재 상태

기준일: 2026-08-29

## 현재 결론

검색, 조건 판단, 부족 정보 선택, 질문과 답변, 관련 조건 재판정, 환자 부담 반영,
결과 저장과 보고서 생성이 하나의 실행 흐름으로 연결돼 있다. 정해진 형식의 JSON
입력에서는 외부 언어모델 없이 실행할 수 있고, 자유 문장이나 코드로 계산할 수 없는
조건에만 언어모델 역할을 선택적으로 붙일 수 있다.

공식 대회 형식의 자유 문장 환자는 별도 시험 파일 없이 실행할 수 있다. 기본 검색은
ClinicalTrials.gov 공식 API에서 현재 모집 가능한 시험을 가져오며, 검색 결과가 없을
때는 무관한 시험을 채우지 않고 별도 결과로 저장한다. 환자별 이동·비용·새 검사 제한은
원본 환자 파일과 분리된 선택 설정으로 받는다.

현재 가장 분명한 성과는 질문 알고리즘의 우월성이 아니다. 정보가 부족한 시험을
바로 버리지 않고 추가 확인 후보로 보존하면서, 질문 뒤 실제 참가 가능 후보와 결국
제외될 후보를 따로 집계하는 프로그램과 평가 방식을 완성한 것이다.

## 작동하는 범위

- ClinicalTrials.gov 공식 API의 모집 가능 시험 검색과 검색 응답 재사용
- 고정 로컬 자료와 TrialGPT 검색 재현을 위한 교체형 검색기
- 선정 조건과 제외 조건의 수치·날짜·예·아니오 판단
- `모두`, `하나 이상`, `일정 개수 이상`으로 묶인 조건 계산
- 시험마다 후보 유지 여부와 현재 자료의 충분성을 따로 계산
- 여러 시험에 필요한 정보와 확인 방법 선택
- 이동·비용·시간 제한, 새 검사와 추가 방문 허용 여부 반영
- 답을 얻지 못했을 때 같은 질문을 반복하지 않고 다른 정보로 이동
- 새 정보와 연결된 조건만 다시 판단
- 중단된 실행 저장과 재개
- 질문 전후 변화, 근거, 남은 정보, 모델 사용량과 환자 부담을 보고서로 생성
- 시험 제목, 현재 확인이 끝난 목록, 추가 확인 후보, 제외 근거와 기준 차이를 한 화면에 표시

## 현재 평가자료

| 자료 | 범위 | 확인한 부분 |
|---|---:|---|
| 공개 시험 기반 전체 흐름 자료 | 10개 질환, 시험 50건, 조건 202개, 합성 환자 50명 | 검색부터 질문 뒤 재판정까지 프로그램 연결 |

| 환자 부담 합성 상황 | 360개 상황, 1,800회 실행 | 이동·비용·시간과 새 검사 제한 적용 |

모든 환자 사례는 합성이다. 공개 시험 조건도 전체 원문이 아니라 객관적으로 계산할 수
있는 일부만 구조화했다.

## 확인된 결과

### 공개 시험 기반 전체 흐름

개발에 사용하지 않은 합성 환자 30명과 시험 5개씩을 연결한 150개 판단에서, 추가
정보를 최대 세 번 확인한 결과는 다음과 같다.

- 현재 가장 많은 시험에 연결된 정보를 먼저 확인: 143/150, 95.3%
- 남은 세 번을 함께 계산해 정보 조합을 선택: 143/150, 95.3%
- 처음에는 보이지 않을 실제 참가 가능 후보 54개를 모두 추가 확인 후보로 보존
- 세 번 안에 실제 후보 47/54개를 확정
- 결국 제외될 후보 68/68개를 질문 뒤 정리
- 남겨야 할 시험을 잘못 제외한 사례 0개
- 정보가 부족한데 현재 확인이 끝났다고 표시한 사례 0개

복잡한 정보 조합 계산과 강한 단순 방법의 결과가 같았다. 따라서 복잡한 계산은 지원
기능으로 남기되 더 높은 정확도의 근거로 사용하지 않는다.

### 새 시험 최종 평가

개발에 쓰지 않은 공개 시험 15건, 합성 환자 25명, 환자와 시험의 조합 75개에서 세
실행 방식을 비교했다.

| 실행 방식 | 최종 상태 일치 | 외부 모델 호출 | 전체 토큰 |
|---|---:|---:|---:|
| 구조화 규칙만 사용 | 75/75 | 0회 | 0 |
| 조건 판단에 GPT-5.6 Sol 사용 | 75/75 | 65회 | 1,033,320 |
| 조건 판단과 질문 문장 작성에 같은 모델 사용 | 75/75 | 105회 | 1,565,829 |

객관적으로 구조화한 조건에서는 모델 호출이 결과를 개선하지 않았다. 이 때문에
구조화 JSON의 기본 실행은 코드만 사용한다. 이 표는 자유 문장 조건이나 임상적 해석이
필요한 조건에서 여러 모델 역할이 쓸모없다는 뜻은 아니다.

### 검색과 질문 전 조건 판단

- TREC 공개자료에서 전문가가 관련 있다고 표시한 시험을 상위 500개 안에 남긴 비율은
  2021년 83.59%, 2022년 81.55%였다. TrialGPT 공개 검색 결과와의 차이는 두 해 모두
  0.1퍼센트포인트보다 작았다.
- TrialGPT 공개 조건 자료의 개발에 사용하지 않은 654개 조건에서 ClarifyTrial의 답
  이름 일치율은 79.1%, 공개 TrialGPT 출력은 88.8%였다. 차이의 대부분은
  `판단 가능`과 `정보 부족`의 경계였다. 두 답이 모두 후보 유지로 이어지는 경우가
  많았지만 전체 조건 판단 성능이 TrialGPT와 같다고 표현하지 않는다.

모든 세부 수치와 해석 범위는 [검증 결과](CLARIFYTRIAL_VALIDATION_RESULTS.md)에 있다.

## 구현 대기 계획

아래 작업은 아직 코드에 반영하지 않았다. 발표 전에 필요한 보강과 이후 확장 기능을
섞지 않도록 순서를 고정했다.

### 1. 평가 숫자의 기준 고정

`질문으로 살릴 수 있었던 후보`와 `질문 뒤 제외해야 했던 후보`는 프로그램의 첫 예측으로
정하지 않는다. 합성 환자의 질문 전 정답과 모든 답이 공개된 뒤의 정답을 비교해 평가
대상을 먼저 고정한 뒤, 각 질문 방법이 그중 몇 건을 처리했는지 센다. 모델이 처음부터
틀린 정도가 질문 방법의 분모를 바꾸지 않게 하기 위한 수정이다.

기존의 `연결된 시험이 가장 적은 정보를 얻지 못함` 상황은 쉬운 오류 처리 점검으로
남긴다. 강건성 평가는 각 방법이 실제로 첫 번째로 고른 정보를 얻지 못하게 한 뒤, 같은
질문을 반복하지 않고 다음으로 중요한 정보로 넘어가는지를 별도로 센다.

### 2. 자유 문장 조건의 안전한 처리

ClinicalTrials.gov 원문의 `선정 조건`과 `제외 조건` 구역을 먼저 보존한다. `모두`,
`하나 이상`, 조건부 문장과 예외를 현재 구조로 표현하지 못하면 여러 조건을 단순히
나열해 확정 판정하지 않고 `해석되지 않은 조건`으로 남긴다.

먼저 이런 문장 30~50개를 골라 어떤 형태가 반복되는지 확인한다. 반복되는 형태만
구조화 규칙으로 추가하고, 모든 자유 문장을 처리하는 범용 문법 해석기는 만들지 않는다.

### 3. 공식 환자 입력의 전체 실행

공식 환자 10명을 다음 순서 전체에 통과시킨다.

1. 공식 API에서 모집 가능한 시험 검색
2. 시험 조건 원문 정리
3. 조건별 판단과 추가 정보 선택
4. 질문 또는 확인 결과 반영
5. 최종 목록과 보고서 저장

환자마다 검색 상위 3개 시험, 총 30쌍은 검색된 이유와 선정·제외 조건 구성이 원문과
맞는지 확인한다. 이 점검은 프로그램 연결과 입력 품질을 보는 것이며 임상적 참가
정확도 수치로 사용하지 않는다.

### 4. 참가 조건에 걸린 시험의 재검토 경로

현재 화면은 어떤 조건에 걸렸고 기준에서 얼마만큼 벗어났는지를 보여 준다. 다음
확장에서는 다음 두 계산을 추가한다.

#### 4.1 달라져야 할 최소 조건 묶음

현재 화면은 걸린 조건을 각각 보여 주지만, 여러 참가 경로 중 어느 경로가 가장 적은
변화로 열리는지는 계산하지 않는다.

예를 들어 참가 조건이 `(혈액검사 A와 B) 또는 검사 C`이고 세 조건에 모두 걸렸다면,
새 계산은 `A와 B가 함께 달라지는 경로`와 `C 하나가 달라지는 경로`를 구분한다. 기존
조건 판정은 그대로 두고, `C 하나가 달라지면 다시 검토할 수 있음`을 별도 결과로 붙인다.

#### 4.2 다시 확인할 날짜

현재 화면은 대기기간이 얼마나 부족한지 보여 줄 수 있지만 달력 날짜까지 만들지는
않는다. 기준이 가리키는 사건과 날짜가 기록에서 확인된 경우에만 날짜를 계산한다.

예를 들어 `항암치료 후 28일 경과`가 필요하고 마지막 치료가 20일 전이라면,
`새 항암치료가 없다는 조건에서 8일 뒤 다시 확인`으로 표시한다. 사건 날짜가 없거나
어떤 치료를 가리키는지 불분명하면 날짜를 만들지 않는다.

두 계산 모두 기존 `참가 조건 불충족` 판정을 바꾸지 않는다. 수치가 좋아질 확률처럼
현재 자료로 뒷받침되지 않는 예측도 만들지 않는다.

### 5. 자동 검사

Windows와 Linux 경로에 의존하지 않는 현재 자동 검사를 GitHub Actions에서 실행한다.
먼저 Python 3.12 한 버전으로 시작하고, 설치·307개 검사·주요 명령 도움말 확인까지만
넣는다. 연구 원자료나 외부 모델 호출은 자동 검사에 포함하지 않는다.

## Dynamic Trial Eligibility 코드 검토

검토 기준은 공개 저장소
[sjo5088/dynamic-trial-eligibility의 2efbb98 커밋](https://github.com/sjo5088/dynamic-trial-eligibility/tree/2efbb98d3478dc5747192b8d6012789a6f74cac0)이다.
이 코드는 임상시험 검색과 질문 흐름 전체를 대체하지 않는다. 현재 `참가 조건 불충족`인
시험 가운데 다시 볼 가치가 있는 시험을 찾는 별도 계산을 제공한다.

### 확인한 동작

- 숫자 조건의 선정·제외 방향을 하나의 참가 가능 구간으로 바꾸는 검사 통과
- 시간 경과 조건의 날짜 계산과 역행 방지 검사 통과
- 미래 확률의 분류와 같은 확률의 공동 순위 처리 검사 통과
- `참가 가능 상태가 되려면 최소 몇 조건이 달라져야 하는가` 계산을 ClarifyTrial의
  현재 조건 논리와 결합한 임시 환경에서 모든 제공 사례 통과
- 적격성 달력의 결정론 검사 16개와 무작위 입력 20,000개 검사 통과

제공된 검사는 각각 독립 실행하면 통과한다. 다만 일반적인 `pytest` 명령에서는 검사
파일이 불러와지는 도중 프로그램을 종료해 전체 검사가 시작되지 않는다. 설치용
`pyproject.toml`과 ClarifyTrial 실행 흐름에 연결하는 코드도 없다. 따라서 현재 상태는
`복사할 수 있는 연구 모듈`에 가깝고 `바로 실행 흐름에 붙는 완성 패키지`는 아니다.

### 가져올 부분과 보류할 부분

| 부분 | 판단 | 적용 방법 |
|---|---|---|
| 조건 논리를 고려한 최소 변경 조건 묶음 | 사용 | 현재 조건 논리와 판정 결과를 그대로 읽는 별도 계산으로 추가 |
| 선정·제외 방향을 반영한 수치 구간 | 수정 후 사용 | 현재 `TrialCriterion` 형식에 맞추고 경계값과 엄격한 부등호를 따로 처리 |
| 시간 경과 뒤 다시 확인할 날짜 | 제한적으로 사용 | 관련 사건과 날짜가 같은 근거에서 확인될 때만 계산 |
| 바뀌기 어려운 이력, 재검사 가능 값, 절차 조건 구분 | 수정 후 사용 | 시간 제한이 붙은 과거 치료를 영구 조건으로 잘못 분류하지 않도록 우선순위와 검사를 수정 |
| Anthropic API 호출과 응답 캐시 | 사용하지 않음 | 현재 ClarifyTrial의 형식 검사, 재시도, 사용량 기록과 조건 저장 캐시를 그대로 사용 |
| eICU 기반 미래 적격 확률 | 보류 | ICU 검사 변화가 다른 임상시험 환자에게 그대로 적용되지 않으며 현재 배포 모형도 보고된 최종 모형과 다름 |
| 여러 검사값의 동시 미래 확률 모형 | 보류 | 연구 결과는 참고하되 현재 ClarifyTrial 입력·출력과 연결된 실행 모듈이 아님 |

그대로 복사하기 전에 고칠 점도 확인했다.

- 엄격한 조건인 `초과`와 `미만`은 값이 기준과 정확히 같을 때 불충족이지만 현재
  거리 계산은 0으로 나온다. `경계에 있으나 불충족` 상태를 따로 표현해야 한다.
- `과거 항암치료 후 6주`처럼 시간이 지나면 달라지는 문장이 영구적으로 바뀌지 않는
  조건으로 분류되는 경우가 있다.
- 예시 연결 코드는 계산한 `호전 방향`을 최종 결과에 넘기지 않아, 환자 상태가
  나빠져야 만족하는 조건을 거르는 기능이 실제 연결 시 빠진다.
- 배포용 확률 파일은 경험적 구간별 비율을 사용하지만 문서의 대표 성능은 로지스틱
  회귀와 별도 확률 보정을 사용한 실험에서 나왔다. 현재 파일만 붙여 같은 수치가
  재현된다고 볼 수 없다.
- API 캐시 키에는 전체 입력은 들어가지만 모델과 지시문 버전이 들어가지 않고,
  재시도와 구조화 응답 검사는 현재 ClarifyTrial 구현보다 약하다.

따라서 1차 통합 범위는 `최소 변경 조건 묶음 + 확인된 시간 날짜`로 제한한다. 기존 수치
차이 표시는 그대로 재사용한다. 미래 적격 확률은 이 기능과 분리해 둔다. 원 저장소의
대표 수치는 동료 연구 결과이며, ClarifyTrial의 성능 수치로 옮겨 쓰지 않는다.

## 결과 해석의 경계

- 95.3%는 합성 답과 구조화 규칙이 전체 실행 흐름을 통과한 비율이다.
- 75/75는 객관적으로 구조화한 일부 조건의 최종 평가다.
- 589건 검색 결과는 고정 자료에서 미리 정한 평가 시험을 검색 결과에 연결한 점검이다. 검색된 모든
  시험의 추천 정확도를 측정한 값이 아니다.
- 전체 임상시험 참가 조건, 실제 환자 결과, 실제 등록 여부는 평가하지 않았다.
- TrialGPT보다 전체 추천 성능이 높다는 결론은 내리지 않는다.

## 자동 검사

현재 코드의 조건 계산, 정보 선택, 전체 실행, 저장·재개, 보고서, 공식 API 검색과 입력
경계 검사 307개가 통과했다. 공식 환자 파일 10명은 원본 형식을 바꾸지 않고 모두 읽었고,
공식 API 읽기 점검에서는 급성 췌장염 10건, 털곰팡이증 9건, 유문협착증의 동의어인
위출구폐쇄 2건을 가져왔다. 존재하지 않도록 만든 질환명은 0건을 반환했다. 이 점검은
검색 연결과 무관한 결과 차단을 확인한 것이며 최종 추천 정확도 평가는 아니다. 재실행
방법은 [실행과 실험 안내](CLARIFYTRIAL_V5_DEVELOPED_EXPERIMENT_GUIDE.md)에 정리돼 있다.
