# ClarifyTrial 시험 검색과 평가 구현

기준일: 2026-08-25

## 1. 검색이 맡는 일

ClarifyTrial의 검색은 환자에게 관련 있을 가능성이 있는 임상시험을 먼저 좁힌다. 검색
결과가 곧 참가 가능 판정은 아니다. 후보 시험을 찾은 뒤 각 시험의 선정·제외 조건을
환자 상태와 다시 비교한다.

```text
환자 상태
→ 관련 시험 검색
→ 시험 조건 불러오기
→ 조건별 판단
→ 부족한 정보 확인
→ 답변 반영과 재판정
```

일반 인터넷 검색으로 참가 조건을 바꾸지 않는다. 시험 조건은 저장된 공식 시험 원문과
구조화한 조건을 사용한다. 인터넷 자료가 필요한 경우는 시험 원문을 새로 받거나 출처를
확인하는 준비 단계로 한정한다.

## 2. 두 검색 경로

### 2.1 프로그램 연결용 공개 시험 검색

팀 공개 파일의 ClinicalTrials.gov 시험 1,931건 중 현재 모집 중이거나 모집 예정인
589건을 사용한다. 환자 질환과 시험 문서의 단어가 겹치는 정도를 계산하는 BM25로 상위
200건을 찾는다.

이 경로의 목적은 검색부터 질문 뒤 재판정까지 한 환자 기록으로 이어지는지 확인하는
것이다. 정밀 평가 대상으로 미리 정한 시험 50건만 뒤쪽 조건 판단에 넣는다. 검색된 다른
시험은 판정하지 않으므로 589건 전체 추천 성능으로 해석하지 않는다.

### 2.2 TrialGPT 검색 재현

TREC Clinical Trials 2021·2022에서는 TrialGPT와 같은 검색 구성을 사용한다.

1. 환자 설명에서 검색어 생성
2. BM25로 같은 표현이 많이 겹치는 시험 검색
3. MedCPT로 뜻이 가까운 시험 검색
4. 두 순위를 합쳐 최종 후보 생성

| 자료 | BM25 상위 500 유지 | MedCPT 상위 500 유지 | 두 검색 결합 |
|---|---:|---:|---:|
| TREC 2021 | 79.07% | 80.44% | **83.59%** |
| TREC 2022 | 78.75% | 78.95% | **81.55%** |

다시 실행한 값과 TrialGPT 공개 자료의 가장 큰 차이는 0.1퍼센트포인트보다 작았다. 이
결과는 검색 단계만 평가한다.

## 3. 자료 저장과 다시 실행

외부 자료는 저장소에 직접 넣지 않고 `.research-cache`에 받는다. 자료의 주소, 받은
날짜, 이용 조건은 [DATA_SOURCES.md](../../DATA_SOURCES.md)에 기록한다.

```text
.research-cache/
├─ team-trials/
│  └─ trials.jsonl
└─ trialgpt/
   ├─ source-data/
   └─ retrieval-cache/
```

BM25가 이미 나눈 단어를 다시 쓰기 위한 저장본은 gzip으로 압축한 JSON이다. 실행될 수
있는 Python 객체 저장 형식은 사용하지 않는다. 파일이 깨졌거나 형식 번호가 다르면
읽지 않고 원문에서 다시 만든다.

저장소에 남는 시험 출처는 공개 URL이다. 개인 컴퓨터의 절대 경로와 작업 폴더 이름은
평가자료와 보고서에 기록하지 않는다.

## 4. 조건 저장소

시험 조건은 검색 문서와 판정 규칙을 분리해 저장한다.

| 저장 내용 | 예 |
|---|---|
| 시험 식별자와 공개 출처 | ClinicalTrials.gov NCT 번호와 URL |
| 조건 원문 | “Platelet count at least 100 × 10⁹/L” |
| 조건 종류 | 선정 또는 제외 |
| 구조화 연산 | 최솟값·최댓값·참거짓·날짜 범위 |
| 필요한 환자 사실 | 혈소판 수치와 검사 날짜 |
| 복합 조건 관계 | 모두·하나 이상·일정 개수 이상 |

한 문장에 여러 수치와 예외가 섞여 안전하게 옮길 수 없으면 자동 계산 대상으로 넣지
않는다. 구조화하지 못한 조건은 모델 해석이나 별도 확인이 필요한 항목으로 남긴다.

## 5. 모델과 코드의 역할

### 코드가 맡는 일

- 후보 검색과 순위 저장
- 수치·단위·날짜·출처 검사
- 구조화된 선정·제외 조건 계산
- 복합 조건 계산
- 후보 유지와 현재 확인 상태 집계
- 다음에 확인할 정보와 확인 방법 선택
- 새 정보와 연결된 시험만 재판정
- 질문·검사·방문·호출·토큰 통계

### 모델이 맡는 일

- 자유 문장 조건의 뜻을 구조화된 조건으로 제안
- 구조화하지 못한 조건의 근거와 판단 이유 작성
- 선택된 미확인 정보를 환자에게 묻는 문장 작성
- 실제 근거 충돌이 있을 때 선택적 검토

구조화된 조건에 대해서는 모델의 답이 코드 계산과 달라도 코드 결과를 사용한다. 단순히
정보가 부족하다는 이유로 별도 검토를 부르지 않는다.

## 6. 검색 뒤 평가 단위

한 환자에게 검색된 모든 시험을 하나의 점수로만 보지 않는다. 시험마다 두 값을 저장한다.

| 값 | 질문 |
|---|---|
| 후보 유지 | 참가 가능성이 남아 있어 계속 확인할 시험인가? |
| 현재 확인 | 지금 자료만으로 참가 조건 확인을 끝낼 수 있는가? |

부족한 정보가 들어오면 연결된 시험만 다시 판단한다. 모든 시험을 처음부터 다시 부르지
않는다. 실행 기록에는 질문 전후 상태, 사용한 근거, 남은 정보와 종료 이유가 남는다.

## 7. 평가자료

| 자료 | 검색 범위 | 뒤쪽 평가 범위 | 용도 |
|---|---:|---:|---|
| 공개 시험 기반 통합 점검 | 589건 | 시험 50건·환자 30명·판단 150개 | 전체 연결과 질문 순서 |
| 새 시험 최종 평가 | 미리 고정한 시험 15건 | 환자 25명·판단 75개 | 모델 호출 구조 비교 |
| TREC 2021·2022 | 수만 건 | 전문가 관련성 표시 | 검색 단계 재현 |
| TrialGPT 조건 자료 | 검색 없음 | 환자 33명·조건 654개 | 질문 전 답 이름 비교 |

통합 점검과 새 시험 최종 평가는 합성 환자를 사용한다. 전체 상태를 먼저 정하고 필요한
사실을 가린 시작 자료와 질문 뒤 답을 만든다. 질문 순서는 숨겨 둔 답을 볼 수 없다.

## 8. 평가 지표

### 검색

- 관련 시험을 정해진 상위 후보 안에 남긴 비율
- 관련 시험의 평균·최저 순위
- 검색에 사용한 시험 수와 서로 다른 평가 대상 시험 수

### 질문 뒤 판단

- 처음 자료에서는 확정되지 않지만 전체 상태에서는 참가 가능한 시험 수
- 추가 확인 후보로 보존한 수와 실제 후보로 확정한 수
- 가능성이 남았지만 전체 상태에서는 제외되는 시험 수와 정리한 수
- 잘못 제외한 시험과 정보가 부족한데 확정한 시험 수
- 확인 횟수별 최종 상태 일치
- 답을 얻지 못한 확인과 같은 정보 반복 수

### 환자 부담과 실행

- 새 검사와 추가 방문 수
- 환자가 원하지 않은 방법을 선택한 수
- 외부 모델 호출, 역할별 토큰과 실행 시간
- 모델 출력 대신 구조화 계산을 적용한 판정 단계 수
- 별도 검토, 실패와 재개 수

같은 환자에게 연결된 여러 시험은 서로 독립인 사례로 세지 않는다. 환자를 단위로 다시
뽑아 95% 구간을 계산하고 질환별 결과 범위를 함께 저장한다.

## 9. 현재 결과

### 공개 시험 기반 통합 점검

추가 확인 세 번에서 실제 후보 47/54개를 확정하고 제외될 후보 68/68개를 정리했다.
최종 상태 일치는 143/150개, 95.3%였다. 강한 단순 질문 방법과 결과가 같았다.

589건 검색에서는 미리 정한 평가 대상 연결 150개가 모두 상위 200개 안에 들어왔다.
검색된 다른 시험은 판정하지 않았으므로 검색 연결 점검으로만 사용한다.

### 새 시험 최종 평가

| 실행 구조 | 최종 상태 일치 | 외부 호출 | 토큰 |
|---|---:|---:|---:|
| 구조화 규칙만 사용 | 75/75 | 0 | 0 |
| 조건 판단 모델만 사용 | 75/75 | 65 | 1,033,320 |
| 조건 판단과 질문 문장 역할 호출 | 75/75 | 105 | 1,565,829 |

구조화된 조건에서 모델 호출은 최종 결과를 높이지 않았다. 기본 실행은 코드를 사용한다.

## 10. 다시 실행하는 명령

### 설치와 자동 검사

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c constraints\research.txt -e ".[dev,retrieval-bm25,codex-subscription]"
.\.venv\Scripts\python.exe -m nltk.downloader punkt
.\.venv\Scripts\python.exe -m pytest -q
```

### 공개 시험 모음 준비

```powershell
.\.venv\Scripts\clarifytrial.exe prepare-team-trials
```

### 통합 점검

```powershell
.\.venv\Scripts\clarifytrial.exe run-workflow-evaluation `
  --trial-set data\public_protocol_benchmark_v1\trial_set.json `
  --patient-pairs data\public_protocol_benchmark_v1\patient_pairs.json `
  --generation-config configs\natural_evaluation_patient_generation_v2.json `
  --broad-corpus .research-cache\team-trials\trials.jsonl `
  --broad-search-top-k 200 `
  --provider deterministic `
  --split heldout `
  --budget-sweep `
  --concurrency 4 `
  --include-unavailable-scenario `
  --include-patient-choice-scenario `
  --approve-synthetic-actions `
  --output runs\public-protocol-budget-sweep
```

### 모델 호출 구조 결과 묶기

```powershell
.\.venv\Scripts\clarifytrial.exe compare-agent-architectures `
  --workflow runs\independent-new-trial-final-rules-v2\summary.json `
  --workflow runs\independent-new-trial-sol-single-judge-v2\summary.json `
  --workflow runs\independent-new-trial-sol-code-routed-v2\summary.json `
  --output docs\internal\results\independent-new-trial-agent-evaluation-v1
```

중단된 일괄 평가는 입력과 설정이 같을 때 `--resume`으로 이어서 실행한다.

## 11. 해석 범위

- TREC 결과는 관련 시험 검색만 평가한다.
- 589건 결과는 미리 정한 평가 대상이 뒤쪽 흐름에 연결됐는지 확인한 값이다.
- 통합 점검 95.3%는 같은 구조화 규칙으로 만든 기대 상태까지의 회복률이다.
- 새 시험 75/75개는 객관적으로 구조화한 일부 조건에 한정한다.
- TrialGPT보다 전체 추천 성능이 높다고 주장하지 않는다.
- 모델 역할을 여러 개로 나눈 것 자체를 성능 향상 근거로 사용하지 않는다.
- 자유 문장 복합 조건 해석은 별도 후속 평가가 필요하다.
