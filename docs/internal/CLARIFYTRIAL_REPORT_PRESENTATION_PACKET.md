# ClarifyTrial 발표 구성과 말하기 대본

기준일: 2026-08-30

## 발표가 끝났을 때 남길 판단

ClarifyTrial은 참가 가능성이 남은 시험을 계속 확인 대상으로 두고, 제한된 확인 기회를 여러 시험에 함께 도움이 되는 정보에 먼저 쓴다. 환자가 이용할 수 있는 확인 방법을 고른 뒤 새 근거와 연결된 조건을 다시 계산한다.

이번 발표에서 방어할 수 있는 범위는 다음과 같다.

- 기본 문진 정보를 넣은 최종 평가에서는 질문 순서 차이가 0.44%포인트로 작았다.
- 같은 현실적 시작 자료에서 남은 미확정 사례를 대상으로 질문 선택, 연결과 재판정이 한 흐름으로 작동했다.
- 질문 순서의 효과는 같은 정보가 여러 시험에 연결되는 방식에 따라 크게 달라졌다. 남은 확인 횟수 안에서 어떤 정보들을 함께 볼지 계산한 방법은 전체 평균 차이는 작았지만, 한 정보의 답이 다음 질문의 필요성을 바꾸는 구조에서는 도움이 됐다.
- 같은 정보를 얻는 방법은 환자 상황에 맞춰 골랐다. 새 검사와 방문을 원하지 않는 경우에는 해당 방법을 뺐고, 그만큼 확인을 기다리는 시험이 더 남았다.
- 수치는 공개 시험의 일부 구조화 조건과 합성 환자에서 관찰한 동작이다. 실제 환자의 모집률, 임상 정확도, 비용 절감과 대기시간 절감으로 넓혀 말하지 않는다.

## 본편 운영 기준

- 본편은 17장, 1,020초, 17분이다.
- 말하기 대본은 공백을 빼고 약 4,400자다. 분당 260~290자로 읽으면 약 15~17분이다.
  화면 전환과 터미널 입력을 포함해 16~18분대로 마치도록 잡았다.
- 3번의 실제 터미널 상호작용은 발표 시작 1분 25초에 보이고 2분 45초 안에 끝난다.
- 목차, 장 구분 화면, 상단 단계 탭, 반복 구호, 작은 카드 묶음은 사용하지 않는다.
- 제목은 35pt 이상으로 한 줄에 놓고, 본문은 18pt 이상, 주요 수치는 28pt 이상으로 둔다.
- 짙은 남색과 청록을 기본으로 쓰고 조건 불충족과 위험 표시에만 탁한 빨강을 쓴다.
- 수치 화면에는 합성자료 여부, 통계에서 무엇을 한 단위로 셌는지, 어디까지 해석할 수 있는지를 한 줄로 적는다.
- ClarifyTrial, ClinicalTrials.gov, HbA1c와 논문명 외에는 자연스러운 한국어를 쓴다.

화면

- 석 달 전: HbA1c 정상
- 오늘: 최근 14일 안의 공식 결과 없음
- 시험 조건: 최근 14일 안의 HbA1c 필요

시간축 아래에는 두 문장만 둔다.

- 참가 가능성은 남아 있다.
- 오늘 가진 자료로는 확인을 끝낼 수 없다.

그림

- 별도 파일 없이 슬라이드 도형으로 시간축을 만든다.

말하기

> 한 시험이 최근 14일 안의 HbA1c를 요구한다고 가정하겠습니다. 환자 기록에는 석 달 전 정상 결과만 있습니다. 최근 결과가 없다는 이유로 후보에서 지우면 오늘 기준을 충족할 환자를 놓칠 수 있습니다. 석 달 전 값만 믿고 확인을 끝내면 시험이 요구한 기간을 무시하게 됩니다. 여기서는 두 가지를 따로 봅니다. 더 확인해 볼 가치가 남아 있는가, 지금 가진 자료로 판단을 끝낼 수 있는가입니다. 이 환자는 후보에서 빼지 않되 최종 판단은 최근 결과가 들어올 때까지 미룹니다. 최근 14일 안에 받은 HbA1c 결과가 있는지 확인하고, 검사일과 기록 출처도 함께 봅니다. 두 상태를 나누면 무엇을 더 알아볼지도 분명하게 남길 수 있습니다.

### 3. 7.5%를 입력하자 두 시험의 판단이 갈렸다 — 1분 20초

1. 두 시험이 최근 HbA1c를 기다리는 상태
2. 최근 공식 결과를 묻는 질문
3. 환자가 입력한 7.5%
4. 같은 근거가 두 시험에 연결된 재판정 결과

화면에 남길 결과는 다음과 같다.

- HbA1c 7.0% 미만 조건: 조건 불충족
- HbA1c 8.0% 미만 조건: 현재 자료로 확인 완료

그림

- docs/internal/diagrams/clarifytrial-terminal-demo.svg

말하기

> 실제 실행 화면입니다. 처음에는 두 시험 모두 후보로 남아 최근 HbA1c를 기다립니다. 같은 정보가 필요해 질문은 한 번만 나옵니다. 7.5%라는 값과 검사일, 기록일, 출처를 함께 입력하면 하나의 근거로 저장됩니다. 답이 오기 전에는 두 시험을 후보로 두고 판단을 보류했습니다. 답이 들어오자 코드가 각 시험 기준을 다시 계산합니다. 7.0% 미만 조건은 충족하지 못했고, 8.0% 미만 조건은 충족한 것으로 확인됩니다. 같은 근거를 썼어도 시험 기준이 달라 결론이 갈렸습니다. 수치와 날짜는 코드가 계산합니다. 화면 아래에는 판단에 쓰인 근거와 아직 필요한 정보가 함께 표시됩니다.

각주

- 합성 환자와 합성 시험을 사용한 통제 예시다.
- 이 결과는 의학적 조언이 아니며 실제 참가 가능성은 해당 시험의 최신 기준과 전체 자료로 다시 확인해야 한다.

> 화면에는 사전 검토를 마친 시험과, 가능성이 남아 있어 추가 확인이 필요한 시험이 따로 표시됩니다. 가능성이 남아도 판단이 끝나지 않았다면 다음 질문이나 기록 조회가 이어집니다. 한 번 확인한 사실은 필요한 시험에 함께 반영하고, 환자가 원하지 않거나 이용하기 어려운 검사와 방문은 확인 방법에서 뺍니다. 조건을 충족하지 못한 시험에는 걸린 조건을 표시합니다. 수치나 날짜로 계산할 수 있다면 기준에서 얼마나 벗어났는지, 언제 다시 확인할 수 있는지도 덧붙입니다. 답이 들어오면 관련된 조건만 다시 계산합니다. 어떤 근거로 판단이 바뀌었고 무엇을 더 확인해야 하는지도 함께 남깁니다.

ClarifyTrial은 미확정 시험을 질문 가능한 상태로 남깁니다. 여러 시험에 함께 필요한 정보와 환자 제한을 살펴 다음 확인을 고른 뒤, 새 답과 관련된 조건만 다시 계산합니다. 참가 가능성이 남았는지와 지금 가진 자료로 판단을 끝냈는지도 따로 저장합니다. 이 흐름이 언제 도움이 되는지는 처음에 주어진 정보와 시험 사이의 정보 연결 구조를 바꿔 확인했습니다.

ClinicalTrials.gov에서 후보를 찾으면 질환 관련성을 확인하고 선정·제외 조건의 원문 위치를 남깁니다. 수치와 날짜처럼 계산 가능한 조건은 코드 규칙으로 바꿉니다. 판단에 필요한 값이 빠져 있으면 어떤 정보를 더 알아야 하는지 조건에 연결해 둡니다. 이어서 판단이 보류된 시험과 가장 많이 연결된 정보를 고르고, 환자가 이용할 수 있는 확인 방법을 찾습니다. 답이 들어오면 관련 조건만 다시 계산합니다. 실행이 중단돼도 이어 갈 수 있도록 선택 이유와 진행 상태도 저장합니다.

### 15. 새 검사와 방문을 빼자 확인을 기다리는 시험이 늘었다 — 1분 5초

화면

- 추가 방문 제안: 56회 → 0회
- 설정 하나에 남은 확인 대기 시험 평균: 0.88개 → 1.24개

### 16. 언제 도움이 되고 어디서 효과가 줄었는지 함께 확인했다 — 1분

화면

한 줄 흐름의 확인된 범위

- 세 기본 문진을 넣은 뒤의 질문 순서 차이
- 추가 답이 들어오면 확인 완료가 되도록 만든 사례에서 질문부터 재판정까지 이어진 흐름
- 정보 연결 모양에 따른 질문 순서 변화
- 환자 상황에 따른 확인 방법 선택
- 금지한 검사와 방문의 차단
- 답변 뒤 관련 조건 재계산과 근거 저장

회색 글씨로 남은 평가 범위를 붙인다.

- 실제 환자의 모집 성과와 임상 판단 정확도
- 다양한 검사와 병력
- 병원마다 다른 비용과 대기시간
- 새로운 질환과 시험 묶음에서의 일반화

그림

- 별도 파일 없이 확인된 범위가 한 줄로 이어지는 도형을 만든다.

말하기

ClarifyTrial은 이 차이를 숨기지 않고, 확인 가능한 범위 안에서 다음 행동과 남은 정보를 함께 보여 줍니다. 이번 결과는 공개 시험의 일부 조건과 합성 환자에서 확인했습니다. 실제 모집 성과와 임상 판단 정확도는 측정하지 않았습니다. 다음 단계에서는 완전한 환자 기록과 독립된 전문가 판단을 바탕으로 새로운 병원 환경에서 평가해야 합니다.

화면 아래 고정 문구

이 결과는 의학적 조언이 아닌 참고용입니다. 임상시험 참가 가능성은 해당 시험의 최신 기준과 전체 자료를 바탕으로 다시 확인해야 합니다.

- 수치 화면에는 합성자료 여부와 해석 범위를 반드시 붙인다.
- 본편에 미확정 수치, 빈 표와 자리표시자를 두지 않는다.
- 3번의 터미널 화면이 발표 시작 3분 안에 실제로 보이는지 리허설로 확인한다.

## 예상 질문과 짧은 답

### 14건 확정은 실제 환자에서 살릴 비율입니까?

> 공개 시험의 일부 구조화 조건과 합성 환자에서 질문부터 재판정까지 이어지는지를 확인한 값입니다. 남은 22건은 추가 답이 들어오면 참가 가능 확인 완료가 되도록 미리 만든 사례였습니다. 실제 환자의 모집 성공률로 일반화하지 않습니다.

### 왜 질문 뒤 14건이 모두 참가 가능 확정이고 제외는 0건입니까?

> 처음 자료로 28건이 정리됐고, 세 기본 문진으로 제외 68건과 참가 가능 확인 완료 32건이 더 정리됐습니다. 남은 22건은 완전한 합성 상태에서 참가 가능 확인 완료가 정답이 되도록 구성했습니다. 질문 뒤 제외 0건은 이 구성에서 예상되는 결과이며 별도 성과로 세지 않습니다.

### 환자는 30명인데 왜 질문이 14회뿐입니까?

> 확인이 필요한 환자에게만 질문했습니다. 14명이 질문을 받았고 각자 한 번씩 답했습니다. 나머지 환자는 시작 자료로 현재 상태를 정리할 수 있었습니다.

### 36.5%포인트가 0.44%포인트로 줄었다면 질문 순서 규칙이 필요 없지 않습니까?

> 기본 문진 정보가 갖춰진 공개 평가에서는 순서 차이가 거의 없었습니다. 그래서 현재 규칙의 성능 우위를 주장하지 않습니다. 남은 22건 실험은 질문 선택, 답 연결과 재판정이 이어지는지 확인했고, 구조 실험은 여러 시험이 한 정보에 직접 묶일 때만 순서 차이가 커진다는 경계를 보여 줬습니다.

### 36.5%포인트를 왜 보여 줍니까?

> 큰 수치가 처음 제공한 정보에 따라 크게 달라졌다는 사실을 숨기지 않기 위해서입니다. 성능 주장에는 쓰지 않습니다.

### 공유 조건 64.4%면 질문 순서의 효과가 항상 큰 것 아닙니까?

> 130개 가운데 126개가 세 기본 정보에 몰려 있었습니다. 연결 구조를 바꾸자 전체 공유에서는 큰 차이가 났지만 완전 분리에서는 차이가 없었고 사슬에서는 현재 규칙이 조금 낮았습니다.

### 사슬형 구조에서 낮아진 이유는 무엇입니까?

> 현재 연결 수만 보는 규칙은 앞으로 몇 번 더 확인할 수 있는지까지 내다보지 못합니다. 확인을 두세 번 허용하고 함께 볼 정보 조합을 계산하자 사슬형 구조에서는 현재 규칙보다 3.2~4.3%포인트 높았습니다. 현재 규칙을 모든 구조에서 우수하다고 말하지 않고, 사슬형 연결은 정보 조합을 계산하는 방법과 함께 비교합니다.

### 앞으로 확인할 정보 조합을 계산하는 방법을 왜 기본값으로 쓰지 않습니까?

> 세 기본 문진을 제공한 합성 자료에서는 질문 순서 차이가 0.44%포인트였습니다. 구조 실험에서도 전체 평균 차이는 1.2~2.0%포인트였고, 현재 규칙은 확인 방법의 부담까지 함께 봅니다. 사슬형 연결에서는 앞으로 확인할 정보 조합을 계산한 방법이 나았으므로 비교 대상으로 남겨 뒀습니다. 어느 연결 방식에서 자동으로 바꿀지는 다음 평가에서 정해야 합니다.

### 85/85 결과가 너무 완벽한 것 아닙니까?

> 같은 답을 주는 두 확인 방법에 합성 시간과 부담만 다르게 붙인 통제 실험입니다. 선택 규칙이 입력에 맞게 움직이는지 본 기능 점검이며 실제 효용 비교가 아닙니다.

### 21회와 56회를 더해 77개 행동을 없앴다고 말할 수 있습니까?

> 한 행동에 새 검사와 추가 방문이 함께 붙을 수 있어 더할 수 없습니다. 두 부담 항목을 각각 0회로 줄였다고만 말합니다.

### 제한 뒤 내부 상태 일치가 높아진 이유는 무엇입니까?

> 환자가 허용한 정보와 확인 방법으로 도달 가능하도록 내부 목표를 정했기 때문입니다. 환자 설정을 적용한 규칙이 그 목표를 지키는지 보는 소프트웨어 점검이며 임상 정확도를 나타내지 않습니다. 해석은 내부 규칙 점검에 한정합니다.

### 제한을 지키면 환자 부담이 실제로 줄었다고 볼 수 있습니까?

> 실제 환자 편익을 측정하지 않았습니다. 합성한 제한을 프로그램이 지켰고, 그 대가로 확인 대기 시험과 끝까지 정리되지 않은 설정이 늘었다는 결과입니다.

### DQueST, MediQ, TrialTriage와 무엇이 다릅니까?

> 공통 질문, 정보 충분성 판단과 답변 뒤 재판정은 선행연구에 있습니다. ClarifyTrial은 후보 상태와 현재 확인 상태, 환자별 확인 방법, 관련 조건 재계산과 근거 저장을 한 실행에 묶었습니다. 처음 제공한 정보에 따라 결과가 얼마나 달라지는지, 질문부터 재판정까지 이어지는지, 어떤 연결 모양에서 효과가 줄어드는지를 함께 측정했습니다.

### TrialGPT보다 성능이 좋다는 뜻입니까?

> 그런 결론을 내리지 않습니다. TrialGPT 공개 조건 자료는 질문 전 조건 판단을 평가합니다. 현재 발표는 정보가 부족한 뒤의 질문 선택, 확인 방법 선택과 상태 변화를 다룹니다.

### 호출·토큰·응답시간 감소를 일반적인 성능 개선으로 볼 수 있습니까?

> 합성 환자 한 사례의 변경 전후 기록입니다. 변경 전 코드가 모델 판정 한 건을 교정한 사실도 영구적인 안전성 성과로 세지 않습니다. 이 추적에서 불필요한 조건 판단 호출을 찾아 제거했고, 변경 후에도 최종 상태와 질문 정보 순서가 같았습니다. 호출, 토큰과 응답시간 합의 감소율은 평균값으로 사용하지 않습니다.

### 확인 횟수가 늘면 연결 구조의 효과도 유지됩니까?

> 합성 답이 나오는 비율을 개발 때와 같게 둔 평가에서 모든 시험이 한 정보를 공유한 구조의 현재 규칙과 단계별 무작위 선택 차이는 확인 1·2·3회에 각각 43.28, 30.09, 19.19%포인트였습니다. 시험마다 필요한 정보가 분리된 구조는 세 경우 모두 차이가 없었습니다. 확인을 두세 번 허용하고 앞으로 확인할 정보 조합을 계산한 방법은 현재 규칙보다 전체 구조 평균 1.2~2.0%포인트, 사슬형 구조에서는 3.2~4.3%포인트 높았습니다.

### 실제 환자에게 적용하려면 무엇이 더 필요합니까?

> 완전한 환자 기록, 독립된 임상 전문가 판단, 다양한 시험 원문, 실제 비용과 대기시간, 사람 검토 과정이 필요합니다. 새로운 질환과 병원 환경에서도 같은 경계를 유지하는지 따로 검증해야 합니다.
