## 작업 범위와 기준 슬라이드

- 기준 슬라이드는 동료가 갱신한 [Google Slides 36장](https://docs.google.com/presentation/d/1h31cn4EuP3Rr9zdDGe6zM1jiZRmhIlDIEh1ccOyaB8o/edit)이다.
- 이 문서는 새 발표 파일을 만드는 설계서가 아니다. 기존 슬라이드의 배치와 도형을
  유지하면서 순서, 제목, 화면 문구와 말하기 대본을 고치는 지시서다. Google Slides
  파일을 직접 수정하는 작업은 이 범위에 포함하지 않는다.
- 현재 수동 수정에서는 기존 13번을 시스템 설계의 마지막 장으로 두고
  [발표용 대화형 데모](demo/clarifytrial-presentation-demo.html)로 교체한다. 데모에서는
  상태 읽기, 다음 행동 결정, 확인 도구 실행, 상태 갱신과 반복·종료 판단을 한 순환으로
  보여 준다. 아래의
  본편 17장·부록 13장 재배치안은 이전 전체 구성 참고이며 이 수동 수정에 자동으로
  적용하지 않는다.
- 이전 재배치안에서는 목차·구분 화면·빈 화면인 기존 2, 3, 6, 14, 22, 25번만 뺀다. 나머지 30장은
  버리지 않고 본편 17장과 부록 13장으로 다시 배치한다.
- 이전 본편 순서는 `1 → 4 → 10 → 5 → 18 → 31 → 7 → 12 → 8 → 9 → 15 → 16 → 17 → 19 → 23 → 27 → 26`이다.
- 이전 부록 순서는 `13 → 20 → 11 → 28 → 30 → 21 → 36 → 29 → 24 → 32 → 33 → 34 → 35`이다.
- 아래에 적은 그림 파일은 수치와 문구를 대조하는 참고 자료다. 기존 슬라이드로 표현할
  수 있는 화면을 새 그림으로 다시 만들라는 뜻이 아니다.

## 발표가 끝났을 때 남길 판단

ClarifyTrial은 정보가 부족한 시험을 바로 제외하지 않는다. 참가 가능성이 남아 있는지와
현재 자료로 확인을 끝낼 수 있는지를 따로 판단한다. 확인이 더 필요하면 여러 시험에
함께 쓰이는 정보를 찾고, 환자가 이용할 수 있는 방법으로 확인한 뒤 새 근거와 연결된
조건만 다시 계산한다.

이번 발표에서 방어할 수 있는 범위는 다음과 같다.

- 기본 문진 정보를 넣은 최종 평가에서는 질문 순서 차이가 0.44%포인트로 작았다.
- 같은 시작 자료에서 남은 미확정 사례를 대상으로 질문 선택, 답 연결과 다시 판단하는
  과정이 끊기지 않고 이어졌다.
- 질문 순서의 효과는 같은 정보가 여러 시험에 연결되는 방식에 따라 크게 달라졌다. 남은 확인 횟수 안에서 어떤 정보들을 함께 볼지 계산한 방법은 전체 평균 차이는 작았지만, 한 정보의 답이 다음 질문의 필요성을 바꾸는 구조에서는 도움이 됐다.
- 같은 정보를 얻는 방법은 환자 상황에 맞춰 골랐다. 새 검사와 방문을 원하지 않는 경우에는 해당 방법을 뺐고, 그만큼 확인을 기다리는 시험이 더 남았다.
- 수치는 공개 시험에서 코드로 계산할 수 있게 정리한 일부 조건과 합성 환자에서 관찰한
  동작이다. 실제 환자의 모집률, 임상 정확도, 비용 절감과 대기시간 절감으로 넓혀 말하지
  않는다.

## 본편 운영 기준

- 본편은 17장이다. 말하기 시간은 945초, 15분 45초로 잡고 화면 전환과 주요 수치 설명을
  포함해 16~17분 안에 마친다.
- 말하기 대본은 공백을 빼고 약 3,400자다. 빠르게 읽어 시간을 채우지 않고, 수치 화면과
  답 반영 결과에서 잠깐 멈출 여유를 둔다.
- 3번 슬라이드의 답 반영 화면은 발표 시작 1분 25초에 보이고 2분 45초 안에 끝난다.
- 목차와 장 구분 화면은 뺀다. 기존 상단 단계 탭은 위치와 색을 유지하되 현재 단계 하나만
  강조한다. 같은 뜻을 반복하는 구호와 장식 카드는 줄인다.
- 제목은 35pt 이상으로 한 줄에 놓고, 본문은 18pt 이상, 주요 수치는 28pt 이상으로 둔다.
- 짙은 남색과 청록을 기본으로 쓰고 조건 불충족과 위험 표시에만 탁한 빨강을 쓴다.
- 수치 화면에는 합성자료 여부, 통계에서 무엇을 한 단위로 셌는지, 어디까지 해석할 수 있는지를 한 줄로 적는다.
- ClarifyTrial, ClinicalTrials.gov, HbA1c와 논문명 외에는 자연스러운 한국어를 쓴다.

화면

- ClarifyTrial
- 정보가 부족한 시험을 남겨 두고, 무엇을 어떤 방법으로 확인할까?
- 팀명

그림

말하기

### 2. 석 달 전 검사만으로는 후보를 지우기 이르다 — 1분

화면

기존 4번의 예시 상자와 두 비교 카드를 그대로 사용한다.

- 예시 상자: 최근 14일 안의 HbA1c가 필요한 시험, 석 달 전 정상 결과만 있는 환자
- 왼쪽 카드: 최근 결과가 없다는 이유로 후보를 바로 지우는 경우
- 오른쪽 카드: 석 달 전 값으로 확인을 끝내는 경우

아래 결론 띠에는 두 판단을 한 문장으로 묶는다.

- 참가 가능성은 남아 있지만, 오늘 가진 자료로는 확인을 끝낼 수 없다.

그림

- 기존 4번의 상자, 비교 카드와 아래 결론 띠를 유지한다.

말하기

> 한 시험이 최근 14일 안의 HbA1c를 요구합니다. 환자 기록에는 석 달 전 정상 결과만 있습니다. 최근 값이 없다고 바로 제외하면 오늘 기준을 충족할 환자를 놓칠 수 있고, 석 달 전 값으로 확인을 끝내면 시험이 요구한 기간을 무시하게 됩니다. 그래서 후보로 남길지와 지금 확인을 끝낼 수 있는지를 나눠 봅니다. 이 환자는 후보로 남기되, 최근 공식 결과가 들어올 때까지 판단을 미룹니다. 검사일과 기록 출처도 함께 확인해야 다음 판단의 근거가 됩니다.

### 3. 7.5%를 입력하자 두 시험의 판단이 갈렸다 — 1분 20초

화면

기존 10번의 세 칸 흐름을 그대로 사용한다.

1. 새 근거 입력: HbA1c 7.5%, 검사일과 출처
2. 관련 조건만 다시 판단: 시험 A는 7.0% 미만, 시험 B는 8.0% 미만
3. 결과와 근거 저장: 시험 A는 조건 불충족, 시험 B는 확인 완료

화면에 남길 결과는 다음과 같다.

- HbA1c 7.0% 미만 조건: 조건 불충족
- HbA1c 8.0% 미만 조건: 현재 자료로 확인 완료

그림

- 기존 10번의 세 칸 흐름을 유지한다.
- `docs/internal/diagrams/clarifytrial-terminal-demo.svg`는 값과 문구를 대조할 때만 참고한다.

말하기

> 처음에는 두 시험 모두 후보로 남아 최근 HbA1c를 기다립니다. 필요한 정보가 같아 질문은 한 번만 나옵니다. 7.5%라는 값과 검사일, 기록일, 출처를 입력하면 하나의 근거로 저장됩니다. 이 값은 7.0% 미만 조건에는 맞지 않지만 8.0% 미만 조건에는 맞습니다. 같은 근거를 사용해도 시험마다 기준이 달라 결론이 갈립니다. 수치와 날짜는 코드가 계산하고, 판단에 쓴 근거와 아직 필요한 정보도 함께 남깁니다.

각주

- 합성 환자와 합성 시험을 사용한 통제 예시다.
- 이 결과는 의학적 조언이 아니며 실제 참가 가능성은 해당 시험의 최신 기준과 전체 자료로 다시 확인해야 한다.

### 4. 후보 유지와 확인 완료는 다른 판단이다 — 55초

화면

최종 화면의 두 목록과 그 아래 상태 흐름을 함께 보여 준다.

- 현재 자료로 조건을 확인한 시험
- 추가 정보를 확인하면 가능성이 남는 시험
- 다음 확인: 최근 공식 HbA1c
- 답변 뒤 변화: 연결된 조건만 다시 계산
- 제외된 시험: 걸린 조건과, 계산할 수 있는 경우의 수치 차이·재확인 시점

그림

- 별도 파일 없이 기존 5번의 상태 요소를 한 줄 흐름으로 다시 그린다.

말하기

> 사전 검토를 마친 시험과 추가 확인이 필요한 시험은 따로 보입니다. 참가 가능성이 남아 있어도 현재 자료가 부족하면 다음 질문이나 기록 조회가 이어집니다. 한 번 확인한 사실은 필요한 시험에 함께 반영하고, 환자가 이용하기 어려운 검사와 방문은 확인 방법에서 뺍니다. 조건을 충족하지 못한 시험에는 걸린 조건과 수치 차이, 계산할 수 있는 경우의 재확인 시점을 붙입니다. 새 답이 들어오면 그 답과 연결된 조건만 다시 계산하고, 판단이 바뀐 근거와 남은 정보도 기록합니다.

### 5. 공통 정보는 많았지만 기본 문진 뒤 순서 차이는 작았다 — 55초

화면

- 공개 임상시험 50건, 코드로 계산할 수 있게 정리한 조건 202개
- 같은 질환의 다른 시험에도 쓰이는 정보와 연결된 조건 130개
- 130개 중 126개는 나이, 임신·수유와 활동성 중증 감염
- 세 기본 정보를 먼저 제공한 뒤 질문 순서 차이: 0.44%포인트

130개와 0.44%포인트를 한 화면에 놓는다. 공통 조건의 수와 질문 순서 효과가 같지
않다는 점이 바로 보이게 한다.

그림

- docs/internal/diagrams/clarifytrial-shared-information-coverage.svg

말하기

> 공개 시험 50건에서 조건 202개를 코드로 계산할 수 있게 정리했습니다. 그중 130개가 같은 질환의 시험 두 건 이상에 쓰이는 정보와 연결됐습니다. 하지만 130개 가운데 126개는 나이, 임신·수유와 활동성 중증 감염이었습니다. 이 세 정보를 기본 문진으로 먼저 주자 현재 규칙과 가능한 모든 질문 순서의 평균 차이는 0.44%포인트였습니다. 공통 정보가 많다는 사실만으로 질문 순서가 중요하다고 볼 수는 없었습니다. 그래서 실제 환자 흐름과 정보 연결 모양을 나눠 확인했습니다.

각주

- 130개 가운데 126개가 나이, 임신·수유와 활동성 감염에 해당한다.
- 공유 비율을 새로운 질환과 복잡한 조건에 그대로 적용하지 않는다.

근거 파일

- runs/public-protocol-shared-facts-v1/shared-fact-report.json

### 6. 선행연구의 기능을 후보 관리와 다시 판단하는 흐름으로 묶었다 — 50초

화면

시험 검색에서 다시 판단하는 과정까지 한 줄로 잇고, 선행연구는 세 묶음으로만 보인다.

- 후보 검색과 조건 판단: TrialGPT
- 부족한 정보와 여러 시험에 공통인 질문: MediQ, DQueST, Chen et al., Yang
- 비용을 고려한 확인과 답변 뒤 다시 판단: Fink 계열, TrialTriage

아래에는 ClarifyTrial이 한 흐름에서 함께 관리하는 네 항목만 둔다.

- 후보로 남길지
- 현재 자료로 확인을 끝낼 수 있는지
- 환자가 이용할 수 있는 확인 방법
- 새 근거와 연결된 조건만 다시 계산하기

그림

- 별도 파일 없이 슬라이드 도형으로 한 줄 흐름을 만든다.

말하기

> 시험 검색과 조건 판단, 공통 질문, 비용을 고려한 확인, 답변 뒤 다시 판단하는 방법은 선행연구에 있습니다. ClarifyTrial은 이 기능들을 처음 만들었다고 주장하지 않습니다. 정보가 부족한 시험을 후보로 관리하고, 현재 자료가 충분한지 확인한 뒤, 환자에게 가능한 방법으로 답을 얻어 관련 조건만 다시 계산하는 데 초점을 뒀습니다. 평가는 이 과정이 끝까지 이어지는지와 어떤 정보 연결 구조에서 질문 순서가 달라지는지를 살폈습니다.

## 예상 질문과 짧은 답

### 14건 확정은 실제 환자에서 살릴 비율입니까?

> 공개 시험의 일부 조건과 합성 환자에서 질문부터 다시 판단하기까지 이어지는지를 확인한 값입니다. 남은 22건은 숨긴 답이 들어오면 참가 가능 확인을 마치도록 만든 사례였습니다. 실제 환자의 모집 성공률로 일반화하지 않습니다.

### 왜 질문 뒤 14건이 모두 참가 가능 확정이고 제외는 0건입니까?

> 처음 자료로 28건이 정리됐고, 세 기본 문진으로 제외 68건과 참가 가능 확인 완료 32건이 더 정리됐습니다. 남은 22건은 합성 환자의 전체 정보 기준으로 참가 가능 확인을 마치도록 구성했습니다. 질문 뒤 제외가 0건인 것은 이 자료 구성에서 예상되는 결과이며 별도 성과로 세지 않습니다.

### 환자는 30명인데 왜 질문이 14회뿐입니까?

> 확인이 필요한 환자에게만 질문했습니다. 14명이 질문을 받았고 각자 한 번씩 답했습니다. 나머지 환자는 시작 자료로 현재 상태를 정리할 수 있었습니다.

### 36.5%포인트가 0.44%포인트로 줄었다면 질문 순서 규칙이 필요 없지 않습니까?

> 기본 문진 정보가 갖춰진 공개 평가에서는 순서 차이가 거의 없었습니다. 그래서 현재 규칙의 성능 우위를 주장하지 않습니다. 남은 22건 실험은 질문 선택, 답 연결과 다시 판단하는 과정이 이어지는지 확인했습니다. 구조 실험에서는 여러 시험이 같은 한 정보를 기다릴 때만 순서 차이가 커졌습니다.

### 36.5%포인트를 왜 보여 줍니까?

> 초기 결과가 처음 제공한 정보에 따라 크게 달라졌다는 점을 보여 주기 위해서입니다. 질문 방법의 성능 주장에는 쓰지 않습니다.

### 공유 조건 64.4%면 질문 순서의 효과가 항상 큰 것 아닙니까?

> 130개 가운데 126개가 세 기본 정보에 몰려 있었습니다. 확인을 두세 번 허용한 연결 구조 실험에서 직접 공유는 현재 규칙이 단계별 무작위보다 높았지만, 완전 분리에서는 세 방법이 같았습니다. 사슬에서는 조합 탐색이 현재 규칙보다 높았습니다.

### 사슬형 구조에서 조합 탐색이 더 높았던 이유는 무엇입니까?

> 현재 연결 수만 보는 규칙은 앞으로 몇 번 더 확인할 수 있는지까지 내다보지 못합니다. 확인을 두세 번 허용하고 함께 볼 정보 조합을 계산하자 사슬형 구조에서는 현재 규칙보다 3.2~4.3%포인트 높았습니다. 현재 규칙을 모든 구조에서 우수하다고 말하지 않고, 사슬형 연결은 정보 조합을 계산하는 방법과 함께 비교합니다.

### 앞으로 확인할 정보 조합을 계산하는 방법을 왜 기본값으로 쓰지 않습니까?

> 세 기본 문진을 제공한 합성 자료에서는 질문 순서 차이가 0.44%포인트였습니다. 구조 실험에서도 전체 평균 차이는 1.2~2.0%포인트였고, 현재 규칙은 확인 방법의 부담까지 함께 봅니다. 사슬형 연결에서는 앞으로 확인할 정보 조합을 계산한 방법이 나았으므로 비교 대상으로 남겨 뒀습니다. 어느 연결 방식에서 자동으로 바꿀지는 다음 평가에서 정해야 합니다.

### 85/85 결과가 너무 완벽한 것 아닙니까?

> 같은 답을 주는 두 확인 방법에 합성 시간과 부담만 다르게 붙인 통제 실험입니다. 선택 규칙이 입력에 맞게 움직이는지 본 기능 점검이며 실제 효용 비교가 아닙니다.

### 21회와 56회를 더해 77개 행동을 없앴다고 말할 수 있습니까?

> 한 행동에 새 검사와 추가 방문이 함께 붙을 수 있어 더할 수 없습니다. 두 부담 항목을 각각 0회로 줄였다고만 말합니다.

### 제한 뒤 내부 상태 일치가 높아진 이유는 무엇입니까?

> 환자가 허용한 정보와 확인 방법으로 도달 가능하도록 내부 목표를 정했기 때문입니다. 환자 설정을 적용한 규칙이 그 목표를 지키는지 보는 소프트웨어 점검이며 임상 정확도를 나타내지 않습니다. 해석은 내부 규칙 점검에 한정합니다.

### 제한을 지키면 환자 부담이 실제로 줄었다고 볼 수 있습니까?

> 실제 환자 편익을 측정하지 않았습니다. 합성한 제한을 프로그램이 지켰고, 그 대가로 확인 대기 시험과 끝까지 정리되지 않은 설정이 늘었다는 결과입니다.

### DQueST, MediQ, TrialTriage와 무엇이 다릅니까?

> 여러 시험에 공통인 질문을 고르고, 현재 정보가 충분한지 확인하며, 답변 뒤 다시 판단하는 방법은 선행연구에 있습니다. ClarifyTrial은 정보가 부족한 시험을 후보로 관리하고, 환자가 이용할 수 있는 방법으로 답을 얻어 관련 조건만 다시 계산합니다. 이번 평가에서는 처음 주어진 정보와 시험 사이의 연결 모양에 따라 결과가 어떻게 달라지는지도 함께 살폈습니다.

### TrialGPT보다 성능이 좋다는 뜻입니까?

> 그런 결론을 내리지 않습니다. TrialGPT 공개 조건 자료는 질문 전 조건 판단을 평가합니다. 현재 발표는 정보가 부족한 뒤의 질문 선택, 확인 방법 선택과 상태 변화를 다룹니다.

### 호출·토큰·응답시간 감소를 일반적인 성능 개선으로 볼 수 있습니까?

> 합성 환자 한 사례의 변경 전후 기록입니다. 변경 전 코드가 모델 판정 한 건을 교정한 사실도 영구적인 안전성 성과로 세지 않습니다. 이 추적에서 불필요한 조건 판단 호출을 찾아 제거했고, 변경 후에도 최종 상태와 질문 정보 순서가 같았습니다. 호출, 토큰과 응답시간 합의 감소율은 평균값으로 사용하지 않습니다.

### 확인 횟수가 늘면 연결 구조의 효과도 유지됩니까?

> 확인을 두 번과 세 번 허용했을 때 모든 시험이 한 정보를 공유한 구조의 현재 규칙과 단계별 무작위 차이는 두 답 분포에서 19.03~30.09%포인트였습니다. 시험마다 필요한 정보가 분리된 구조에서는 세 방법이 같았습니다. 조합 탐색은 현재 규칙보다 전체 구조 평균 1.2~2.0%포인트, 사슬형 구조에서 3.2~4.3%포인트 높았습니다. 확인 1회 결과는 첫 질문만 분리한 보조 분석으로 남겼습니다.

### 실제 환자에게 적용하려면 무엇이 더 필요합니까?

> 완전한 환자 기록, 독립된 임상 전문가 판단, 다양한 시험 원문, 실제 비용과 대기시간, 사람 검토 과정이 필요합니다. 새로운 질환과 병원 환경에서도 같은 경계를 유지하는지 따로 검증해야 합니다.

발표에서 사용할 기여 문장

> ClarifyTrial은 정보가 부족한 시험을 바로 제외하지 않는다. 여러 시험에 함께 필요한 정보를 찾고, 환자가 이용할 수 있는 방법으로 확인한 뒤, 새 근거와 연결된 조건만 다시 계산한다. 이번 합성 평가에서는 이 과정이 끝까지 이어지는지와 어떤 정보 연결 모양에서 질문 순서가 달라지는지를 확인했다.
