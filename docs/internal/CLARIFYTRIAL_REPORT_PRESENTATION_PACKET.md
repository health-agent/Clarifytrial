# ClarifyTrial 연구 요약

## 핵심 아이디어

환자 정보가 부족할 때 시험 하나에 두 가지 결과를 따로 표시한다.

1. 참가 가능성이 남아 있어 계속 확인할 후보인가?
2. 지금 가진 자료만으로 참가 조건 확인을 끝낼 수 있는가?

최근 14일 이내 혈액검사가 필요한데 3개월 전 결과만 있다고 가정한다. 이전 수치가 조건
안에 있었다면 시험을 바로 버리지 않고 `추가 확인 후보`로 남긴다. 다만 현재 조건 확인은
끝내지 않고 최근 결과가 필요하다고 표시한다. 새 결과가 들어오면 그 검사와 연결된
시험만 다시 판단한다.

이 구분 덕분에 정보가 부족한 시험을 탈락시키거나, 반대로 가능성만 보고 참가 가능으로
확정하는 두 오류를 함께 피할 수 있다.

## 전체 실행 순서

![ClarifyTrial 전체 흐름](diagrams/clarifytrial-workflow.svg)

```text
정해진 형식의 환자 상태 읽기
→ 모집 중·모집 예정 시험에서 관련 시험 찾기
→ 각 시험의 선정·제외 조건 확인
→ 현재 확인 완료·추가 확인 후보·조건 불충족으로 나누기
→ 여러 시험의 판단을 바꿀 수 있는 정보부터 고르기
→ 병원 기록·환자 답변·기존 공식 결과·새 검사 중 확인 방법 고르기
→ 답을 반영해 관련 시험만 다시 판단하기
→ 질문 전후 변화, 남은 정보와 검사·방문 부담을 함께 보여 주기
```

검색은 공개 시험 1,931건 가운데 현재 모집 중이거나 모집 예정인 589건에서 시작한다.
먼저 관련 시험을 좁힌 뒤 조건을 하나씩 판단한다. 정보가 부족한 시험은 질문할 이유와
확인 방법을 붙여 남긴다.

## 여러 정보가 부족할 때

환자 한 명에게 시험이 여러 개 연결돼 있으면 같은 정보가 여러 시험을 동시에 막을 수
있다. 예를 들어 최근 혈액검사는 시험 네 개, 복용약 확인은 시험 한 개에 영향을 줄 수
있다. 확인 기회가 한 번뿐이면 혈액검사를 먼저 확인하는 편이 더 많은 판단을 끝낸다.

프로그램은 다음 내용을 계산한다.

- 그 정보를 확인하면 상태가 바뀔 수 있는 시험 수
- 연결된 미확인 조건 수
- 남은 확인 횟수 안에서 끝낼 수 있는 판단 수
- 환자가 이용할 수 있는 확인 방법
- 새 검사, 추가 방문, 대기와 비용 부담

현재 자료에서는 남은 횟수 전체를 계산한 방법과 “지금 가장 많은 시험에 연결된 정보”를
고르는 단순한 방법의 결과가 같았다. 복잡한 계산이 더 우수하다고 주장하지 않고, 단순한
방법을 강한 비교 기준으로 남긴다.

## 환자 상황이 바꾸는 부분

환자 상황은 참가 조건을 바꾸지 않는다. 같은 정보를 어떤 순서와 방법으로 확인할지만
바꾼다.

예를 들어 병원 기록 조회와 새 검사가 모두 가능하다면 기존 기록을 먼저 확인한다. 환자가
새 검사나 추가 방문을 원하지 않는다고 입력하면 해당 방법을 고르지 않는다. 그 때문에
확정을 끝내지 못한 시험은 `추가 확인 후보`에 남고, 피한 검사·방문과 줄어든 확정 수가
결과에 함께 나온다.

## 합성 환자와 숨긴 정보

실험에서는 공개 시험 조건에 맞춰 가상 환자의 전체 상태를 먼저 만든다. 그다음 판단에
필요한 사실 일부를 가려 첫 입력을 만든다.

```text
전체 상태: 최근 혈액검사 정상, 특정 약을 복용하지 않음, 수술 이력 없음
첫 입력: 최근 혈액검사와 복용약 정보가 빠져 있음
시스템 질문: 최근 혈액검사 결과가 있습니까?
가상 답변 환경: 미리 만든 전체 상태에 있는 답만 제공
재판정: 그 결과와 연결된 시험만 다시 확인
```

가상 답변 환경은 처음부터 만든 전체 상태에 없는 사실을 새로 만들지 않는다. 어떤
정보를 가렸는지 알기 때문에 필요한 정보를 물었는지, 답을 받은 뒤 어떤 시험이
확정되거나 제외됐는지 자동으로 셀 수 있다. 한 사실만 빠진 사례뿐 아니라 여러 사실이
동시에 빠진 사례, 질문해도 답을 얻지 못하는 사례와 새 검사를 원하지 않는 사례도
포함한다.

나이와 임신·수유 상태처럼 서로 연결된 사실은 따로 만들지 않는다. 생식 가능 연령을
벗어난 환자에게 임신 여부를 핵심 미확인 정보로 두지 않는다.

## 통합 점검에서 확인한 변화

별도 평가 환자 30명에게 시험 5개씩 연결해 150개 판단을 만들고 추가 확인을 세 번
허용했다.

| 다음 정보를 고른 방법 | 최종 상태 일치 | 실제 후보 확정 | 제외 후보 정리 |
|---|---:|---:|---:|
| 추가 확인 없음 | 28/150개, 18.7% | 0/54개 | 0/68개 |
| 입력 파일에 적힌 순서 | 141/150개, 94.0% | 45/54개 | 68/68개 |
| 지금 가장 많은 시험에 연결된 정보 우선 | 143/150개, 95.3% | 47/54개 | 68/68개 |
| ClarifyTrial | 143/150개, 95.3% | 47/54개 | 68/68개 |

처음 자료만 보면 확정할 수 없지만 전체 상태에서는 참가 가능한 시험이 54개였다. 이
54개를 모두 추가 확인 후보로 남겼고 세 번 안에 47개를 확정했다. 반대로 전체 상태에서
제외되는 후보 68개는 모두 정리했다. 잘못 제외한 시험과 정보가 부족한데 확정한 시험은
없었다.

이 95.3%는 임상 판단 정확도가 아니다. 기대 결과도 같은 구조화 규칙으로 만든 자료에서
질문 세 번 뒤 정해진 상태까지 얼마나 도달했는지 보는 통합 점검이다.

같은 환자에게 연결된 시험을 서로 독립인 사례로 세지 않고 환자 단위로 다시 계산하면
95% 범위는 91.3~98.7%였고, 질환별 결과는 86.7~100.0%였다.

## 새 시험에서 모델 호출을 비교한 결과

기존 평가와 겹치지 않는 시험 30건을 개발용 15건과 최종 평가용 15건으로 나눴다. 최종
평가에는 합성 환자 25명과 환자–시험 판단 75개를 사용했다.

| 실행 구조 | 최종 상태 일치 | 실제 후보 확정 | 제외 후보 정리 | 외부 모델 호출 | 토큰 |
|---|---:|---:|---:|---:|---:|
| 구조화 규칙만 사용 | 75/75개 | 36/36개 | 23/23개 | 0회 | 0 |
| 조건 판단 모델만 사용 | 75/75개 | 36/36개 | 23/23개 | 65회 | 1,033,320 |
| 조건 판단과 질문 문장 작성에 모델 사용 | 75/75개 | 36/36개 | 23/23개 | 105회 | 1,565,829 |

조건이 이미 수치·날짜·참거짓으로 정리돼 있으면 코드를 쓰는 편이 같은 결과를 더 적은
비용으로 냈다. 현재 기본 구조는 코드가 전체 순서와 계산을 맡고, 모델은 문장의 뜻을
구조화해야 할 때만 부른다. 실제 근거가 서로 충돌할 때만 별도 검토를 부른다.

## 조건 불충족 시험의 차이 표시

모든 참가 조건에 “얼마나 아까운 탈락인지”를 숫자로 붙이지 않는다. 의미가 분명한
수치·날짜 조건에서만 기준과의 차이를 계산한다.

```text
조건: 혈소판 100 이상
환자값: 96
결과: 현재 조건 불충족, 기준까지 4 부족
```

수치와 날짜처럼 같은 단위로 비교할 수 있는 조건은 경계와의 차이를 보여 준다. 임신,
과거 치료, 특정 질환 유무처럼 거리로 표현할 수 없는 조건은 충족·불충족과 근거만
표시한다. 서로 다른 검사값의 차이를 하나의 점수로 합쳐 순위를 만들지 않는다.

## 연구 기여의 범위

질문 생성, 답변 반영, 여러 모델 역할, 비용을 고려한 행동 선택은 선행연구에 있다.
ClarifyTrial은 다음 내용을 한 실행과 평가표 안에서 연결한다.

- 현재 확인된 시험과 추가 확인 후보를 분리한 결과
- 처음 자료에서 보이지 않을 실제 후보를 보존하고 확정한 수
- 가능성이 남았지만 결국 제외되는 후보를 정리한 수
- 잘못 제외와 성급한 확정을 함께 막는 평가
- 질문 수뿐 아니라 새 검사·추가 방문과 환자 선택을 기록하는 방식
- 검색부터 복합 조건 판정, 질문 뒤 재판정과 보고서 생성까지 이어지는 프로그램

TrialGPT보다 전체 추천 성능이 높다는 결론과 새 질문 알고리즘의 우월성은 현재 결과에
포함하지 않는다. 가장 강한 단순 질문 방식과 ClarifyTrial의 결과가 같았고, 구조화된
조건에서는 모델 호출을 늘려도 결과가 좋아지지 않았다.
