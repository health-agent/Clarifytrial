# ClarifyTrial 연구 요약

ClarifyTrial은 환자 정보가 부족한 상황에서 임상시험 후보를 유지할지, 현재 자료로
참가 조건을 확인할 수 있는지를 따로 판단한다. 부족한 정보가 여러 개라면 제한된 확인
횟수로 가장 많은 시험의 판단을 끝낼 정보를 먼저 확인한다.

## 핵심 아이디어

한 시험에 대해 두 가지 결과를 따로 낸다.

1. **후보 유지:** 참가 가능성이 남아 있어 계속 검토할 시험인가?
2. **현재 확인:** 지금 확보한 자료만으로 참가 조건을 확인할 수 있는가?

예를 들어 시험에서 최근 14일 이내 혈액검사를 요구하는데 환자에게 3개월 전 결과만
있다면 후보는 유지한다. 다만 현재 상태는 `최근 검사 결과 대기`로 남긴다. 최근 결과가
들어오면 그 정보와 연결된 시험만 다시 판단한다.

## 전체 흐름

```text
환자 상태와 시험 조건 입력
→ 관련 시험 검색
→ 조건별 환자 상태와 근거 확인
→ 후보 유지 여부와 현재 확인 가능 여부 분리
→ 가장 도움이 되는 다음 정보 선택
→ 기존 기록·환자 답변·공식 결과·새 검사 중 확인 방법 선택
→ 새 정보를 반영해 관련 시험만 다시 판단
→ 현재 확인된 시험과 추가 확인 후보를 나누어 출력
```

![ClarifyTrial 전체 흐름](diagrams/clarifytrial-workflow.svg)

## 어떤 정보를 먼저 확인하는가

후보 시험 5개에 다음 정보가 부족하고 확인 기회가 세 번이라면 전부 확인할 수 없다.

```text
최근 혈액검사
현재 복용약
과거 수술 여부
병리검사 결과
치료 시작일
```

최근 혈액검사 하나로 시험 4개의 판단을 끝낼 수 있고 과거 수술 여부는 시험 1개에만
영향을 준다면 최근 혈액검사를 먼저 확인한다. 한 번 확인할 때마다 남은 시험과 정보를
다시 계산한다.

## 환자 부담을 반영한 확인 방법

같은 정보도 여러 방법으로 확인할 수 있다.

- 현재 병원 기록 확인
- 다른 병원의 기존 기록 요청
- 환자에게 질문
- 이미 받은 공식 결과 확인
- 새로운 검사 또는 평가
- 담당 의료진의 판단

기존 기록이나 환자 답변으로 확인할 수 있다면 새 검사보다 먼저 사용한다. 이동과 비용,
시간 긴급성, 새 검사에 대한 선호가 입력되면 확인 순서에 반영한다. 이런 입력은 참가
조건을 바꾸지 않고 확인 방법만 바꾼다.

## 사용한 자료

| 자료 | 사용 목적 | 현재 규모 |
|---|---|---:|
| TREC Clinical Trials 2021·2022 | 수만 건 중 관련 시험 검색 | 공개 평가자료 두 개 |
| TrialGPT 조건 판단 자료 | 환자 기록과 참가 조건 하나의 판단 | 조건 1,015개 |
| ClinicalTrials.gov | 실제 시험 원문 기반 조건 제작 | 평가 시험 15건·조건 92개 |
| ClarifyTrial 합성 환자 | 질문과 재판정 | 개발 30명·별도 평가 30명 |
| 환자 부담 합성 상황 | 확인 방법 선택 | 360개 상황·1,800회 실행 |

환자 자료는 모두 합성이다. 환자 상태와 답을 먼저 정한 뒤 일부 정보를 가렸으며,
질문을 고르는 과정에서는 가려 둔 답을 볼 수 없다.

## 현재 결과

### 관련 시험 검색

전문가가 관련 있다고 표시한 시험을 검색 결과 상위 500개 안에 남긴 비율이다.

| 공개 평가자료 | 관련 시험을 상위 500개 안에 남긴 비율 |
|---|---:|
| TREC 2021 | 83.59% |
| TREC 2022 | 81.55% |

두 값은 TrialGPT 논문의 공개 수치와 소수점 첫째 자리까지 같았다. 후보 검색만 평가한
결과이며 참가 조건 판단과 최종 추천은 포함하지 않는다.

### 한 번의 조건 판단

평가 환자 33명·조건 654개에서 현재 판단은 전문가가 붙인 답 이름과 79.1% 일치했고,
같은 자료의 TrialGPT 공개 답은 88.8% 일치했다. 별도 개발 표본의 오답 51개 중 47개는
`판단 가능`과 `정보 부족` 사이의 답 이름 차이였다. 두 답은 ClarifyTrial에서 모두 후보
유지로 이어진다.

### 질문 뒤 판단 완료

별도 합성 환자 30명에게 시험 5개씩 연결해 시험 판단 150개를 만들고, 추가 정보를
최대 세 번 확인했다.

| 확인 방법 | 세 번 안에 판단을 끝낸 시험 |
|---|---:|
| 추가 정보를 확인하지 않음 | 63개, 42% |
| 입력 파일에 적힌 순서대로 확인 | 99개, 66% |
| 가장 많은 시험 판단을 끝낼 정보를 매번 계산 | 115개, 77% |

현재 방법은 입력 순서 방식보다 환자 16명에서 좋았고, 12명에서 같았으며, 2명에서
낮았다.

![질문 순서 결과](diagrams/clarifytrial-question-policy-results.svg)

### 환자 부담을 반영한 확인 방법

이동과 비용 제한이 있는 합성 상황 80개의 결과다.

| 측정 내용 | 모든 환자에게 같은 확인 순서 | 환자의 제한을 반영한 확인 방법 |
|---|---:|---:|
| 실제로 이용할 수 있는 방법만 사용해 판단을 끝낸 시험 | 81.0% | 88.5% |
| 새 검사나 추가 방문을 피해야 하는데도 그런 방법을 선택한 횟수 | 65회 | 0회 |

![환자 부담 결과](diagrams/clarifytrial-patient-burden-results.svg)

## 대표 사례

합성 유방암 환자 한 명에게 후보 시험 5개와 부족한 정보 5개를 배정하고 확인 횟수를
세 번으로 제한했다.

![대표 합성 환자 사례](diagrams/clarifytrial-representative-case.svg)

```text
시작: 시험 2/5개 판단 완료
나이 확인: 3/5개 판단 완료
보정 혈청 칼슘 확인: 4/5개 판단 완료
이전 전신치료 횟수 확인: 5/5개 판단 완료
최종 목록: 현재 확인 3개 · 추가 확인 후보 0개 · 제외 2개
```

## 확인된 범위

| 확인된 내용 | 아직 측정하지 않은 내용 |
|---|---|
| 정해진 JSON 입력에서 전체 흐름이 작동한다 | 실제 진료기록 전체의 해석 성능 |
| 같은 합성 환자에게 질문 순서만 바꿔 비교했다 | TrialGPT보다 높은 전체 추천 성능 |
| 환자 부담 입력에 따라 확인 방법이 달라졌다 | 실제 환자의 비용·시간 변화 |
| 검색 단계가 TrialGPT 공개 결과와 거의 같았다 | 검색부터 최종 추천까지의 임상 성능 |

현재 정밀 평가는 3개 질환·15개 시험에 한정된다. 다음 평가는 팀 공개 시험 1,931건을
넓은 검색 자료로 사용하고, 정밀 평가 범위를 약 10개 질환·50개 시험으로 넓힌다.
