# ClarifyTrial 연구 요약

## 핵심 아이디어

환자 정보가 부족한 시험을 하나의 답으로 처리하면 두 방향의 문제가 생긴다.

- 확실한 자료가 없다는 이유로 참가 가능성이 있는 시험을 버릴 수 있다.
- 가능성이 있다는 이유로 필요한 확인이 끝났다고 표시할 수 있다.

ClarifyTrial은 시험마다 다음 두 결과를 따로 낸다.

| 결과 | 묻는 질문 |
|---|---|
| 후보 유지 여부 | 더 확인하면 참가 가능성이 남아 있는가? |
| 현재 확인 상태 | 지금 확보한 자료만으로 이번 사전 검토의 조건을 확인할 수 있는가? |

예를 들어 최근 14일 이내 혈액검사가 필요한 시험에 3개월 전 정상 결과만 있는 환자가
있다. 오래된 정상 결과는 참가 가능성을 보여 주므로 시험은 후보로 남는다. 그러나
최근 결과가 없으므로 현재 확인은 끝나지 않는다. 프로그램은 `최근 혈액검사 필요`를
표시하고 새 결과가 들어오면 관련 조건만 다시 판단한다.

## 실행 흐름

![ClarifyTrial 전체 흐름](diagrams/clarifytrial-workflow.svg)

1. 모집 중이거나 모집 예정인 시험에서 환자와 관련 있는 후보를 찾는다.
2. 검색된 시험이 실제로 환자의 질환을 다루는지 확인한다.
3. 시험의 선정 조건과 제외 조건을 하나씩 판단하고 근거를 저장한다.
4. 현재 확인이 끝난 시험, 추가 정보가 필요한 후보, 조건을 위반한 시험을 나눈다.
5. 부족한 정보마다 몇 개 시험의 판단에 영향을 주는지 계산한다.
6. 기존 기록, 환자 답변, 이미 받은 공식 결과, 새 검사 가운데 확인 방법을 고른다.
7. 환자가 밝힌 이동·비용·시간 제한과 새 검사 허용 여부를 적용한다.
8. 새 답을 반영해 관련 조건만 다시 판단한다.
9. 질문 전후에 살아난 후보, 제외된 후보와 아직 남은 정보를 함께 보여 준다.

## 여러 정보 중 무엇을 먼저 확인하는가

후보 시험 5개에 부족한 정보가 5개인데 세 번만 확인할 수 있다면 모든 정보를 물을 수
없다. 최근 혈액검사 하나가 시험 4개에 필요하고 과거 수술 여부가 시험 1개에만
필요하다면 혈액검사를 먼저 확인하는 편이 유리하다.

현재 구현은 두 방법을 비교할 수 있다.

- 그 순간 가장 많은 미완료 시험에 연결된 정보를 고르는 방법
- 남은 확인 횟수 안에서 사용할 정보 조합을 계산하는 방법

공개 시험 기반 평가에서 두 방법의 최종 결과는 같았다. 따라서 연구의 중심은 복잡한
질문 순서 계산이 더 좋다는 주장이 아니라, 정보가 부족한 후보를 보존하고 확인 뒤
정리하는 전체 흐름에 있다.

## 실험자료

| 자료 | 범위 | 사용한 목적 |
|---|---:|---|
| ClinicalTrials.gov 공식 API | 실행 시점의 모집 가능 시험 | 일반 실행의 후보 검색과 원문 가져오기 |
| 공식 대회 합성 환자 | 환자 10명, 실제 판정 시험 25건, 조건 472개 | 자유 문장부터 공식 검색·판정·질문·저장까지 연결 |
| 고정 공개 임상시험 모음 | 전체 1,931건, 평가 검색 589건 | 같은 자료로 검색 연결을 다시 확인 |
| 공개 시험 기반 전체 흐름 자료 | 10개 질환, 시험 50건, 조건 202개 | 검색·판단·질문·재판정 연결 |
| 합성 환자 | 50명 | 일부 정보를 감춘 시작 상태와 확인 뒤 답 |
| 기존 자료와 겹치지 않는 새 시험 | 5개 질환, 시험 30건, 조건 116개 | 개발과 분리한 최종 평가 |
| TREC Clinical Trials 2021·2022 | 수만 건의 시험 문서 | 관련 시험 검색 성능 |
| TrialGPT 조건 판단 자료 | 조건 1,015개 | 질문 전 한 번의 조건 판단 |
| 환자 부담 합성 상황 | 360개 | 이동·비용·시간 제한 적용 |

환자 자료는 모두 합성이다. 가상 환자의 전체 상태를 먼저 저장한 뒤 시작 입력에서 일부
사실을 감췄다. 질문을 고르는 프로그램은 감춘 답을 볼 수 없고, 선택한 확인 행동이
실행된 뒤에만 그 답을 받는다.

공개 시험의 조건 202개와 116개는 각 시험의 전체 참가 조건이 아니다. 나이, 단일
수치, 날짜, 명확한 상태와 원문에서 관계가 분명한 일부 조건만 사용했다.

## 전체 흐름에서 확인한 결과

개발에 사용하지 않은 합성 환자 30명에게 시험 5개씩을 연결해 150개 판단을 만들었다.
환자 한 명당 추가 정보는 최대 세 번 확인했다.

| 정보를 고른 방법 | 최종 상태가 기대 결과와 같은 시험 | 실제 참가 가능 후보로 확정 | 결국 제외될 후보를 정리 |
|---|---:|---:|---:|
| 추가 확인 없음 | 28/150, 18.7% | 0/54 | 0/68 |
| 입력에 적힌 순서 | 141/150, 94.0% | 45/54 | 68/68 |
| 현재 가장 많은 시험에 연결된 정보 우선 | 143/150, 95.3% | 47/54 | 68/68 |
| 남은 세 번의 확인을 함께 고려 | 143/150, 95.3% | 47/54 | 68/68 |

![정보 선택 방법별 최종 상태 일치](diagrams/clarifytrial-question-policy-results.svg)

처음 화면에서 확인이 끝난 시험만 보여 주면 실제 참가 가능 후보 54개가 보이지 않는다.
ClarifyTrial은 54개를 모두 추가 확인 후보로 남겼고 세 번 안에 47개를 실제 후보로
확정했다. 반대로 처음에는 정보 부족으로 남았지만 전체 상태에서는 부적합인 후보
68개는 모두 질문 뒤 제외했다.

답 하나를 얻지 못하게 한 경우에는 실제 후보 41/54개를 확정했고, 같은 정보를 다시
묻지 않았다. 새 검사와 추가 방문을 원하지 않는다고 입력한 경우에는 새 검사와 추가
방문을 한 번도 고르지 않으면서 43/54개를 확정했다.

### 공식 입력을 처음부터 끝까지 실행한 결과

공식 대회 합성 환자 10명을 4개씩 병렬로 실행했다. ClinicalTrials.gov에서 가져온
원자료 후보 101건 가운데 질환 확인 단계에서 7건을 제거했고, 환자당 최대 3개씩 이
확인을 통과한 시험 25건을 조건 판정으로 넘겼다. 한 환자는 관련 모집 시험이 없었고 한 환자는
한 개만 남아 30건을 억지로 채우지 않았다.

- 선정 조건 204개와 제외 조건 268개를 구조화했다.
- 조건 472개 모두 저장한 공식 원문의 해당 글자 위치와 일치했다.
- 복합 조건 관계를 안전하게 표현하지 못한 시험 11건은 참가 가능으로 확정하지 않았다.
- 추가 정보 확인을 27번 시도했다.
- 모델을 97번 호출해 1,538,814토큰을 사용했다.

모든 질문에는 `unknown`을 입력했다. 따라서 이 실행은 전체 프로그램 연결과 원문 보존
점검이며 추천 정확도 실험은 아니다. 실행에서 평범한 정보 부족을 검토 모델이 되풀이한
7회 호출도 확인해, 이후에는 근거 충돌이나 잘못된 확정 근거에만 검토 모델을 부르도록
수정했다.

## 환자 상황에 따른 확인 방법

이동·비용·시간 제한을 조합한 합성 상황 360개에서 확인 방법을 1,800번 골랐다. 모든
환자에게 같은 비용표를 적용하면 제한이 있는 환자에게 허용된 방법만 사용하고도 판단을
끝낸 시험 비율이 81.0%였다. 환자별 제한을 먼저 적용하면 88.5%였고, 피해야 하는 새
검사나 추가 방문을 제안한 횟수는 65회에서 0회로 줄었다.

![환자 제한에 따른 확인 방법 선택](diagrams/clarifytrial-patient-burden-results.svg)

## 새 시험에서 모델 호출을 비교한 결과

기존 평가와 겹치지 않는 공개 시험 15건, 합성 환자 25명, 환자와 시험의 조합 75개를
최종 평가에 사용했다.

| 실행 방식 | 최종 상태 일치 | 외부 모델 호출 | 전체 토큰 |
|---|---:|---:|---:|
| 수치·날짜 규칙을 코드로 계산 | 75/75 | 0회 | 0 |
| 조건 판단에 GPT-5.6 Sol 사용 | 75/75 | 65회 | 1,033,320 |
| 조건 판단과 질문 문장 작성에 같은 모델 사용 | 75/75 | 105회 | 1,565,829 |

이 평가의 조건은 코드가 직접 계산할 수 있도록 구조화돼 있었다. 모델 호출을 늘려도
결과가 좋아지지 않았으므로, 구조화된 입력에서는 코드를 기본값으로 둔다. 자유 문장
조건의 의미 해석 성능이나 여러 모델 역할의 일반적인 우열을 보여 주는 결과는 아니다.

## 연구에서 강조할 부분

1. **회색지대를 결과에 남긴다.** 참가 가능성이 남은 시험과 지금 확인이 끝난 시험을
   같은 목록으로 뭉개지 않는다.
2. **한쪽에 유리한 통계를 막는다.** 추가 확인으로 살린 실제 후보와 결국 제외한 후보를
   함께 센다.
3. **환자가 실제로 감당할 확인 방법을 고른다.** 질문 수만 세지 않고 새 검사, 추가
   방문, 대기와 환자 선택을 기록한다.
4. **처음부터 끝까지 같은 상태를 사용한다.** 검색, 판단, 질문, 답변과 재판정을 한
   프로그램에서 실행하고 각 변화의 근거를 남긴다.

질문 생성, 답변 반영, 관련 문서 검색, 여러 모델 역할과 비용을 고려한 정보 선택은
이미 선행연구에 있다. ClarifyTrial보다 TrialGPT의 전체 추천 성능이 낮다고 주장하지
않으며, 현재 실험은 실제 등록률이나 임상 결과를 측정하지 않았다.

세부 수치는 [검증 결과](CLARIFYTRIAL_VALIDATION_RESULTS.md), 프로그램의 현재 범위는
[현재 상태](CURRENT_STATUS.md), 연구 질문과 비교 기준은
[현행 연구계획 v5](CLARIFYTRIAL_RESEARCH_PLAN_V5.md)에 정리돼 있다.
