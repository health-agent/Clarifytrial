# 오래된 혈액검사 예제

이 예제는 한 가지 차이를 보여 준다.

환자의 3개월 전 혈소판 수치는 참가 가능성을 뒷받침한다. 따라서 환자를 후보에서 빼지 않는다. 다만 임상시험은 최근 14일 안에 받은 공식 검사 결과를 요구하므로, 현재 자료만으로 참가 조건 확인을 끝낼 수는 없다. 시스템은 최근 공식 검사를 요청하고, 그 결과가 들어온 뒤 같은 조건을 다시 판단한다.

## 파일을 나눈 이유

- `system_input.json`: 시스템이 처음부터 볼 수 있는 임상시험 조건과 환자 기록
- `public_questions.json`: 시스템이 선택할 수 있는 추가 확인 항목과 확인 방법
- `hidden_answers.json`: 선택한 확인 절차를 실행한 뒤에만 공개되는 합성 답변
- `gold_initial.json`: 첫 판단이 맞았는지 실행 후 채점하는 정답표

숨은 답변과 정답표는 에이전트 입력에 포함되지 않는다. `hidden_answers.json`은 시스템이 올바른 확인 절차를 선택했을 때만 실행 환경이 읽어 새 사실을 돌려준다. `gold_initial.json`은 전체 실행이 끝난 뒤 첫 판단을 채점할 때만 읽는다.

## 실행

```powershell
clarifytrial run-example `
  --case examples/stale_lab `
  --output runs/stale_lab
```

결과는 `runs/stale_lab/result.json`, 호출 순서와 상태 변화는 `runs/stale_lab/trace.jsonl`에 저장된다.

이 실행은 외부 모델에 접속하지 않는다. 역할별 응답을 코드에 고정한 `ScriptedStructuredModel`로 전체 연결과 상태 변화를 점검한다. 따라서 이 예제의 성공은 모델 성능 측정값이 아니다.

혈소판 수치, 단위, 검사 날짜, 자료 출처와 확인 상태는 별도 필드로도 저장한다. 코드는
이 값들을 직접 검사하고 검색·판정 결과와 다르면 선택 검토 표시를 붙인다. 자유문에서
수치를 추측하거나 단위를 자동으로 바꾸지는 않는다.
